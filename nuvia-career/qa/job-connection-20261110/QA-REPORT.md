## 재검사 이력과 환경

최초 45개 조합 중 41개 통과, 4개는 의도적으로 사용한 가짜 인증 주소 `qa.invalid`의 Clerk JS 로드 오류로 실패했습니다. 중국어 번체 360, 러시아어 768, 프랑스어 768, 이탈리아어 360을 전체 여정으로 재실행하여 모두 통과했습니다. 로컬 실행기는 **이 가짜 주소의 정확히 일치하는 로드 오류만** 별도 환경 오류로 기록합니다. 다른 브라우저 오류는 계속 실패 처리합니다. 재검사 중 해당 환경 오류는 1건 기록됐습니다. 최초 실패 결과를 삭제하지 않았습니다.

검사 코드의 존재하지 않는 Radix `data-value` 선택자를 언어별 접근성 이름으로 교정하고, 언어 메뉴 종료 대기 및 문서 검사 결과 폴더를 바로잡았습니다. locale 참조는 scripts TypeScript 범위를 넓히지 않는 런타임 로드로 수정했습니다. 제품 동작 코드는 Replit 원본과 동일합니다. 실행별 source fingerprint는 검사 코드 수정 때문에 다를 수 있으며, 제품 소스 동일성은 별도 `source-equality.json`으로 검증했습니다.

Windows/Node 24 환경에서 기존 캐시와 잠금파일로 설치했습니다. 원본이 제외한 Windows 네이티브 빌드 모듈은 동일 버전의 별도 QA 의존성에서 연결했습니다. 제품 잠금파일은 수정하지 않았습니다. Headless Chromium, 원본 public API router와 빌드 화면을 사용했고 계정 API는 차단했습니다. DB는 도달 불가능한 localhost 합성 설정입니다. 실제 서비스 인증·사용자 데이터·운영 DB는 사용하지 않았습니다. 내보내기 속도 제한을 변경하지 않았으며 조합 간 최소 대기를 적용했습니다.

기존 sourcemap 및 큰 번들 경고는 남아 있으나 빌드는 성공했습니다. 초기 환경 경로·실행 권한·별칭 설정 문제는 검증 환경에서 수정했으며 제품 실패로 집계하지 않았습니다.
