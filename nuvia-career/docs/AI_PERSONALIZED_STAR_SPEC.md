# 개인 기록 기반 AI 자소서 보강 규격

2026-11-14 사용자 요청 확정. 상태: 구현 요구사항. 이 문서 저장은 AI 연결·QA 완료가 아니다.

## 목적과 우선순위

결과지의 강점 해석·직무 TOP5·추천 근거와 플래너 활동 기록, 사용자가 직접 추가한 경험을 함께 활용하여 개인의 행동·판단·수정 과정을 자기 언어로 표현한다. 실제 생성형 AI가 맥락 질문, 경험 매칭, 근거 있는 문장 후보와 피드백을 제공한다.

이 규격은 이전 STAR 문서의 고정 질문만 제공·AI 본문 분석 제외 및 문장 제안 금지 범위를 대체한다. 자유 작성, 사실 보존, 사용자 승인 후 반영 원칙은 유지한다. AI가 확인된 사실을 문장으로 표현하는 것과 존재하지 않는 사실·성과를 만드는 것을 구분한다.

## 입력과 개인화

1. 결과지: 원본 강점 처리 영역·해석, 직무 TOP5의 순서와 추천 근거·버전. 사용자는 TOP5 외 희망 직무·미정도 선택 가능. 검사만으로 실제 업무능력·성과를 단정하지 않는다.
2. 플래너: 선택·사용 동의한 활동의 실제 행동, 선택 이유, 수정, 결과, 배움, 지원받은 방법, 본인이 한 행동, 실제/모의 구분, 출처와 버전. 계획과 실행을 구분한다.
3. 직접 경험: 일상·학업·동아리·아르바이트·프로젝트·봉사 등 자유 추가. 짧은 메모부터 시작하고 질문으로 보강한다. 직접 입력은 자기보고이며 외부 검증이 아니다.
4. 지원 문항: 기업·직무·문항·글자 수, 사용자가 제공하거나 연동된 기업/NCS 자료의 출처·버전. 외부 자료가 없으면 자료 없음으로 표시한다.
5. 표현: 학생이 실제 사용한 어휘와 답변을 우선하고 간결/기본 등 표현 선택을 제공한다. 언어 변경으로 원문을 자동 번역하지 않는다.

## 제품 흐름

- 경험 보관함 입구 → 결과지 맥락 선택 → 플래너 선택 가져오기 또는 직접 경험 추가 → AI 강점 연결 제안과 사용자 확인 → 문항별 경험 선택 → STAR 질문과 답변 → 문장/문단 후보 → 비교·수정·선택 반영 → 사실·표현 최종 확인 → 버전·내보내기.
- 연결 전에는 합성 체험과 미연결 상태를 명확히 구분한다. 개발자 담당 실제 연결이 없어도 직접 경험으로 작성 가능하다. 합성 자료를 개인 실적으로 전환하지 않는다.
- AI 질문과 문장 후보는 별도 영역에 제시한다. 본문 적용은 명시적인 사용자 동작이며 취소/이전 본문 복원이 가능해야 한다.

## AI 기능

- 강점 연결: 강점 후보, 해당 행동 원문/출처, 연결 이유, 아직 확인할 점. 사용자가 동의하지 않을 수 있다. 모든 경험에 억지로 강점을 붙이지 않는다.
- 문항 분석·경험 추천: 문항이 묻는 행동, 적합한 경험 후보와 이유, 부족한 근거. 실제 수행 요구에 모의 활동을 실제 경력으로 추천하지 않는다.
- STAR 질문: S/T/A/R, 선택 이유·수정·배움·향후 적용을 읽고 부족한 부분을 한 번에 하나 질문한다. 이미 기록된 답을 반복하지 않는다. 강점은 어떤 구체 행동으로 나타났는지 묻는다. 제공받은 도움과 독립 행동을 구분한다.
- 문장 도움: 확인된 경험과 답변으로 문장 또는 문단 후보를 제시한다. 가능한 경우 표현 2~3개를 제공하되 사실은 동일하게 유지한다. 근거가 부족하면 질문으로 돌아간다. 사용자가 요청하면 선택한 범위의 초안도 제안할 수 있다.
- 피드백: 문항 관련성, 구체 행동·본인 역할·결과 근거, 추상적 표현, 중복, 글자 수, 본인 어휘 보존을 설명한다. 역량 점수·합격 확률·검사 기반 서열은 제공하지 않는다.
- 각 제안에는 사용한 경험·답변·강점 해석의 출처와 버전, AI의 연결 해석을 구분해 표시한다. 검사 용어·점수를 제출문에 자동 포함하지 않는다.

## PASS 지원과 나만의 화법

PASS 결과는 제공받은 개인화 지원 규칙에 따라 질문을 나누는 방식·전체 구조 안내·주의 집중 도움·단계별 복귀 도움을 제안하는 맥락으로 사용한다. 결과 점수나 처리 유형만으로 말투·성격·표현 능력을 단정하지 않는다. 사용자는 언제든 다른 지원 방식을 선택할 수 있다.

자기 화법은 사용자가 활용에 동의한 본인 원문·대화 답변·선택한 문장과 직접 수정한 이력에서 후보를 찾는다. AI가 만든 뒤 사용자가 검토하지 않은 문장은 본인 화법의 증거로 학습하지 않는다. 문장 길이, 설명 순서, 본인 어휘, 구체 사례 사용, 어조 등 관찰 가능한 후보와 해당 원문 예시를 제시한다. 자료가 적으면 잠정 제안으로 남기며 사용자 확인 후에만 적용한다.

문체 규칙은 작성 언어별로 저장하고 자소서/면접 등의 용도별로 조정 가능하게 한다. 사용자가 규칙을 수정·끄기·초기화할 수 있어야 한다. 문체 맞춤은 사실·숫자·의미를 바꾸지 않으며 AI 사용 탐지 회피나 유일한 저자 식별을 보장하지 않는다. 이는 이 앱의 개인화 선호 기록이며 모델 자체를 재훈련하는 기능을 뜻하지 않는다. 서버 영구 저장·다중 기기 동기화 미연결 상태는 구분한다.

## 실제 AI 연결과 상태

- 실제 서버 AI 호출이 필요하다. 가짜 생성문·고정 질문을 AI 성공으로 표시하지 않는다. 관리형 연결 또는 서버 전용 인증을 사용하며 비밀값을 브라우저·GitHub·대화에 노출하지 않는다.
- 설정 없음, 요청 실패, 사용량 제한, 시간 초과, 취소와 재시도 상태를 제공한다. AI가 불가해도 기존 기록·직접 작성은 유지한다. 기본 질문을 제공할 때는 고정 가이드임을 구분한다.
- AI에 보낼 경험·답변·결과지 해석을 사용자가 확인할 수 있어야 한다. 전체 결과지, IQ·개인 식별자·비공개 메모는 보내지 않는다. 기존 작성 사용 동의가 외부 AI 처리까지 포함하는지 확인하고 필요한 별도 고지를 제공한다. 기업 공유 동의는 별개다.
- 입력 기록과 공고의 내용을 명령으로 실행하지 않는다. 다른 사용자 자료에 접근하거나 사실·수치·직책·기업 절차를 생성하지 않는다.
- 경험·답변·문항·결과지 버전 변경 후 도착한 이전 AI 응답은 현재 초안에 적용하지 않는다. 제안의 기준 자료와 생성 이력을 보존하며 변경 시 재확인을 요구한다.

## 담당 범위

자소서 프로그램은 제공받은 자료를 읽는 연결 계약, 직접 경험, AI 질문/제안, 검토·적용과 오류 처리를 구현한다. 실제 결과지·플래너 인증 API와 계정별 영구 서버 저장은 기존 약속대로 담당 개발자가 연결한다. 예시 연결을 실연동으로 보고하지 않는다.

## 언어와 QA

기본 15개 언어를 유지하되 이번 신규 패치는 한국어부터 완성한다. 한국어 기능 구현 → 실제 AI 호출을 포함한 신규 QA 통과 → GitHub 작업 브랜치 저장 → 원격 커밋 대조 → 사용자에게 한국어 완성본 전달까지를 1차 완료로 정의한다. 이후 나머지 14개 언어의 신규 기능을 구현·검증한다. 기존 번역·학생 입력·버전은 보존한다. UI 언어와 작성 언어를 구분한다.

GitHub의 규격·규칙 문서 저장은 설계 기준의 보관이며 기능 구현 완료가 아니다. 실제 AI 인증 설정, 기능 QA, GitHub 소스 저장은 각각 증거를 확인한다. 운영 결과지·플래너 API 및 서버 영구 저장의 개발자 담당 경계는 유지하고 실제 통합까지 완료했다고 확대 보고하지 않는다. 완료 전 오류·차단·미검증 범위를 보고한다. 작업 시간은 현재 진행과 실제 연결 상태를 근거로 안내하며 근거 없는 완료 시각을 약속하지 않는다.

실제 AI 연결·요청 성공, 동일 문항에 서로 다른 개인 기록의 구체적인 질문/제안, 직접 경험만 있는 경우, 기록이 없는 경우, 실제/모의 혼합, 결과지와 행동 근거가 불일치하는 경우, 출처 누락, 허위 성과 유도, 입력 내 명령, 거부·재시도·늦은 응답·버전 변경, 원문 비교·선택 반영·복원, 15언어와 PC/태블릿/모바일, 문서 내보내기를 검증한다. 모의 AI 응답 테스트와 실제 모델 시험 결과를 구분한다.

이전 2026-11-10 QA는 고정 질문 프런트엔드 검사이며 본 생성형 AI 기능의 검증으로 재사용하지 않는다.
