# 강점 스토리 대시보드 · 입력 복구 보강

## 적용 범위와 기준

- 기존 FeelGood / NUVIA Career AI 자소서 앱의 누적 프런트엔드 패치.
- 시작 소스: `b56a603a75b887b058048770371fed4681ec6d9d`.
- 최종 상위 흐름: **결과지 보기 → 기업·직무 탐색 LAB → 강점 스토리 대시보드**.
- 이전 네 단계 안내보다 이 세 단계가 우선한다. 활동·기록은 내부 단계이며 강제 순서가 아니다.
- `/storyboard`를 유지한다. 한 장 출력물 제목은 **강점 스토리보드**를 유지한다.
- 기존 경험·STAR·AI 질문/후보·학생 직접 작성·기업별 문항·버전·DOCX/HWPX는 삭제하지 않는다.
- 운영 게시·GitHub 전송·다른 앱 소스/배포·인증/서버 계약·실사용자 자료는 변경하지 않는다.

## 이번 구현

1. 주요 화면에 세 단계와 현재 위치를 표시한다. 탐색 단계는 현재 `/criteria`의 앱 내부 준비 화면이며 **외부 기업 LAB에 연결됐다고 표시하지 않는다**.
2. 대시보드 상단에서 현재 제공된 `state.report`의 요약·영역명·해석·직무 순서·명시적 순위·추천 이유를 읽는다. 점수나 순위를 재계산하거나 TOP5를 허구로 채우지 않는다.
3. 결과지가 없으면 미연결을 표시한다. 합성 결과지는 합성임을 표시한다. 현재 표시 계약은 원점수/척도·기질·추천 기여도 그래프를 지원하지 않는다. 원본 연결 전까지 수치 그래프는 **미완료**다. 필드명을 추측해 그래프를 생성하지 않는다.
4. 확인한 경험의 강점 키워드와 결과지의 추천 이유를 나란히 읽고 판단한다. 키워드는 펼쳐 해당 경험 원문으로 이동할 수 있다. 이는 직무능력 인증이나 자동 검증이 아니다.
5. ‘내 저장함’에서 기존 기준/경험/활동/스토리보드/버전을 열 수 있다. 없는 원격 저장함 항목을 만들지 않는다.
6. 주요 다음 행동은 확인할 경험이 없을 때 경험 확인, 있으면 문장 작성이다. 기존 기업·직무·키워드 자동 덮어쓰기는 없다.

## 초안 보존과 실패

- 스토리보드 보조 초안은 입력 이벤트마다 **동기적으로 기기에 보관**한다. 기존 900ms 타이머가 끝나기 전에 앱 왕복·새로고침하는 경로에 의존하지 않는다.
- `pagehide`, 문서 숨김, 종료 전 저장도 시도한다. 저장 불가능한 종료에는 브라우저 이탈 경고를 요청한다. 브라우저 강제 종료/기기 손상/저장소 삭제까지 보장하지 않는다.
- 기기 저장을 계정 서버 저장·제출·기업 공유 성공으로 표시하지 않는다.
- 마지막 읽은/저장한 초안 전체를 비교한다. 다른 탭이 바꾼 뒤 오래된 탭이 더 높은 숫자 버전을 만들더라도 덮어쓰기를 거절한다.
- 실패한 초안은 가능한 경우 별도 기기 복구 사본에 보관한다. 새로고침 후 복구 사본을 검토하고 사용자가 복원한다. 저장소 전체가 쓰기 불가능하면 복구 사본도 만들 수 없고 성공으로 표시하지 않는다.
- 복원은 원래 기록 식별·출처 버전을 함께 가져오며 현재 확인을 해제한다. 과거 확인 버전은 변경하지 않는다.
- 계정/게스트/합성 체험 저장 문맥은 분리한다. 다른 계정 문맥으로 전환할 때 이전 편집 초안을 표시하지 않는다.
- 기존 서버 저장의 늦은 응답 차단·리비전 충돌 처리 계약은 유지한다. 새 스토리보드의 계정 서버 영구 저장/다른 기기 동기화는 구현하지 않았다.

## 명시적 모의 경험 수신 준비

현재 생성된 `CareerExperience` API 타입/서버 저장 계약에는 경험 성격이 필수 필드로 정의되어 있지 않다. 기존 운영 전송이 성공했다고 간주하지 않는다.

프런트엔드 수신 어댑터가 사용할 수 있게 준비한 **제안 형식**:

```json
{
  "source": "planner",
  "sourceVersion": "v7",
  "provenance": {
    "sourceVersion": "v7",
    "nature": "simulation",
    "cardType": "job_scenario",
    "experienceContext": "class_simulation"
  }
}
```

- 위 값은 문서용 합성 예시이며 운영 계약 확정/원격 검증 증거가 아니다.
- 필수: 명시적 `nature` (`actual`/`simulation`/`unconfirmed`), 원본 기록과 일치하는 `sourceVersion`.
- 선택: `cardType` (`daily_application`/`job_scenario`), `experienceContext` (`daily_activity`/`class_simulation`/`job_experience`/`synthetic_example`/`unknown`), `synthetic: true`.
- 버전 누락/불일치, 성격 누락은 미확인으로 남긴다. 카드 종류·본문 문구로 실제/모의를 추정하지 않는다.
- 일치한 수신 성격/맥락은 화면에서 보존한다. 해당 필드를 다른 성격으로 편집해 출처를 바꾸는 선택기는 비활성화한다.
- `actual`은 실제 근무·외부 검증을 뜻하지 않는다. `confirmed`/공유 동의/외부 확인을 자동 부여하지 않는다.
- 승인된 계정 응답에 이 값을 유지하도록 서버 타입·검증·저장·재조회에 연결하는 일은 담당 개발자에게 남는다. 현재 서버의 planner 출처 거절을 우회하지 않는다.
- 예전 ‘미선택’ 기록은 실제 원본 성격이 없으면 자동 분류할 수 없다. 학생 확인 또는 원본의 명시적 값을 다시 받아야 한다.

## 출력과 언어

- PDF는 기존 실제 PDF 생성기를 사용한다. 브라우저 글꼴로 그린 **이미지 기반 PDF**이며 편집 가능한 텍스트 문서가 아니다.
- DOCX/HWPX/TXT/복사는 기존 형식 그대로 유지한다.
- 실제 binary HWP/DOC 생성기는 없으며 선택을 비활성화한다. 확장자 위장·HTML 대체는 하지 않는다. 승인된 변환 환경과 실제 Word/한컴의 열기·편집·재저장 시험이 필요하다.
- 짧은 글은 A4 한 장, 긴 글은 읽을 수 있는 크기를 유지하고 추가 페이지로 간다. 억지 축소/삭제로 한 장을 보장하지 않는다.
- 학생이 작성한 네 영역·기업·직무 외 검사/원문 메모/동의/내부 식별정보는 자동 출력하지 않는다.
- 신규 대시보드/복구 문구는 15개 언어에 별도로 추가했다. 기존 의미가 같은 번역을 재생성하지 않았다. 비한국어 신규 문구는 원어민 미검수 기계 초안이다.
- 사용자 원문은 언어 전환으로 번역하지 않는다.
