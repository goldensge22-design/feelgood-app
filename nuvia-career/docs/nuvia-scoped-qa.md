## 1. 실제 로그인 후 전체 여정: 미실행

- 관리형 Clerk 상태는 `managed`, 대시보드 접근은 `authorized`로 확인했다.
- 웹 `/`와 API `/api/career/overview`는 HTTPS HTTP 200이었다.
- `/sign-in?lang=ko`를 실제 캡처 브라우저에서 열어 정상 로그인 UI를 확인했다.
  증거: `generated-artifacts/scoped-qa/sign-in-desktop.jpg`.
  이는 **로그인 성공이나 계정 저장 성공 증거가 아니다.**
- 지원된 검사 설정으로 실행한 테스트 도구가 사용자 여정을 시작하기 전에
  `subagent: Unknown config kind: testing`으로 거부됐다.
  프로젝트 인증 설정이나 데이터베이스를 고쳐 해결할 수 있는 코드 오류라는
  증거는 없다. 같은 호출을 반복하거나 보안을 우회하지 않았다.
- 대체 도구를 검색했으나 사용 가능한 다른 브라우저 인증 도구는 발견되지
  않았다. 공식 Replit 문서에서 App Testing의 사용자 `Begin take over`
  인증 경로를 확인했다:
  https://docs.replit.com/features/agent/app-testing
  현재 세션에는 이 검사용 브라우저 제어 기능도 노출되지 않는다.
- 현재 허용된 기존 테스트 계정 식별/로그인 세션도 제공되지 않았다.
  임의 계정을 만들거나 실제 사용자 목록/쿠키/토큰을 수집하지 않았다.

따라서 문항/글자 수 등록, 경험 작성·선택, 직접 작성·코치, 실제 계정 저장,
새로고침·재접속 복원, 독립 기업·문항 버전, 비교/과거 버전에서 새 초안,
언어 전환, 동시 편집 충돌/복구, 로그아웃 후 차단, 계정 간 분리 및
계정 화면에서 DOCX/HWPX 다운로드는 **이번 실행에서 전부 미실행**이다.
기존 단위검사·기기 저장 QA를 이 항목의 통과 증거로 사용하지 않았다.

### 안전한 재개 경로

1. Agent의 Advanced settings에서 App Testing이 사용 가능한지 확인한다.
   활성화만으로 현재 도구 오류가 해결된다고 보장하지 않는다.
2. 정상 검사 브라우저가 제공되면 위임 검사에서 `Begin take over`를 통해
   사용자가 기존의 허용된 테스트 계정으로 직접 로그인한 뒤 제어를 돌려준다.
   또는 정상 제공된 `signInClerkUser` 경로에서 사전에 허용된 기존 테스트
   계정만 사용한다. 새 계정 생성은 하지 않는다.
3. 비밀번호·인증코드·쿠키·세션 토큰을 채팅이나 검사 파일로 전달하지 않는다.
   일반 사용자 미리보기에서 로그인했다고 Agent의 별도 브라우저까지
   인증된 것으로 간주하지 않는다.
4. 합성 입력만 사용하고 원래 기록을 삭제/덮어쓰지 않은 채 아래 여정을
   실제 UI로 실행한다. 허용된 두 번째 계정이 없으면 계정 간 분리는 미실행이다.

## 2. Microsoft Word/한컴 실제 열기: 미실행

이 Linux 실행환경에서 접근 가능한 Word·한컴 실행 파일/GUI와 인증된
Office 웹 세션이 없었다. Word/한컴 제품 버전, 복구 경고, 페이지 수,
폰트 대체와 실제 시각적 배치는 확인하지 못했다.
다른 문서 판독기를 Word/한컴으로 간주하지 않았다.

### 가능한 범위의 인계 자료 준비: 통과

`2026-10-23T07:52:48.099Z`에 현재 내보내기 API에서 다음을 실제로
생성·다운로드했다. **계정 화면 다운로드가 아닌 비인증 합성 대조용이다.**

- `generated-artifacts/scoped-qa/nuvia-office-qa.docx`
- `generated-artifacts/scoped-qa/nuvia-office-qa.hwpx`
- `generated-artifacts/scoped-qa/expected-input.json` / `.txt`
- `generated-artifacts/scoped-qa/office-qa-guide.html`
- `generated-artifacts/scoped-qa/office-results.json`

긴 한국어 문항과 순서가 있는 90개 문단·빈 문단·기호·최종 문장이 포함된다.
DOCX는 HTTP/MIME·ZIP/XML·Mammoth 원문 순서 재판독, HWPX는
HTTP/MIME·ZIP/XML·첫 mimetype·미리보기/본문 순서 대조가 통과했다.
합성 검사결과/비공개 메모/코치/내부 식별자 표식을 추가 필드로 넣었으나
출력 패키지에는 포함되지 않았다. 검사 스크립트 타입 검사도 통과했다.
이는 **실제 오피스 앱 열기나 계정 흐름 QA 통과가 아니다.**

재현 명령:

```sh
pnpm --filter @workspace/scripts run typecheck
NUVIA_TEST_ORIGIN="https://<현재 미리보기 호스트>" \
  ./scripts/node_modules/.bin/tsx scripts/src/nuvia-scoped-office-fixtures.ts
```

이후 기존 라이선스가 있는 Microsoft Word에서 DOCX, 한컴 한글에서 HWPX와
가능하면 DOCX를 연다. 앱/버전·OS·시각, 복구/손상 경고, 한글·긴 문항·문단·
줄바꿈·페이지 경계·폰트 대체·누락·겹침·잘림을 기록한다.
첫/중간/마지막 페이지를 원문과 대조해 캡처한다. Word의 HWPX 미지원은
앱 결함으로 판정하지 않는다. 실제 로그인 QA가 가능해지면 동일 입력을
계정 화면에서 다운로드한 파일로 바꾸어 이 검사도 다시 수행한다.
