# 기업 공유 동의·행동 근거 지표·면접 확인 규칙

- 규칙 버전: 1.0 / 2026-10-27 (Asia/Seoul)
- 상태: 개발 규칙 저장 완료. 아래 기업 공유 화면·API·지표는 신규 구현 요구이며 현재 구현 완료를 의미하지 않는다.
- 적용: NUVIA 자소서와 기업 대시보드 사이의 제출·열람 계약. 기업 대시보드 전체 또는 기존 결과지·플래너를 재작성하지 않는다.
- 기준 소스: GitHub 인계 커밋 `0b17477f6f9ac18dec6d8caf6086912fdafeea1a`.

## 0. 현재 소스에서 확인한 경계

`ExpMeta`에는 `usageConsent`, `factConsent`, `consentAt`가 있지만 이는 기기 보관용 출처 부가정보다. 특정 기업의 수신 권한을 부여하는 서버 동의 레코드가 아니다. `CareerExperience.confirmed` 역시 사용자의 확인이며 기업 검증 완료가 아니다.

현재 내보내기 요청은 기업명·직무명·문항·사용자 본문·파일 형식·확인값을 전달한다. 파일에 기업명이 있다고 그 기업에 전송된 것이 아니다. 기존 DOCX/HWPX 계약을 기업 전송용으로 재해석하지 않는다. 기업 공유용 서버 계약을 별도로 추가한다.

## 1. 기업 공유 동의를 받을 화면

위치: **자소서 최종 검토·내보내기 화면**에서 기존 복사·파일 다운로드와 구분된 **기업에 공유** 버튼을 제공한다.

흐름:

`결과지 → 플래너 → 선택 경험 가져오기 → 자소서 직접 작성 → 최종 사실 확인 → 기업에 공유 → 기업용 미리보기·동의 → 공유 실행 → 공유 내역`

기업용 미리보기에서는 다음 항목을 명확히 보여준다.

| 항목 | 규칙 |
| --- | --- |
| 받는 기업·공고·직무 | 서버에서 확인한 기업/공고 식별자와 이름. 사용자 입력 기업명만으로 수신자를 결정하지 않는다. |
| 공유 목적 | 해당 지원서 검토 및 면접 준비. 다른 기업/다른 목적으로 자동 확장하지 않는다. |
| 공유 자료 | 선택한 최종 자소서 버전. 경험 근거를 함께 공유하려면 사용자가 추가로 선택한 경험의 허용 필드만 포함한다. |
| 경험 선택 | 기업용 근거의 기본 선택은 비어 있다. 본문에 적힌 내용은 본문 공유에 포함됨을 미리보기로 확인한다. 경험을 선택하지 않아도 본문만 공유할 수 있다. |
| 열람·보관 조건 | 실제 서비스가 정한 열람 종료 시점과 보관 정책, 철회 경로를 표시한다. 값이나 정책이 확정되지 않으면 실서비스 공유를 활성화하지 않는다. |
| 동의 | 기본 미선택 체크박스. 작성 사용 동의 및 사실 확인과 묶지 않는다. |
| 최종 실행 | 사용자가 직접 누르는 '동의하고 공유'에서 서버가 소유권·수신자·범위·버전을 검증한다. 성공 응답 후에만 공유 완료로 표시한다. |

동의 문구의 제품 예시: **“선택한 지원서와 경험 근거를 {기업명}의 {공고명} 지원 검토 및 면접 준비 목적으로 공유하는 데 동의합니다.”** 이 문구는 표시할 수신자·자료·열람/보관 안내를 대신하지 않는다.

기본 제외: 개인 메모, 코치와의 대화, 미선택 경험/필드, 검사 원점수·IQ·81유형 등 개인 검사 상세, 비공개 원본 URL, 내부 식별자. 강점 활용은 사용자가 공유하기로 한 구체적 행동 설명만 포함한다. 인지검사 특성으로 기업용 능력점수를 만들지 않는다.

기업은 로그인 및 수신 기업 권한 확인을 거쳐 공유된 자료만 열람한다. 공개 데모·게스트의 합성 자료는 실제 기업에 전송하지 않는다. 다운로드·복사는 공유를 거절해도 사용할 수 있다.

### 저장·재공유·철회

아래 이름은 추가 계약 제안이며 현재 API에 존재한다고 가정하지 않는다.

- 동의/공유 레코드: 공유 ID, 서버 인증 소유자, 수신 기업·공고, 목적, 선택 자료·필드 목록, 제출 버전과 근거 원본 버전, 동의 문구 버전, 동의 시각, 열람 종료 시각, 상태, 철회 시각.
- 기업 열람 자료는 그때 선택한 내용의 불변 스냅샷이다. 내용·기업·공고·공유 범위 변경 시 새 미리보기와 동의를 받고 새 공유 버전을 만든다. 기존 작성 동의에서 기업 공유 동의를 자동 이관하지 않는다.
- 중복 클릭/재시도는 동일 요청 식별자에 대해 한 번만 전송한다. 클라이언트 전달 소유자 ID·체크박스를 그대로 신뢰하지 않는다.
- 공유 내역에서 기업·자료·공유일·상태·열람 종료·철회 기능을 제공한다. 철회/만료 이후 신규 열람·다운로드·지표 집계를 서버에서 차단하며 관련 캐시도 무효화한다.
- 이미 기업이 내려받은 파일은 원격으로 회수됐다고 안내하지 않는다. 서비스 내 접근 중단과 외부 사본 처리 정책을 구분한다.
- 공유 철회가 개인의 작성문·과거 제출 버전을 자동 삭제하는 동작으로 이어지지 않는다. 보존 의무가 있는 감사 기록의 접근·보관과 일반 기업 열람은 별도로 처리한다.

## 2. 대시보드 지표 계산

### 표시명과 의미

기존 문의의 **확인 역량 수**는 **근거 확인 역량 수**, **근거 일치도(%)**는 **직무 기준 근거 확인률(%)**로 표시한다. API에 기존 키가 있다면 버전·alias 매핑으로 보존하며 조용히 의미를 바꾸지 않는다.

두 수치는 실제 능력 수준, 성과 확률, 검사 간 일치도, 인재상 적합도, 진실성 점수가 아니다. **해당 지원 건에서 직무 기준에 연결된 행동 기록을 검토한 범위**다. 툴팁에 이를 설명하고 n/N 및 기준 버전을 함께 제공한다. 이 수치로 지원자 자동 서열·합격/탈락을 결정하지 않는다.

### 분모 N

해당 기업·공고·직무에 사전 확정된, 행동으로 확인 가능한 기준의 고유 ID 수. 예: 문제 파악, 정보 비교, 우선순위 설정, 협업, 실행 점검 = 5개.

- NCS/기업 공개 기준의 출처·기준일·버전과 행동 확인 기준을 저장한다. 임의의 AI 키워드 목록을 분모로 쓰지 않는다.
- 동일 기준의 별칭은 하나로 센다. 지원자별 기록 양에 따라 분모를 줄이지 않는다. 가중치는 초기 버전에서 사용하지 않는다.
- 기준이 없거나 아직 확정되지 않았으면 `— / 기준 미설정`이다. 0으로 나누지 않는다.

### 분자 n

N개 기준 중 아래 조건을 모두 만족한 근거가 한 건 이상 연결된 고유 기준 수.

1. 해당 기업·공고에 유효한 공유 범위이고 소유권·원본 상태 확인이 성공했다.
2. 사용자가 실제 수행으로 확인한 경험이며 합성 예시·모의 활동·미분류가 아니다.
3. 구체적 행동과 관찰 결과가 있다. 결과는 숫자 성과일 필요가 없고 실패·수정·배움도 사실대로 기록할 수 있다.
4. 그 행동이 기준의 어느 항목을 뒷받침하는지 원문 인용·출처·버전으로 연결돼 있다.
5. 권한 있는 담당자가 해당 연결의 타당성을 검토하고 '근거 확인'으로 기록했다. 담당자·시각·기준 버전·검토 이유를 남긴다. 지원자의 체크박스나 AI 후보 매칭만으로 올리지 않는다.

여기서 담당자 확인은 **제출된 기록의 관련성·구체성 검토**다. 외부 증빙에 의한 사실 검증과는 다르다. 자기보고/첨부자료/면접 확인 등 확인 수준을 별도 표시한다.

- 같은 기준에 경험이 여러 개여도 n은 1 증가한다. 하나의 경험이 여러 기준을 뒷받침할 수 있지만 각각 다른 행동 근거와 연결 검토가 있어야 한다.
- 하나의 플래너 기록을 자소서에 인용한 경우 원본 식별자·버전으로 중복을 제거한다. 복사한 문장 수를 독립 근거 수로 세지 않는다.
- 모의 활동은 '모의 연습 근거'로 따로 제공한다. 실제 경험 분자에 합산하지 않는다.
- IQ·PASS/D-CAS 점수·81유형·TOP5, 강점 태그 개수, 활동 시간·수행률은 분자/분모에 사용하지 않는다.

**근거 확인 역량 수 = n개 / 대상 기준 N개**

**직무 기준 근거 확인률 = round(100 × n / N)%**

예: 확정 기준 5개 중 실제 행동 근거 연결이 담당자 확인을 통과한 기준이 3개면 **3/5개, 60%**다. '직무능력 60점'으로 표시하지 않는다.

### 빈 상태·검토 중·변경 상태

- 기준 있음 + 근거 공유 없음/공유 미동의: `— / 공유된 근거 없음`. 역량 0개나 능력 0%로 표시하지 않는다.
- 검토 중: 확인된 개수는 '현재 확인 n/N'로 표시할 수 있으나 최종 %는 `— / 검토 중`. 모든 기준이 검토 완료 또는 근거 없음으로 분류된 뒤 %를 확정한다.
- 충분한 공유 자료를 대상으로 모든 기준을 검토했으나 관련 근거가 하나도 없으면 n=0, 0% 표시 가능. '제출 자료에서 해당 근거를 확인하지 못함'을 함께 표시한다.
- 조회 오류·권한 실패는 `— / 확인 불가`. 기준/근거 버전 변경이나 모순 발견은 '재확인 필요'로 전환하고 현재 지표 확정을 보류한다. 오류나 누락을 낮은 역량으로 해석하지 않는다.
- 철회·만료 자료는 기업용 화면과 집계에서 제외한다. 남은 자료로 재검토하며 과거 %를 현재 값으로 유지하지 않는다. 과거 감사 기록은 일반 화면과 분리한다.
- 공유 범위와 기준 버전이 다른 지원자들의 수치를 동등한 능력 비교로 사용하지 않는다.

## 3. 공통 근거에 사용할 기록

'공통 근거'는 해당 직무 기준에 연결된 공유 가능한 행동 기록을 보여준다. 결과지 해석을 실제 행동으로 확인했다고 단정하지 않는다.

| 현재 자소서 데이터 | 기업에 보낼 수 있는 내용 | 주의 |
| --- | --- | --- |
| `CareerExperience.action` | 본인이 실제로 한 행동의 원문/발췌 | 경험·필드 공유 범위 확인 |
| `result`, `learning` | 관찰 결과, 배움 | 숫자·성과·성공을 임의 보충하지 않음 |
| `criterionIds` | 연결 기준 ID 후보 | 태그 선택만으로 검토 완료 처리하지 않음 |
| `ExpMeta.planner.selectedAction`, `selectionReason`, `changed`, `result`, `learning` | 플래너에서 사용자가 선택해 전송한 행동·이유·수정·결과·배움 | 지금은 기기 저장 메타데이터. 서버 원본·동의 검증 후 사용 |
| `practiceAction`, `checkCriterion`, `observedEvidence` | 연습 행동·확인 기준·관찰 근거 | 모의/실제 구분을 함께 표시 |
| `strengthStrategy`, `supportProvided`, `independentSteps` | 강점을 활용한 전략, 제공받은 도움, 본인이 선택한 단계 | 도움을 받은 것과 스스로 한 것을 분리. 공유 선택한 필드만 |
| `source`, `sourceId`, `sourceVersion` 및 제출 스냅샷 | 출처 중복 제거·당시 버전 추적 | 내부 ID·비공개 URL은 사용자/기업 화면에 그대로 노출하지 않음 |
| 자소서 최종 본문 | 같은 행동을 설명한 해당 문장 | 본문과 경험 원본을 교차 참조하되 독립 증거 두 건으로 세지 않음 |

권장 표시: **기준명 → 구체 행동 → 결과/배움 → 출처·실제/모의·검토 상태**. 현재/과거 버전을 섞지 않는다.

예: '우선순위 설정 — 예약 문의 유형을 정리하고 처리 순서를 바꿈 — 재문의가 줄었다고 기록 — 플래너 원본과 자소서 제출 문장의 연결, 실제 수행·본인 기록.' '재문의가 줄었다'는 객관 검증 수치로 승격하지 않는다.

반복 공통 근거는 서로 다른 실제 활동 에피소드 2개 이상이 같은 기준을 뒷받침할 때만 표시한다. 단일 원본을 여러 화면에서 가져온 경우 '동일 기록 연결', 독립 기록 1건뿐이면 '단일 기록 근거'다. 자료가 없으면 '공유된 근거 없음'으로 표시한다. 결과지의 강점·추천 직무와의 연결은 사용자 준비 맥락이며 기업용 능력 확인 근거 수에 포함하지 않는다.

## 4. 면접 확인사항에 사용할 기록

면접 질문은 공유된 경험의 구체적 확인 필요 항목에서 만든다. 검사상 약점·성격·IQ·인지유형에서 업무능력 부족을 추정해 만들지 않는다.

| 기록 상태 | 질문 예시 |
| --- | --- |
| 행동은 있으나 본인 역할이 불명확 | '이 활동에서 직접 맡은 일과 다른 사람이 맡은 일을 구분해 설명해 주세요.' |
| `selectionReason` 없음 | '그 방법을 선택한 이유와 비교한 다른 방법은 무엇인가요?' |
| `changed` 또는 실행 변경 설명 부족 | '계획과 달라졌을 때 무엇을 바꾸었고 왜 바꾸었나요?' |
| 결과 표현이 추상적·관찰 근거 없음 | '어떤 변화를 관찰했고, 그렇게 판단한 근거는 무엇인가요?' |
| 도움과 독립 행동이 혼재 | '제공받은 도움과 본인이 직접 정한 단계는 각각 무엇인가요?' |
| 모의 경험만 있음 | '모의 상황에서 선택한 대응은 무엇인가요? 비슷한 행동을 실제 상황에서 해본 적이 있나요?' |
| 본문과 선택한 경험의 행동/결과가 다름 | '두 기록의 설명이 다른데, 당시 상황을 구분해 설명해 주세요.' |
| 기준에 해당하는 공유 근거 없음 | '이 행동을 보여줄 수 있는 경험이 있다면 설명해 주세요.' |

질문 후보마다 기준, 경험/버전 참조, 질문을 만든 이유, 관련 원문을 연결한다. 코치의 비공개 대화는 기업으로 넘기지 않는다. 기존 코치 질문을 복사하는 대신 공유 범위 안의 근거로 면접 질문 후보를 생성한다. 기업 담당자가 검토·편집하여 사용하며 답변은 지원자 원문을 바꾸지 않는 별도 평가 기록으로 저장한다. 근거 없음은 '미확인'이지 부정적 사실이 아니다.

## 5. 구현·한국어 수용 검사·다국어 순서

먼저 한국어에서 다음 항목을 실제 테스트 계정과 합성 자료로 검증한다.

1. 작성 동의만 한 상태에서 기업 공유 API·기업 열람이 차단됨.
2. 수신 기업/공고/필드/버전 미리보기, 기본 미선택, 취소, 재공유 동의, 요청 재시도와 중복 방지.
3. 본문만 공유 가능하며 일반 복사·다운로드는 기업 공유 동의 없이 유지됨.
4. 다른 기업·다른 계정 접근 차단, 철회·만료 후 목록·상세·다운로드·집계·캐시 차단.
5. 5개 기준/3개 확인 = 3/5·60%, 중복 근거 무가산, 모의·합성·미분류·검사 점수 제외.
6. N=0, 미동의, 공유 근거 없음, 검토 중, 오류, 원본 변경, 모순, 철회 상태를 0%와 구분함.
7. 원문과 공통 근거·질문 후보의 출처를 대조. 모의가 실제 경력으로 표시되거나 도움을 독립 수행으로 바꾸는 오류가 없음.
8. 결과지 → 플래너 → 자소서 → 기업 공유 → 기업 대시보드 여정 및 기존 작성·버전·내보내기 회귀 검사. PC·태블릿·모바일에서 확인함.

한국어 검토에서 수정이 나오면 먼저 수정·재검증한다. 한국어 흐름·문구·계산 규칙 확정 후 나머지 14개 언어에 추가/의미 변경 key만 반영하고 언어별 레이아웃·RTL·입력/경로 유지·내보내기를 검수한다. 기존 검수 번역을 일괄 재생성하지 않는다. 이 단계 구분은 15개 언어 정책을 축소하거나 기존 언어를 삭제하는 뜻이 아니다.

실제 API·서버 스키마·인증·소유권·공유 이력 구현은 담당 개발자 범위다. 한국어 수용 검사, 실제 로그인 전체 여정, Word·한컴 직접 열기, 다국어 검수를 각각 별도 완료 상태로 기록한다.
