# NUVIA 독립 검토본 — 기기 기록·활동 이력 인계

## 검토본과 운영 범위

- `/demo/review` 전용이다. 기존 `/demo`와 실제 계정 작업 공간의 인증, 소유권 검사, 데이터베이스, 배포는 변경하지 않는다.
- 홈/시작의 **가상 프로필 · 이 기기 저장 및 백업**에서 프로필을 구분한다. 가상 프로필은 편의상 분리한 이름 공간이지, 이 브라우저를 공유하는 다른 사람에게 비밀인 계정이 아니다. 개인정보를 넣지 않는다. 자동 기기 간 동기화·서버 수신·연구 전송은 없다.
- 운영 구조: `review-central-contract.ts`의 `CentralReviewPersistence`는 계약/연결 지점이지 구현된 네트워크 호출이 아니다. 실제 개발자는 안정적인 중앙 세션 검증·자원 소유권 검사 뒤에 붙인다. 브라우저의 가상 ID나 URL 파라미터를 계정 증거로 받지 않는다.

## 상태, 원본, 변경 이력

| 저장 자료 | 경계와 버전 |
|---|---|
| 원본 작업대 | 원래 상태 계약·카드 ID·날짜·예정 시간·실행/중단/재개/완료·메모·기존 유효성 검사 보존. 검토 어댑터만 사용하고 운영 작업대 동작은 유지. |
| 결과와 추천 | 합성 결과의 네 원래 필드, 강점과 보완 영역, 날짜와 TOP5 순서·이유를 그대로 보존. 결과·해석·TOP5 버전과 추천 규칙 버전을 기록. 결과가 없는 카드에는 연결 참조를 넣지 않음. 인지 점수 재계산 없음. |
| 쓰기 자료 | 활동지 초안/저장 표시·수정, 자유 일상기록, 확인한 활동 출처와 버전, 적용 후보/원문/본문·확정본 및 다운로드 시도 결과를 분리. 가정 상황 생각쓰기·자기보고·사용자 확인·규칙형 후보는 근무 실적, 외부 확인, 또는 실제 AI가 아니다. |
| LAB 이용 | 검색 제출어와 조건, 결과 노출·선택·비교, 공고/직무 상세, 링크 열기 시도, 입력한 공개 자료, 상위 경로 이동. 검색/조회만으로 선호가 되지 않음. 명시 선호 목록 및 추가·해제 이력은 별도. 외부 사이트의 실제 도착·지원 여부 또는 방문 기록은 취급하지 않음. URL 인증정보·query·fragment를 분석 이력에 포함하지 않음. |
| 동의 | 개인 서비스 기록 저장과 연구 목적 별도. 연구 기본 미선택, 프로필 가명·목적·버전·기기 시각·부여·철회 이력. 백업을 다른 가상 프로필로 복원할 때 유효 연구 동의는 초기화. 검토본은 부여 후에도 전송하지 않음. |

`review-device.ts`는 프로필별 최신 값과 수정 저널의 기반이다. 저널은 각 키의 보존된 이전 값을 재현할 수 있도록 순서가 있는 문자열 변경분, 이전/다음 리비전, UUID, 의미 있는 동작, 기기 시각을 남긴다. `receivedAt:null`은 **서버 수신 없음**이다. `review-trail.ts`의 `review:activity-event:v1:*` 값은 익명 검토용 구조화 행동이며 평가 지표가 아니다. 빠른 동일 동작은 중복 반영하지 않고 의도적인 이후의 검색은 새 사건이다. 문서 이벤트는 파일을 **브라우저에 전달**했다는 뜻이지 사용자가 로컬 파일을 끝까지 저장했는지 또는 읽었는지 증명하지 않는다.

## 이관, 장애, 백업

- 기존 `nuvia:review-demo:v1:*` 탭 원문과 해당 작업대 위치를 첫 접근에 읽고, 원래 키를 지우지 않는다. 이미 기기 기본 기록이 있고 값이 충돌하는 경우 두 기록을 섞지 않고 기존 탭 데이터를 별도 복구 가상 프로필에서 연다. 기존 일시 자료의 과거 수정 시각은 만들어내지 않는다. ‘이관’ 시각만 기록한다.
- 디스크/할당량 실패는 저장 성공이 아니다. 실패한 최신 변경은 현재 화면/메모리에 남기고 경고와 재시도를 제공한다. 브라우저가 저장을 계속 거절하는 중 강제로 닫으면 미저장 입력 보존을 보장할 수 없다. 백업은 마지막으로 저장된 자료다. 길게 사용하여 브라우저 용량에 가까워지면 기존 기록을 조용히 정리하지 않는다.
- 검토용 백업은 평문 JSON이다. 기존 기록에 덮어쓰지 않고 새 가상 프로필에 복원한다. 변경 이력을 재생하여 현재 스냅샷과 대조한 후 저장한다. 실제 개인정보·운영 자료·브라우저 세션 파일은 인계 묶음에 넣지 않는다.

## 중앙 서버와 분석을 붙일 때

1. 모든 적재/조회에 기존 인증 세션과 개인 소유권을 확인한다. 같은 계정의 같은 `eventId`는 DB 유일 키로 처리하고, 다른 이벤트의 `expectedRevision` 불일치는 `conflict`를 반환한다. 복구는 원본을 건드리지 않고 사용자 변경을 별도 보존한다. 프로젝트/프로필/계정 간 자료를 섞지 않는다.
2. 원본 검사 ID·제공자·해석/TOP5 버전·아티팩트 체크섬은 참조로 저장하고 검사 원점수를 재작성하지 않는다. 카드·실행·활동지·LAB·스토리보드의 원본과 버전은 append-only 저널과 현재 읽기 뷰로 나눈다. 모든 필드는 서버에서 다시 검증하고 사용 목적·보존 정책·접근 권한에 따라 최소화한다.
3. 서버에서 받은 시각을 별도 기록한다. 기기 시각으로 정렬을 강제하지 않는다. UUID 재시도/중복은 동일 응답, 서버 반영 전에는 ‘전송 대기’, `conflict`/재시도할 수 없는 오류는 별도 표시한다. 실제 서버에 대한 전송/복원 구현과 검증은 중앙 개발자 담당이다.
4. 연구용 분석 데이터 집합은 개인 서비스 저장과 별도 승인 및 가명화로 구축한다. 연구 추출 직전 유효 동의와 철회, 정책 버전, 분석 목적을 별도로 검증한다. 검색·기록만으로 인지 능력, 성격, 채용 적합성을 확정하거나 검사 점수를 자동 변경하지 않는다. 정밀도 향상을 주장하려면 별도의 연구 설계와 검증이 필요하다.

## 최근 모바일·다운로드 수정

- 360px 작업대의 데스크톱 grid 위치 때문에 생긴 숨은 열을 검토 프레임 스타일에서 제거했다. 원본 시간·타이머·이동·메뉴 컴포넌트 자체는 사용한다.
- `/demo/review/storyboard`의 DOCX와 HWPX는 현재 공유 포맷터를 사용해 브라우저에서 생성한다. 기존 계정 작업 공간/API의 서버 문서 계약은 유지한다. 원래 개발 프록시는 현재의 합성 요청에서 정상 응답했으며 앞서 보고된 연결 장애의 당시 원인은 확정하지 않는다. 실제 다운로드와 구조 판독은 데스크톱 Word/한컴 직접 열기 확인과 구분한다.
