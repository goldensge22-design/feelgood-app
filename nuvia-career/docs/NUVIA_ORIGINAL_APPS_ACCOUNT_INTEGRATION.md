## 데이터와 사용자 경계

- `/lab`은 로그인한 사람의 자기설정에 따라 원본 진로 LAB과 기업직무 LAB을 분리한다. 자기설정은 중앙 서버의 권한·연령 검증이 아니다. 기존 Clerk 세션으로 요청하고 `/api/career/workspace`의 소유자별 JSON 및 revision을 재사용한다. `ownerId`를 브라우저나 외부 링크에서 받아 신뢰하지 않는다. 무인증으로 `/api/career/original-enterprise`와 `/api/career/workspace`에 접근하면 거절된다.
- `youthLab`은 원본 진로 LAB 상태(버전 1), `youthLabRecovery`는 충돌 시 별도 보관한 초안이다. 첨부에 실제 결과지가 없으므로 원점수/검사 자료를 불러오지 않는다. 사용자가 직접 쓴 강점은 검사 수치·결과와 별개다. 진로 LAB의 원래 외부 AI/검사 추출은 연결하지 않는다.
- `labHandoffs`에는 자기설정 범주, 원본 식별자/버전, 제목·사용 선택 키워드·짧은 발췌·공개 링크(있을 때), 모의/탐색, 승인/철회 시각, 플래너 카드 접수 참조를 보관한다. 확인 카드에는 공유되는 부분만 표시한다. 미리보기 취소는 저장하지 않는다. 발췌는 탐색/모의 재료이며 완료·성과·실무 경력으로 기록하지 않는다.
- 승인 후 같은 계정의 플래너 선반에 원본 작업 생성 명령을 사용한다. 네이티브 `requestId`는 같은 승인으로 카드 둘을 만들지 않는다. 철회 후 별도로 다시 동의할 수 있으며 이미 기록한 원본과 예전 문서 버전은 유지한다. 진로 LAB 활동 원본이 수정되면 새 작성에서 다시 확인해야 한다.
- 스토리로는 학생이 골라 확인한 실제 발췌나 모의 생각만 전달한다. 모의 자료에서 생성된 작업은 스토리 전송에서 ‘생각 연습’으로 고정한다. 결과·성과·합격 가능성은 만들지 않는다. 버전에는 출처와 자료 버전 참조가 남고, 사용자가 쓴 본문을 우선한다. 기업 제출/연구 전송을 추가하지 않았다.
- 동시 편집은 기존 서버 revision으로 충돌을 거절한다. 진로 LAB 사본과 기존 계정 복구 동작을 보존한다. 철회된 자료가 오래된 사본에서 저절로 다시 승인되지 않는다. 별도 계정 서버/새 테이블/자동 마이그레이션을 추가하지 않았다.
- 중앙 D-CAS 실제 자료, 별도 Replit 간 서비스 인증, 중앙 운영 SSO/배포는 이 검토본 연결과 다르다. 실제 결과지는 `/report`에서 없음을 표시한다. 계정 스토리의 규칙형 미리보기는 실제 GPT 생성으로 표시하지 않는다. 계정 자소서의 기존 AI 도움은 남아 있으나 이 패치는 새 모델 시험을 수행하지 않는다.

개발 재현: 기존 Replit 웹/API 워크플로와 Clerk 개발 환경을 사용한다. `/sign-in?account=lab&lang=ko`로 로그인 후 홈에서 청소년/성인을 선택한다. 청소년 `/lab/majors`, 성인 `/lab`에서 원본 자료 확인 → 플래너 선반 → 작업대 → 확인한 기록 연결 → 스토리 버전 저장. 변경 전후 해시와 실제 검사 증거는 인계 ZIP의 `MANIFEST.json`과 `qa/`를 참조한다.
