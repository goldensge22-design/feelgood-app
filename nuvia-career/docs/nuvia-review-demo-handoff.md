# NUVIA 강점 스토리보드 검토용 데모 인계

## 실행

기존 Career 웹과 API 워크플로를 실행해 `/demo/review?lang=ko`를 연다. 설치·계정·비밀번호 입력 없이 **데모로 시작**을 선택한다. 개발 링크는 워크스페이스 미리보기이고 공개 배포 주소가 아니다.

1. **MY NUVIA**: 검사 당사자와 보호자 관점으로 플래너·히스토리·강점 스토리보드를 본다. 결과를 먼저 보려면 **결과 보기**를 선택한다.
2. **결과지**: 가상 대학생 한별의 네 처리 영역 도움 예시를 읽고 기업·직무 LAB으로 간다. 점수나 실제 검사 결과는 없다.
3. **LAB → 플래너**: 가상 기업·직무를 하나 고르고 **플래너 행동카드 만들기**로 간다. 목표, 오늘의 상황, 할 행동, 완료 기준, 계획 시점을 직접 작성한다. 미리 보고 확인한 뒤 추가한다. 원하는 만큼 다른 카드를 추가할 수 있다.
4. **플래너 → 히스토리**: 계획은 카드별로 수정한다. 시작·멈춤·재개 및 완료 표시는 사용자가 직접 한다. 본인이 한 행동과 관찰 결과, 배운 점 또는 다음 행동을 기록한다. 실행하지 않은 계획이나 빈 결과는 기록으로 만들어 내지 않는다. 히스토리에서 정확한 카드와 기록 버전을 확인하고 **이 기록 사용하기**를 선택한다.
5. **스토리보드**: 선택한 카드의 기업·직무·키워드와 사용자 확인 기록을 표시한다. 네 장면에 직접 입력한다. 사실 및 사용 범위를 확인하고 확정한다. 원본 카드가 수정되면 최신 버전을 다시 확인하고 확정해야 내보낼 수 있다. 이전 본문과 확정 버전은 그대로 남는다.
6. **이어쓰기**: 다른 화면이나 뒤로가기로 이동하거나 새로고침해도 같은 탭에 남는다. **체험 나가기**는 시작 상태만 종료한다. 같은 탭에서 다시 시작하면 미리 저장하지 않은 입력도 이어 쓸 수 있다. 교사 안내는 별도 읽기 경로이며 계정 접근이 아니다.

## 변경·보존 경계

- 새 경로는 `/demo/review` 하위에서만 동작한다. 기존 `/demo`, `/storyboard`, `/write`, `/?view=summary`, 기존 지원 문항·경험·버전·내보내기 경로는 그대로다. 기존 작업 공간으로 돌아가는 링크를 둔다. 새 데모에서 기존 계정/게스트의 실제 기록을 읽거나 옮기지 않는다.
- `nuvia:review-demo:v1:`의 `sessionStorage`를 사용해 기존 합성 데모·게스트·계정과 저장 키를 분리했다. 계정 영구 저장, 탭 종료 후 복원, 기기 간 동기화를 제공하지 않는다. 브라우저의 탭 복원 동작에 의존해 개인정보를 보관하지 않는다.
- 새 데모는 인증 제공자를 시작하지 않는다. 결과지·LAB은 내장 가상 예시이고, 플래너의 계획·기록은 각 탭에서 직접 작성한다. 기존 고정 샘플은 그 샘플을 사용하는 과거 초안 호환에만 남겨 둔다. 실제 AI 호출을 하지 않는다.
- 스토리보드 편집기는 기존 확인·저장·버전 컴포넌트를 재사용한다. 다시 같은 선택으로 들어와도 사용자가 입력한 회사·본문·이력을 덮어쓰지 않는다. 다른 기업·직무를 적용하면 확인을 다시 받고 기존 본문과 이전 버전은 보존한다.
- TXT/PDF는 브라우저에서 생성한다. DOCX/HWPX는 기존 개발 문서 생성 API에 확정한 기업·직무·제목·본문만 전송한다. 데모 문서 요청에서 인증 쿠키를 생략하며 계정 저장을 하지 않는다. 종전 HWP/DOC 제한은 변경하지 않는다.
- 기존 15개 언어 선택과 편집기 번역을 유지한다. 로그인 체험·홈·결과·LAB·플래너·히스토리는 한국어 검토본이며 전체 15개 신규 여정 번역을 완료한 것이 아니다. 언어를 바꿔도 학생 원문은 번역하지 않는다.

## 개발자가 이식할 때

- 새 화면: `src/pages/review-demo.tsx`, `src/components/review-demo-view.tsx`.
- 가상 입력과 선택 연결: `src/lib/review-demo-fixture.ts`, `src/lib/review-demo-state.ts`. 카드와 기록: `src/components/review-planner-view.tsx`, `src/lib/review-planner-model.ts`, `src/lib/review-planner.ts`. 카드 버전 확인은 이 탭 안의 명시적 승인이지, 외부 사실 검증 또는 계정 동의가 아니다. `다음 행동`과 계획 세부 항목은 모의 활동 이력에만 유지한다.
- 기존 재사용 지점: `App.tsx`, `public-demo.ts`, `workspace.tsx`, `provenance.ts`, `pages/storyboard.tsx`, 문서 생성 호출.
- ZIP의 `MANIFEST.json`에 기준 Git 커밋, 실제 포함 파일과 SHA256, 최종 소스 지문을 기록한다. `career-dashboard.patch`는 이전 검수 기준 이후의 **누적** 변경이다. 중앙본의 같은 파일 해시가 다르면 강제로 적용하지 말고 필요한 변경만 대조 이식한다.
- 실제 인증/권한, 원본 보고서와 LAB/플래너 송수신, 중앙 계정 저장, 배포는 연결하지 않았다. 중앙 앱의 홈·교사 역할 권한도 변경하지 않았다.
- 명령: `pnpm --filter @workspace/nuvia-career typecheck`, `PORT=24976 BASE_PATH=/ pnpm --filter @workspace/nuvia-career build`, `NUVIA_TEST_ORIGIN=https://<승인된 개발 미리보기 호스트> pnpm --filter @workspace/scripts exec tsx src/nuvia-review-planner-qa.ts`. 다운로드 검사에는 Chromium, Python, `pdfinfo`·`pdftoppm`이 필요하다. 이전 `nuvia-review-demo-journey-qa.ts`와 `...download-qa.ts`는 고정 샘플을 보내던 구버전 `ec689e0` 재현용이다.
- 최신 증거는 `qa/review-planner/RESULTS.md`와 같은 폴더의 `browser-results.json`, 파일·화면에서 확인한다. 이전 QA는 이번 통과 수에 합산하지 않는다.
