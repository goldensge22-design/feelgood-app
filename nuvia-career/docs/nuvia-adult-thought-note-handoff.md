# 성인 검토본: 오늘의 생각 한 장

## MY NUVIA의 일상 이용과 홈 화면 추가

- 홈 제목 아래 4단계는 길 안내이지 LAB을 매일 거쳐야 하는 필수 경로가 아니다. 플래너 5~10분 기록은 바로 시작할 수 있다. 스토리보드는 사용자가 자료를 고르고 후보를 명시적으로 적용할 때만 본문이 바뀐다.
- 검토 주소(`/demo/review/home?shortcut=home`, `/demo/review/planner?shortcut=planner`)는 목적지와 파라미터가 일치할 때만 작동하며, 독립적인 합성 체험을 연다. 일반적인 데모 진입, 계정 로그인, 인증·세션 관리는 변경하지 않는다. 새 브라우저 탭/창 또는 기기에서 데모 자료는 합쳐지지 않는다.
- 두 웹 매니페스트의 식별자·시작 URL·범위를 분리하였다. 설치 준비 페이지를 새 문서로 열어 해당 문서에 하나만 연결한다. 조건에 맞는 브라우저 설치 신호가 있을 때 명시적 클릭으로만 브라우저에 요청한다. 브라우저 선택 수락과 브라우저가 보낸 설치 완료 신호를 구분한다. 기설치 여부를 장치에서 직접 조회하지 않는다. 앱 창이라는 사실만으로 다른 별도 앱의 설치를 추정하지 않는다. 브라우저가 설치를 제공하지 않거나 독립 두 개를 지원하지 않으면 해당 페이지의 바로가기 또는 북마크를 사용한다.
- 서비스 워커/오프라인 저장을 추가하지 않았다. 실제 도메인에서 탭/앱 창 인증과 로그인 반환 경로, 사적 기록 권한 및 계정 동기화는 중앙 담당 개발자가 기존 인증·저장 체계와 연결해 검수한다. 검토 경로를 실제 인증의 대안으로 사용하지 않는다.
- 실제 기기 승인 전에는 iOS Safari 공유 메뉴로 추가한 두 아이콘, Android Chrome 앱 설치/페이지 바로가기, PC 앱 설치/북마크, 인앱 브라우저 → 일반 브라우저 이관을 각각 시도하고, 최초/재실행 목적지·취소·기설치 안내를 확인한다.

## 검토본 시작과 소개

진입: 기존 Replit 앱의 `/demo/review?lang=ko` → **성인 데모로 시작** → **MY NUVIA**. 가상 결과지 → 기업·직무 LAB → 오늘의 생각 한 장 → 활동지 → 플래너 일상기록 → 나의 강점 스토리보드 → 최종 확인·다운로드. 성인 화면의 단계별 다음 버튼으로 진행하며, 홈의 **이어서 하기**는 마지막 작성 화면이나 개별 카드를 연다. 성인에게 히스토리는 없고 예전 주소는 플래너에 연결한다. 아동·보호자 경로와 교사 안내, 기존 자소서 경로 및 검토 탭의 예전 기록을 유지한다. 이 자료는 중앙 운영본 업데이트가 아니다.

체험을 나갔다 같은 탭에서 다시 들어와도 복귀 위치·입력·버전은 유지한다. 활동지에서 생각을 적은 다음 **저장하고 플래너로 가기**는 두 저장이 성공한 뒤만 이동한다. 플래너에서는 활동지 내용을 직접 불러와 확인·기록하고, 한 건을 바로 사용하거나 여러 건을 고른다. 생각 연습을 실제 수행으로 표시하지 않으며, 스토리보드 후보 적용·최종 확인과 다운로드는 별도 사용자 행동이다.

### MY NUVIA 홈 · 기존 화면 기준

이 저장소에는 중앙 로그인 후 MY NUVIA의 원본 페이지나 공통 레이아웃이 없다. 사용자가 직접 확인한 화면 구조를 따라, 독립 검토본에서 기존 공통 색상·언어 선택기를 사용해 시각 검토용으로 재현했다. 운영 화면에 반영할 때는 중앙 앱의 기존 탑바·카드·데이터 어댑터를 재사용하고 안내 문구·자소서 카드의 명칭/진입만 병합한다. 중앙 로그인 화면, 인증/소유권, 서비스 주소나 네비게이션을 통째로 치환하지 않는다.

- 첫 화면의 기존 데모 로그인 카드에 짧은 순서 안내만 두며, 별도 홍보 상자는 두지 않는다. 홈은 인지 프로파일/MY GROWTH 2열, 기업 LAB·NUVIA PLANNER·나의 강점 스토리보드의 동일 크기 3열이다. 휴대폰에서는 같은 순서로 카드가 세로로 놓인다.
- `HomeReportSummary`는 독립 검토본의 **표시용 형태**이며 운영 인증 API 계약이 아니다. 승인된 원본에서 `areas`의 값·표시명·순서·단위, `scale`, `assessedOn` 원문과 강점/성장 포인트 해석을 받아 그대로 보여 준다. 자릿수까지 보존할 필요가 있는 수치는 원본 표시 문자열로 전달한다. `0`은 값으로 유지하고, 누락값에 0·표준점수·IQ·백분위를 덧붙이지 않는다. 강점과 성장 포인트는 점수에서 생성하지 않는다.
- 데모의 숫자와 날짜, TOP 5의 다섯 직무는 새로 만든 가상 자료이고, 실제 결과는 미연결이다. MY GROWTH는 TRAIN·THINK·MANAGE·METACOGNITION 세로 목록으로 영역별 자료 부족만 보여 준다. 수치·강점·성장 포인트는 각각 옅은 파랑/파란 숫자·옅은 주황·회색으로 표시한다. `topJobs`는 원래 순서·직무명·이유·출처를 그대로 보여 주며, 예를 들어 원본이 두 건이면 두 건만 보인다. `reviewRole`은 가상 직무를 가상 LAB에서 고르기 위한 검토본 전용 키다. 운영 연결에서는 기존 직무 식별자와 인증된 저장 방식을 사용하고, 자료가 없으면 LAB의 직접 탐색은 열어 둔다.
- LAB의 기업 추천·탐색은 가상 자료와 검색어를 일치시키는 체험이다. 자료 없음 → AI로 찾아보기/분석 도움은 LAB 안에서 기업 조건·직무·궁금한 역량을 입력한 뒤, 합성 기업 후보·역량 가설·확인할 공식 공개자료 목록을 검토하고 후보 선택 또는 검색으로 돌아오는 흐름이다. 출력은 자료 기반 사실·실시간 검색·AI 호출을 가장하지 않는다. 기존 인증된 AI는 문장 작성 도움이고 LAB 조사 계약이 아니다. 담당 개발자는 LAB의 인증된 검색/조사 경로, 승인된 입력·전송 동의·소유권·검증 가능한 출처/버전이 제공될 때만 실제 도움을 붙인다. 자소서 AI로 이동하거나 인증을 약화하지 않는다.
- 활동지에서 **저장하고 플래너로 가기**가 성공한 뒤에만 이동한다. 플래너에서 기록과 작성 사용을 확인한 후 **기록 저장하고 나의 강점 스토리보드로**를 선택하면 먼저 그 기록을 저장하고 스토리보드 작성 자료에 등록한다. 성공한 자료는 같은 버전일 때 확인을 다시 받지 않으며, 실패 시 위치와 원문을 보존하고 플래너 저장과 스토리보드 연결의 성공 여부를 구분한다. 같은 근거 묶음에서 이미 확인해 연결한 자료와 작성글·확정본은 그대로 남는다.

## 추천과 사용자 입력

- LAB의 두 기능: **기업·직무 키워드 분석과 결과지 강점 매칭**, **오늘의 생각 한 장 만들기**. 기업 자료와 결과지 예시는 합성이며 점수나 적합률을 생성하지 않는다.
- 활동은 아침에 한 일·대략의 시간 적기, 20분 남은 약속에 어느 길로 갈지 생각하기, 준비물 다시 보기로 시작한다. 보완영역은 제안 순서·도움말의 양, 강점은 도움말 방식에 사용한다. 직무 필요역량은 상황을 다시 쓰지 않고 끝의 접힌 활용 설명에만 연결한다. 보완영역이 없는 가상 프로필에서는 추천을 막고 연결 필요 안내를 표시한다. 직접 기록은 항상 가능하다.
- 추천은 5분 기본, 10분은 선택. 글은 짧아도 저장된다. 등록한 계획·활동지와 플래너에서 실제로 확인한 기록을 분리한다. `한 장 더 만들기`는 새 카드이며 같은 카드의 등록 중복은 같은 요청으로 처리한다.
- 플래너 `일상 직접 기록`은 추천 카드·LAB 선택 없이 별도 기록을 만든다. 같은 날 여러 카드와 여러 직접 기록을 저장하고 원본별로 이어 쓸 수 있다. 아침 일상 기록과 가정 상황의 선택 기록, 별도로 본인이 적은 실제 적용을 표시한다. 내용의 진위나 숙련도를 자동 검증하지 않는다.
- 복수 기록은 확인한 최신 버전만 사용한다. 계획, 다른 직무의 카드, 미저장 수정은 선택을 막는다. 직접 기록은 LAB 없이도 사용할 수 있다. 재매칭하거나 원본을 수정하면 이전 문장을 보존하고 재확인을 요구한다.

## AI 및 문서

- 데모의 두 후보는 규칙 기반이며 실제 AI 요청을 보내지 않는다. 후보 적용 전 원문과 생각 입력 및 활동 선택은 이 브라우저 탭에만 남는다. 결과지·직무·자료가 변경되면 오래된 후보는 적용할 수 없다.
- ‘선호 표현’은 데모에서 메모로만 저장한다. 말투 지시를 사실이나 자기소개 문장으로 붙이지 않는다. 기존 방식으로 생성된 다듬기 후보는 비교용으로 보존하지만, 다시 만들기 전 적용을 막는다. 본문과 확정 버전은 바뀌지 않는다.
- 비교의 ‘내 원문’은 편집기 현재 본문을 읽는다. 후보 적용 때마다 마지막 적용 직전 글을 별도 보관해, 근거를 다시 확인하더라도 후보·복원용 이전 글·V1 확정 버전이 서로 바뀌지 않는다.
- 한국어 실제 계정 경로의 스토리보드는 기존 `/api/career/ai-jobs` 인증·계정 범위·요청 조정을 사용한다. 현재 계정의 확인된 실제/모의 기록과 선택적으로 동의한 결과지 해석만 모델에 보낸다. 연결된 자소서에 당시 사용자가 검토한 동일 직무 근거가 있으면 출처 버전과 함께 보낸다. 다듬기에서만 해당 장면의 본문과 사용자의 생각을 추가한다. 다른 계정의 자료, 검토 데모 데이터, 원본 점수 구조, 비공개 메모와 미선택 기록의 전송을 금한다. 후보는 자동 삽입되지 않으며 원문으로 돌아갈 수 있다.
- 문서는 확인된 본문만 TXT/DOCX/HWPX/PDF로 생성한다. PDF는 한글 등 브라우저 글리프를 사용한 A4 이미지 기반 출력으로, 길면 글자를 줄이지 않고 페이지를 추가한다. `.hwp`와 `.doc`를 대체 확장자로 내보내지 않는다. QA 기록에서 생성·판독과 Word/한컴 열기를 구분한다.
- 새 데모 및 계정 AI 화면은 한국어 검토 대상이다. 기존 15언어 편집기와 번역은 변경하지 않았다.

## 운영 개발 인계

별도 승인된 결과지·LAB·플래너 계약에 따라 원래 강점과 보완영역, 직무 근거의 출처·버전, 일상기록 성격·사용동의·원본 소유자·수신 및 철회를 연결한다. 프로그램 프로젝트 링크를 API 주소로 사용하지 않는다. 계정 후보와 생각 입력은 해당 계정 브라우저의 탭 저장이며 새 영구 서버 저장이 아니다. 운영 배포·중앙 통합·GitHub 원격 푸시는 이 패치에서 수행하지 않는다.
