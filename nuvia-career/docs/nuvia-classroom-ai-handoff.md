# 55명·5시간 수업용 AI 비용/혼잡 보강 인계

**최신 긴 대기 보강:** 작성 화면은 비동기 접수·자동 상태 조회를 사용한다. 정상 큐 대기를 180/200초 오류로 끝내지 않는다. `docs/nuvia-async-ai-handoff.md`와 최신 ZIP `qa/async30-final.json`, `qa/async-browser.json`이 우선한다. 아래 200/210초 설명은 이전 동기 호환 경로다. 실제 AI 모델·공유 호출 상한은 유지한다.

## 적용 범위와 운영 판정

기존 NUVIA/FeelGood 자소서 누적 패치다. 기존 경험/STAR/직접 작성/학생 사실 확인/AI 전송 동의/버전/내보내기를 유지한다. 고정 질문을 AI 성공으로 표시하지 않는다. 운영 `nuvia.feel-good.io/career`의 원본 프로젝트와 이번 작업본의 배포 연결은 미확인이다. 이번 작업은 Replit 작업본과 합성 QA/인계 패키지이며 **운영 수정·공개 배포·55명 운영 동시 사용 보증이 아니다**. 결제/자동충전/공개 권한/Clerk/기존 사용자 테이블·기록은 변경하지 않는다. 이번 추가분은 기존 개발 PostgreSQL에 AI 조정용 테이블 3개를 더한다. 운영 DDL이나 시작 시 자동 DDL은 없다.

## 오류와 보존

| 오류 코드 | 의미 | 자동 재시도 |
|---|---|---|
| AI_LOCAL_LIMIT | 계정당 고유 요청 8회/분 | 없음 |
| AI_CLASS_LIMIT | 계정당 30회/5시간 또는 공유 공급자 시도 1,100회/5시간 | 없음 |
| AI_QUEUE_FULL | 대기열 60개 초과 또는 대기 기한 초과 | 없음 |
| AI_PROVIDER_BUSY | 공급자 일시적 429; 상세 코드 미제공이면 결제라고 단정하지 않음 | Retry-After 10초 이하일 때 최대 1회 |
| AI_USAGE_LIMIT | 공급자 명시 quota/billing 코드 또는 HTTP 402 | 없음, 전체 공급자 호출 5분 보류 |
| AI_UNCERTAIN / AI_TIMEOUT | 공급자 요청 후 응답 완료 불명/시간초과/중단 서버 | 없음, 중복 방지 원장이 있는 동안 동일 요청 재생성 금지 |
| AI_UPSTREAM_FAILED / AI_INVALID_RESPONSE | 전송/공급자 실패 또는 잘못된 응답 | 없음, 동일 요청을 자동 재생성하지 않음 |
| AI_INPUT_LIMIT | 목적별 선택 자료 12,000자 초과 | 없음, 선택 축소 안내; 원문 자르지 않음 |
| AI_NOT_CONFIGURED | 연결 설정, 서버 간 비밀값/조정 정책 불일치 | 없음 |
| AI_COORDINATION_UNAVAILABLE | 공유 DB 조회/갱신 불가 | 공급자 호출 없이 중단; 명시적 재확인 가능 |
| AI_COORDINATION_WAIT | 접수 후 200초 내 완료 확인 안 됨 | 원장 유지, 같은 요청으로 진행 상태 재확인 |
| AI_RESULT_EXPIRED | 5시간 보관 결과 만료 | 원장을 보고 동일 요청 자동 재생성 금지 |

일시적 공급자 429와 로컬 제한·대기·이용한도/결제를 구분해 15개 기존 UI 언어로 안내한다. 새 번역은 내부 검토 수준이며 원어민 미검수다. 본문·답변·STAR를 오류 처리에서 수정/초기화하지 않는다. 자동 생성문 삽입은 없다. 사실 확인과 외부 AI 전송 동의는 기존대로 요청마다 필요하다. 기업 공유 동의와 별개다.

## 비용·개인정보 경계

- 인증된 서버의 사용자 ID를 서버 전용 HMAC에 포함한다. 같은 선택 자료라도 계정이 다르면 응답을 공유하지 않는다. 원문/사용자ID/경험ID/키/인증 헤더를 사용량 로그에 쓰지 않는다.
- 같은 계정·같은 목적·같은 실제 선택 내용은 진행 중 1건으로 합치고 성공 결과를 최대 5시간 재사용한다. 자료 버전/원문/문항/작성 언어/선택 화법 변경은 다른 요청이다. UI의 소스 지문만 바뀌면 캐시 내용은 재사용하되 현재 지문을 다시 부여하며, 기존 화면의 늦은 응답 차단은 그대로 유지한다.
- 성공 결과는 AES-256-GCM으로 암호화해 공유 DB에 최대 5시간 재사용한다. 계정과 요청 해시를 AAD에 묶어 다른 계정의 암호문을 대입해도 해독하지 않는다. 평문 프롬프트·선택 원문은 DB 조정 테이블에 저장하지 않는다. 재사용은 원래 모델 결과이지 새로운 모델 생성 성공이 아니다.
- 5시간이 지나면 다음 공유 조정 시 만료 암호문을 지운다. 요청/계정 해시·상태·시도수·토큰 등 중복 방지 원장은 유지하며, 단순 결과 만료로 새 유료 생성을 허용하지 않는다. `retainUntil`은 향후 개인정보 보존 정책 검토용 값이지 자동 삭제 작업이 아니다. 현재 원장은 자동 삭제하지 않으므로 운영자는 보존·삭제 정책을 확정해야 한다. 삭제하면 해당 기간 중복 방지 증거도 사라진다.
- 질문/분석에는 화법 원문을 보내지 않고, 화법 요청에는 경험·결과지·지원서 본문을 보내지 않는다. 질문 1개, 문장 후보 2개(각 최대 2문장), 화법 규칙 최대 3개를 지시한다. 선택 사실은 임의로 자르지 않고 너무 길면 요청을 거절한다.
- 기존 모델 `gpt-5.6-luna` 유지. 출력 상한 coach 768 / draft 1,800 / analyze·voice 1,200 토큰. 구조화 JSON 응답 + 기존 생성 계약 검증을 병행한다. 짧은 토큰 상한이 실제 비용을 같은 비율로 줄였다는 뜻은 아니다.
- 화면 표시/편집/저장/기본 검사/캐시 재사용은 공급자 호출을 하지 않는다. 별도 주기적 AI 분석·자동 문장 재생성은 없다.

## 공유 PostgreSQL 조정 정책과 필수 운영 인계

공유 DB 기준 동시 공급자 호출 최대 4, 시작 간격 최소 2초(최대 약 30회/분), 대기열 60, 최초 대기 상한 180초, 공급자 시도당 45초, 접수부터 응답 확인 전체 200초, 브라우저 210초. 전송 전 취소는 대기를 멈추고, 마지막 대기자의 임대가 끝나면 다른 대기 요청을 막지 않는다. 원격 전송을 이미 예약한 경계에서는 취소해도 1회 호출될 수 있다. 전송 후 브라우저 연결 종료는 모델 재호출/전체 작업 취소가 아니라 결과 저장과 다음 접속 재사용으로 이어진다. 이미 공급자가 처리한 요청은 취소해도 과금될 수 있다.

**현재 실제 라우트는 `SharedCareerAi`를 사용한다.** 이전 메모리 큐는 과거 검사의 비교용으로 남았으며 실패 시 대체 경로가 아니다. 공유 DB의 단일 조정 행 잠금으로 접수·전송 예약·공급자 시도 상한·계정 한도·혼잡/결제 회로를 원자적으로 갱신한다. 운영 연결 담당자는 다음을 확인해야 한다.

1. 운영 `/career`의 실제 API/배포 커밋/OpenAI 프로젝트와 지원 모델을 식별한다. 모든 AI 요청을 새 공유 경로로 통일하고, 예전 메모리 큐 서버와 혼합 운영하지 않는다. 기존 메모리 캐시를 DB로 복원할 수 있다고 주장하지 않는다.
2. 모든 API 복제본에 동일한 기존 PostgreSQL·32자 이상 `SESSION_SECRET`·조정 정책이 필요하다. 키나 정책이 다르면 안전하게 거절한다. 키를 임의 교체하면 안 되며, 교체하려면 기존 원장·암호문 유지/전환 절차를 별도 검토해야 한다. 새 키를 자동 생성하거나 서버별 키를 쓰지 않는다.
3. `lib/db/src/schema/career-ai.ts`의 추가 테이블을 기존 DB 배포 절차로 적용한다. 개발 DB에는 적용·검증하며 운영 DB는 이번에 접근/변경하지 않는다. Replit 관리 DB는 지원되는 게시 스키마 절차, 외부 DB는 담당자의 승인된 마이그레이션을 사용한다. 앱 시작 DDL은 없다.
4. 전송 전 대기는 다른 서버가 동일 자료로 이어갈 수 있다. 전송 의도를 커밋한 후 서버가 죽으면 90초 임대 뒤 `AI_UNCERTAIN`으로 남겨 절대로 자동 재전송하지 않는다. 원래 서버가 뒤늦게 결과 저장을 완료하면 같은 토큰의 결과만 수용하고 재접속에서 재사용한다. 공급자 처리 여부 자체를 알 수 없는 단절에서 ‘정확히 한 번 생성’과 ‘무조건 자동 재생성’을 동시에 보장할 수 없으므로, 확인 필요 상태는 숨기지 않는다.
5. 실제 OpenAI 모델의 RPM/TPM/프로젝트 지출 한도를 확인한다. 앱의 30RPM은 공급자가 보장하는 한도가 아니다. 본 패치는 달러 단위 예산/자동충전을 변경하지 않는다.
6. 원래 UI 프록시의 응답 시간 제한이 210초 대기를 허용하는지 확인한다. 먼저 끊겨도 원장은 남고 같은 요청으로 재확인한다. 확인 전 55명 운영 준비 완료로 표시하지 않는다.

## 원문 없는 관측

`Career AI capacity` 구조 로그의 `coordinator=postgres-v2`를 확인한다. `shared_dispatch`는 공급자 예약 시도와 대기 ms, `shared_reuse`는 완료 결과 재사용, `shared_result`는 이 처리자가 전송한 결과, `shared_finish`는 상태·안전 오류코드·공유 기간 누적 호출/입력/출력 토큰을 기록한다. `provider_usage`는 해당 호출의 공급자 반환 inputTokens/outputTokens/cachedInputTokens/totalTokens다. 공급자 오류는 allowlist 코드와 HTTP 상태만 남기며 원문 응답 본문은 버린다. 사용량 없는 실패는 `usage_unknown`이므로 0원/0토큰이라 가정하지 않는다. 중단된 프로세스가 공급자 사용량을 받지 못하면 실제 청구는 공급자 프로젝트에서 대조해야 한다.

공유 DB에는 요청별 시도수·대기시간·반환 사용량과 전역 누적 호출/입력/출력 토큰을 기록한다. 사용자 원문·원래 사용자ID·키를 통계로 노출하지 않는다. 대기·만료·중단 상태와 `coordination_unavailable`, `completion_not_committed`를 구별한다. HTTP `X-AI-Reused`, `X-AI-Queue-Ms`, 오류 `Retry-After`와 `private, no-store`를 유지한다. 공개 통계 API는 추가하지 않는다.

## QA 및 예산

새 결과는 ZIP의 `qa/` 및 `qa-summary.json`, `budget.json`을 본다. 과거 고정 질문/한국어 QA를 이번 비용·부하 검사로 재사용하지 않는다.

- 모의 공급자로 55개 합성 계정 식별자를 사용한다. 55개의 실제 Clerk 계정/운영 사용자를 생성한 부하 시험이 아니다.
- 원문·계정 간 격리/중복/제한/timeout/취소/모의 quota와 실제 모델 연결 시험을 구분한다. 2초 실제 간격의 모의 55명 시험을 포함한다.
- 이전 단계의 실제 모델 소수 시험과 최초 형식 실패·수정 재검사 기록은 과거 근거다. **이번 공유 조정 추가분은 실제 모델 호출 0회**이며 모의 공급자로만 검사한다. 과거 실제 호출을 이번 실행으로 합산하지 않는다.
- 모델 비용은 공급자 사용량의 실제 토큰과 모델 단가로 계산한다. 이번 환경에서 신뢰할 수 있는 해당 요청의 달러 청구 내역/정확한 단가를 확인하지 못했으므로 달러 가격을 만들어내지 않는다.
- 실제 `/career` 운영 연결, 운영 로그인/SSO/다중 서버 권한, Word/한컴 직접 열기, 원어민 검수는 별도 미검증이다.

## 운영자의 OpenAI 직접 연결(BYOK) 유지

사용자는 2026-11-15 운영 키 조직이 **Personal**임을 확인했고, 승인된 **5달러 충전 후 운영 질문 1회·문장 후보 1회·검토 후 V2 저장 성공**을 알렸다. 이는 사용자 확인 운영 결과이며 이번 Agent의 운영 호출/청구서 검증은 아니다. 이전 0달러·조직 동일성 미확인 설명은 과거 관찰로 대체한다. 현재 잔액·운영 모델·토큰/청구액을 추측하지 않는다. 이 패치는 어느 키/결제/조직/자동충전도 변경하지 않으며 추가 실제 AI 호출을 하지 않는다.

서버 전용 설정(값을 프런트엔드나 저장소에 넣지 않음):

| 방식 | 명시적 선택 | 키·주소·모델 |
|---|---|---|
| 개발 관리형(기존 기본값) | `CAREER_AI_PROVIDER=managed` 또는 미지정 | 기존 `AI_INTEGRATIONS_OPENAI_API_KEY`, `AI_INTEGRATIONS_OPENAI_BASE_URL`; 모델 기본 `gpt-5.6-luna` |
| 운영 OpenAI 직접 | `CAREER_AI_PROVIDER=openai` | 기존 `OPENAI_API_KEY` 사용, `OPENAI_BASE_URL` 미지정 시 공식 `https://api.openai.com/v1`; `CAREER_AI_MODEL`은 운영자가 사용 권한·호환을 확인한 실제 모델명을 **필수 지정** |

`CAREER_AI_RESPONSE_FORMAT=json_schema`(기본) 또는 `json_object`를 운영 모델의 지원 범위에 맞게 명시할 수 있다. JSON object 모드에서도 기존 응답 계약 검증을 생략하지 않는다. gpt-4/gpt-3 계열 토큰 인자는 `max_tokens`, 그 외 현재 경로는 `max_completion_tokens`다. 모델이 Chat Completions API·JSON 출력·선택한 출력 상한을 지원해야 한다. Responses API 전용 모델/지원하지 않는 조합을 자동으로 다른 모델/다른 키에 재과금해 시도하지 않는다. 호환 여부는 실제 운영 모델로 담당 개발자가 확인해야 하며 이번에 BYOK 실제 키 호출은 수행하지 않는다.

`model_not_found`, `unsupported_parameter`, `unsupported_value`, `invalid_json_schema` 등은 `AI_MODEL_CONFIG`로 구분하고 재시도하지 않는다. 401/403은 연결/인증 설정 문제이며 quota라 단정하지 않는다. 명시적 `insufficient_quota`·billing 코드/HTTP 402만 이용한도·결제 확인으로 분류한다. 공급자가 상세 원인을 주지 않는 429는 일시적 제한으로 표시하고 원인을 더 단정하지 않는다.

공급자·모델·응답 형식도 재사용 키와 비식별 사용량 로그에 포함한다. 기존 키로 연결하려면 운영 담당자가 위 설정을 **실제 운영 API 서버**에 맞춰 적용·재시작하는 별도 절차가 필요하다. 이번 작업이 해당 설정을 변경하거나 실제 운영 연결을 완료한 것은 아니다.
