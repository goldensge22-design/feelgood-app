# NUVIA AI 자기소개서: 직무 연결·배움·향후 적용 규칙

2026-11-14 개정: AI의 분석·질문·문장 후보 역할은 [개인 기록 기반 AI 자소서 보강 규격](AI_PERSONALIZED_STAR_SPEC.md)을 우선한다. 아래 직접 작성 규칙은 학생의 선택권과 사실 보존을 뜻하며, 확인된 자료에 기반한 AI 문장 제안을 금지하지 않는다. 이 문서의 과거 구현 설명은 새 기능 완료 증거가 아니다.

이 문서는 기존 HeavenlyWiltedConstants / NUVIA AI 자기소개서 앱에 추가한 프런트엔드 보강 규칙이다. 결과지, 플래너, 기업·직무 탐색 LAB, 로그인 또는 서버 저장의 실제 연결을 뜻하지 않는다.

## 기록의 의미를 섞지 않는다

- 활동 카드 유형과 경험 성격은 서로 다른 필드다. 카드 유형은 일상 적용형 또는 직무 상황형이고, 경험 성격은 실제 수행·모의 연습·미확인이다.
- 실제 수행 여부와 경험 맥락도 분리한다. 맥락은 일상 활동·수업 모의훈련·실제 직무 경험·합성 예시·미확인으로 둔다. 예: 카드가 직무 상황형이라는 이유만으로 모의 연습이라고 판정하지 않는다.
- 자기보고와 외부 확인은 별도 의미다. 현재 UI의 학생 선택은 외부 확인으로 승격되지 않는다. 이전 기록의 누락된 출처·맥락은 미확인으로 둔다.
- 앱에서 제공한 합성 예시는 합성 예시로 유지한다. 직접 입력하거나 외부에서 선택·확인한 기록으로 가장하지 않는다.
- 계획, 연습 제안, 아직 실행하지 않은 행동은 수행 사실이나 결과로 바꾸지 않는다. 제공받은 도움과 학생이 직접 선택한 행동도 구분한다.

## 직무 연결은 제안과 근거를 구분한다

- 선택 직무의 구체 업무, 학생의 공통 행동, 배운 판단 원칙, 다음 적용 방법을 별도 입력으로 보존한다.
- 자료 종류는 공식 자료, 채용공고, 기업 공개 자료, 교육용 연결 추론, 미확인으로 표시한다. 자료명·기업·직무·버전/기준 시점은 학생이 입력한다.
- 앱은 자료를 조회하거나 공식성·정확성·기업 절차를 검증하지 않는다. 교육용 연결 추론은 공식 업무자료와 다른 상태다.
- 회사·직무가 다른 출처는 섞지 않는다. 기록된 출처 범위가 현재 지원 회사·직무와 다르면 경고하고 학생 확인을 비활성화한다.
- “확인·대조·전달”만으로 특정 직무의 실제 업무를 단정하지 않는다. 연결이 검증되지 않은 경우 후보 또는 확인 필요로 남긴다.

## 학생의 작성·확인 권한

- 직접 작성이 기본이다. 질문 코치는 비어 있는 설명을 우선해 한 번에 하나씩 질문한다. 답변·성과를 생성하거나 본문에 삽입·재작성하지 않는다.
- 직무 연결 질문은 구체 업무, 경험 행동과의 공통점, 배운 원칙, 향후 적용을 차례로 돕는다. “성실함/꼼꼼함”처럼 일반적인 배움에는 구체적인 판단과 행동을 묻는다.
- 경험, 지원 회사·직무·문항, 근거, 배움, 향후 적용이 같은 지원서 맥락에 연결된 때만 학생 확인을 저장한다.
- 연결 내용, 선택 경험, 지원 범위나 경험 증거가 바뀌면 확인 상태를 무효화한다. 이전 문구로 되돌아가도 옛 확인 상태를 자동 복구하지 않는다.
- 확인은 사실 검증, 기업 공유 동의, 작성 사용 동의가 아니다. 새 보조 기록은 본문·파일·기업 공유에 자동 추가하지 않는다.

## 버전·저장·내보내기

- 경험·지원서별 보조 연결은 기존 자기소개서 본문과 별도 기기 저장 sidecar에 둔다. 현재 개발 범위에서 서버 동기화·다른 기기 복원은 구현하지 않는다.
- 버전 스냅샷은 해당 시점의 연결 메모와 학생 확인 상태를 선택 경험별로 보존한다. 과거 버전은 수정하지 않는다.
- 과거 버전에서 새 초안을 만들면 현재 앱/지원서 식별 맥락에 대한 확인은 다시 받아야 한다.
- 기존 내보내기/기업 공유 계약을 유지한다. 연결 보조 메모, 검사자료, 비공개 메모, 코치 대화는 내보내거나 전송하지 않는다. 학생이 직접 자기소개서 본문에 작성한 문구만 기존 본문 정책에 따른다.
- 저장 실패는 성공으로 표시하지 않는다. 입력은 화면에 보존하고 재시도를 제공한다. 새 보조 기록의 저장 범위는 사용자에게 기기 저장이라고 알린다.

## 다음 개발자에게 필요한 실제 연결

- 별도 담당자가 인증된 플래너 기록의 선택·소유권·동의·원본 버전·삭제·공유 철회 계약을 제공해야 한다.
- 결과지와 기업·직무 탐색 LAB의 실제 데이터 계약은 출처/식별자/기준시점/공개 범위가 확인된 뒤 연결한다. 현재 UI 입력을 실제 공식자료 조회로 간주하지 않는다.
- 로그인 계정별 영구 저장과 다중 기기 복원은 기존 서버 소유권 검사를 유지한 채 별도 구현·QA한다.
- 이 프런트엔드의 합성 QA는 외부 제품 연결 또는 서버 저장 QA의 증거가 아니다.
