# NUVIA 자소서 앱 — 구현 및 검증 범위

## GitHub 인계 및 최종 QA 재개 — 2026-10-23

이번에는 기존 작업을 보존하면서 다음 결함을 보강했다.

- 계정/공간 전환 도중 늦게 도착한 저장·서버 복구·버전 생성 응답에
  세대별 경계를 적용했다. 이전 응답이 새 공간의 저장 큐를 막거나
  현재 공간에 반영되지 않게 했다. 계정이 나갔다가 같은 ID로 돌아오는
  경우도 이전 요청으로 구분한다. 이는 코드·단위검사 확인이며
  실제 로그인 브라우저 QA를 대체하지 않는다.
- 선택 경험을 계정/직접 기록/가상 예시별로 복원하고, 과거 버전에서
  새 초안을 만들 때 최신 공간의 선택 저장 함수를 사용하도록 했다.
- 인증 컨텍스트가 준비되기 전 이전 공간의 본문·선택을 노출하지 않는다.
- 안전한 소스 인계 허용 목록, SHA-256 파일 목록,
  실행·검증 안내와 합성 HTTP 문서 재판독 스크립트를 추가했다.

인증 도구를 다시 요청했으나 `Unknown config kind: testing`으로
생성되지 않았다. 인증 생략/세션 위조 경로를 만들지 않았다.
Clerk 관리 상태는 `managed`/`authorized`이며 실제 로그인 실패나
결제·사용량 오류가 확인된 것은 아니다.

GitHub 공개 소스에서 D-CAS 입력 adapter와 플래너 인계 자료를 새로
확인했다. 기존 제품의 실제 운영 API 접근이 생긴 것은 아니다.
상세 출처와 추가로 필요한 범위는 `nuvia-integration-contract.md`에 기록했다.
Replit 백업 원격을 GitHub로 바꾸지 않으며, 원격 main을 덮어쓰지 않는다.
소스 저장 위치/검사 명령은 `nuvia-runbook.md`를 따른다.

### 이번에 재현·수정한 오버레이

처음 전체 여정 검사에서 `es-768` 활동 상태 편집 중 오류가 발생했다.
원본 이벤트는 `ResizeObserver loop completed with undelivered notifications.`였고
`Error` 객체는 null이어서 개발 플러그인은 `(unknown runtime error)`로 표시했다.
`generated-artifacts/final-qa/overlay-first-reproduction.json`에 최초 실패를 보존했다.

관찰자 생성 스택/대상 치수 수집 후 같은 활동을 반복 편집하여 다시 재현했다.
`autoUpdate` 위치 계산 관찰자가 `select-act-status` 및 팝업 DIV를 관찰했고,
팝업 폭이 확대 전환 중 약 300~305px 사이에서 계속 변하는 기록을 확보했다
(`overlay-observer-trace.json`).
대화상자와 선택창의 확대/이동 애니메이션을 페이드로 바꿔 측정 치수를 안정화했다.
오류 이벤트/오버레이를 무시하거나 관찰자를 전역 비활성화하지 않았다.

같은 스페인어 태블릿 여정에서 추가 80회 상태 변경을 수행한
`resize-stress-fixed.json`은 통과했고 원본 오류/거부 이벤트와 pageerror가 모두 0이었다.
이번에 재현한 원인과 수정의 증거이며, 원본 기록이 없었던 과거 모든
일반 오류 메시지가 이 원인 하나였다고 단정하는 것은 아니다.

## 최근 체크포인트 보강

- 기존 결과·사용자 저장소·제품 경로·배포 주소를 교체하지 않았다. 공개 배포 없음.
- 직접 기록/계정의 결과 요약 우측 카드는 경험 보관함 진입이다.
  가상 예시는 별도 공간 선택과 명시적 체험 동작으로만 들어간다.
- 공통 예시의 동일 출처 문구 중복을 제거했다. 공식 출처·날짜·버전은 유지했다.
- 번역 검수 배너/초안 배지/검수 표시점은 일반 사용자 화면에서 제거했다.
  내부 검수 메타데이터와 실제 데이터·개인정보·내보내기 제한 안내는 보존했다.
  기존 번역을 재생성하지 않고 이미 존재하는 문구를 재사용했다.
- 직접 기록/예시 전환 시 URL의 `space`도 변경하여 새로고침 후 공간이
  바뀌지 않게 했다. 언어·경로·다른 매개변수·해시는 유지한다.
- 최신 프런트엔드/검사 스크립트 타입 검사와 프로덕션 빌드 통과.
  기존 청크 크기 경고는 남는다.

검사 범위는 기존 전체 45개 기기 저장 여정과 별개로 구분한다.
이번 보강의 요약/출처/선택기/언어·공간 전환/원문 입력 복원 검사는
`scripts/src/nuvia-checkpoint-regression.ts` 및
`generated-artifacts/checkpoint/regression.json`에 기록한다.
최종 **45/45 통과**, 135개 화면 캡처·기하 측정, 원본 브라우저 오류 이벤트 0개다.
이 검사는 수정한 화면과 상태 전환의 회귀 검사이며, 기존 45개 전체 작성 여정을
새로 모두 수행했다는 의미는 아니다. 크메르어·아제르바이잔어·아랍어 공개
로그인도 360px에서 선택기/넘침을 추가 확인했다(인증 완료 아님).
최신 한국어 360px의 기기 저장 전체 여정도 재실행하여 통과했다
(`generated-artifacts/browser/smoke.json`). 이는 계정 세션/외부 연결 검사가 아니다.

인증 검사를 재시도했지만 검사 도구가 `Unknown config kind: testing`으로
생성되지 않았다. Clerk 관리 상태는 현재 `managed`, 대시보드 접근은
`authorized`이며, 도구 오류를 로그인 실패·사용량·결제 문제로 해석하지 않는다.
실제 로그인 완료 이후 계정 화면의 전체 여정은 여전히 미검증이다.
현재 환경에서 Microsoft Word/한컴 실행 도구도 확인되지 않아 네이티브
문서 열기 검증은 여전히 미확인이다.
실제 예시 데모의 HTTPS 응답 200과 렌더링을 확인했다:
https://546ebb1e-3eed-447d-99fc-f558586d3f51-00-1hmnxial7hba6.pike.replit.dev/?space=example&lang=ko
로그인 없이 가상 예시로 들어가며, 실제 개인 검사 결과나 기존 플래너 연결
성공을 나타내지 않는다. 직접 기록은 `space=guest`로 구분한다.

## 인수 상태

**검토 가능한 실행 미리보기이며, 전체 요청의 완료·기존 제품 연동 완료·공개 배포 완료가 아니다.**
대학생·취업 준비생용 별도 앱이다. 기존 결과지·플래너의 공개 소스는
읽기 전용 확인했으며 운영 배포/데이터에 접근하거나 기존 경로를 변경하지 않았다.

## 구현한 범위

- 결과지 미연결 화면, 네 처리 영역의 활동 전략, 관심 직무 직접 선택. 가상 예시는 개인 공간과 분리.
- 경험 보관함 생성·수정·삭제·사용자 사실 확인, 기준 연결, 명시적 강점 선택.
- 공통 실천 **예시**, 사용자 채용공고 원문, 공식 출처에서 확인한 NCS 직업공통능력 3개를 구분한다.
  공식 NCS는 문제분석·대안발굴·의사결정(26v1)의 고정 스냅샷이다.
  특정 개인 결과지나 특정 직무의 전체 NCS 능력단위가 연결된 것은 아니다.
- 작은 활동의 목표·단계·날짜·완료 기준·근거 메모, 사용자 수락, 시작·중단·재개·부분 완료·회고.
- 선택한 회고 항목만 경험으로 가져오기, 동일 활동 재전송 시 기존 경험 갱신, 개인 메모 제외.
- 지원처·직무·문항·공백 포함/제외·제한 없음·작성 언어, 기준 중복 근거에 따른 경험 제안.
- 직접 작성 편집기와 한 번에 한 질문 코치. 문장 생성·자동 삽입 기능은 없다.
- 자동 저장, 서버 저장 충돌 경고, 복구본에서 새 초안 만들기, 독립 버전, 두 버전 비교, 이전 버전에서 새 초안.
- 계정별 서버 저장. 비로그인 직접 기록/가상 예시는 각각 별도 브라우저 저장이며 기기 간 동기화가 아니다.
- 내보내기 미리보기·사실 확인·글자 수 초과 차단, 복사용 텍스트·TXT·실제 DOCX·실제 HWPX.
- 복사 실패 시 선택 가능한 읽기 전용 원문과 전체 선택 버튼을 제공한다.
- 제출물에는 회사·직무·문항·작성한 글만 포함.
- HWPX는 OWPML XML/패키지 매니페스트/스타일/본문을 포함하는 실제 ZIP 문서다.
  한컴에서의 시각적 열기는 아직 검증하지 못했다는 안내를 표시한다.
- 언어 변경 시 기존 URL 매개변수·해시와 입력을 보존하고 `lang`을 갱신한다.
  새 문항은 초기 저장소 준비 전에는 생성할 수 없으며, 선택한 지원서도 공간/계정별로 복원한다.

  Unicode 글자 수, 안전한 URL, 내보내기 필드 제한, OOXML 문서 생성,
  실제 HWPX 패키지/문자 이스케이프/금지 문자 거부, 승인된 공식 NCS 스냅샷 채택·위조 거부.
- 언어 검사 3개 통과: 15개 언어의 전체 UI 키 존재·치환 변수 일치, 지원 별칭, 코드의 고정 번역 키 참조 검사.
- HTTP 검사: 공개 조회/가상 데이터 조회 성공, 비로그인 개인 저장소·버전 조회 401,
  DOCX/HWPX 다운로드 성공, 사실 확인 누락 및 XML 불허 문자 거부.
- DOCX ZIP 무결성·XML 파싱과 한국어/영어/일본어/아랍어/태국어/크메르어 문자열 검사.
  별도 Mammoth 문서 판독기로 다시 열어 문단 확인, 경고 없음.
  HWPX는 별도 Python ZIP/XML 판독기로 CRC·XML 파싱·매니페스트/본문 순서 참조·
  미리보기와 본문의 정확한 재판독을 확인했다.
  **공식 XSD 전체 검증과 Microsoft Word/한컴오피스의 시각적 열기는 하지 못했다.**

## 화면 검사

### 브라우저 핵심 여정

Chromium의 1440×1000 / 768×1024 / 360×800 뷰포트에서
한국어·영어·일본어·중국어 간체/번체·몽골어·태국어·베트남어·아랍어·러시아어·
크메르어·스페인어·프랑스어·이탈리아어·아제르바이잔어를 검사한다.

실행 스크립트와 최신 원본 결과:

- `scripts/src/nuvia-browser-validation.ts`
- `generated-artifacts/browser/matrix.json`
- `scripts/src/nuvia-signin-display-validation.ts`
- `generated-artifacts/browser/signin-display.json`

핵심 여정은 **기기 저장 모드**에서 미연결 결과/빈 보관함 → 공식 기준 선택 →
수락한 로컬 활동 → 실행·중단·재개·부분 완료 → 선택 항목만 가져오기/중복 방지 →
문항·경험 선택 → 직접 작성/질문 코치 → 언어 왕복 → 새로고침 복원 →
두 버전 비교 → 이전 버전에서 새 지원서 → 내보내기 미리보기/사실 확인이다.
모든 조합에서 선택기 44px, 우측 상단, RTL, 가로 넘침을 측정하고 화면을 캡처한다.
실제 HWPX 다운로드는 각 언어의 PC에서, TXT/DOCX는 한국어 PC에서 추가 확인한다.

**최종 핵심 여정 45/45 통과.** 병렬 검사에서 중단된 항목은 개별/순차로
다시 실행했다. 이미 통과한 항목의 데이터를 다시 작성하지 않고 결과를 합산했다.
수정한 결과 요약 화면은 별도로 최신 코드에서 45조합을 다시 캡처/측정했다.
HTTP로 다운로드한 언어별 HWPX 15개와 재시도 검사 HWPX 1개, 총 16개를
독립 ZIP/XML 판독기로 추가 확인했다
(`generated-artifacts/document-verification.json`).

이 검사는 **로그인 계정 여정·실제 외부 제품 연동·실물 기기/다른 브라우저·원어민 번역 검수**가 아니다.
로그인 화면은 입력/제출하지 않고 공개 위젯 표시만 확인했다.
최신 로그인 45조합과 수정 후 결과 요약 45조합은 모두 표시/폭/선택기 검사를 통과했다.

### 오류/경계 동작

`scripts/src/nuvia-browser-edge-validation.ts`의 8개 검사 통과.
원본 결과는 `generated-artifacts/browser/edge-cases.json`.
가상/개인 공간 분리, URL/언어 보존, 기기 저장 실패·재시도·복원, 클립보드 실패 대안,
내보내기 503·재시도, 글자 수 초과 차단, 로컬 원본 변경/삭제 후 글·버전 보존,
익명 개인 API 읽기/쓰기 401을 검사했다. 오류 주입은 테스트 브라우저 안에서만 실행했다.
이 오류 화면 검사는 주로 한국어/크메르어 360px이며 15개 언어 전 오류 상태 검사는 아니다.

### 직접 살펴본 대표 캡처

이전 대표 캡처에 더해 최신 아랍어 작성 360px, 크메르어/아제르바이잔어 로그인 360px,
태국어 작성 360px을 살펴봤다. 전체 캡처의 모든 문장을 사람이 검수한 것은 아니다.

| 화면 | 언어 | 크기 | 확인 범위 |
|---|---|---|---|
| 결과지 미연결 | 한국어 | 1440×1050 | 빈 결과, 네 영역, 관심 직무, 상단 선택기 |
| 작성 | 영어 | 1440×1100 | 편집기·질문 코치·기준·연결 경험 배치 |
| 직무 준비 기준 | 태국어 | 820×1180 | 카드 줄바꿈·출처·행동 버튼 |
| 작성 | 아랍어 | 360×1000/1100 | RTL·언어 선택기·모바일 순서, 전체 페이지 1회 |
| 경험 보관함 | 크메르어 | 360×1100 | 글꼴·줄바꿈·긴 카드·선택기 |

위 표는 이전 정적 캡처 범위다. 최신 기기 저장 여정 검사는 위 브라우저 절과 구분한다.
로그인 후 UI와 실제 결과지/플래너의 회귀 검사는 **미검증**이다.

### 검사 중 관찰한 미확인 오류

아래는 이전 기록이다. 이번 재개에서 실제 원본 이벤트를 확보해 수정한 사례는
문서 상단의 「이번에 재현·수정한 오버레이」와 구분한다.

일부 병렬 여정 검사에서 개발 오버레이가 `(unknown runtime error)`를 표시해 클릭을 막았다.
해당 당시 Playwright `pageerror`에는 실제 오류가 없었고 원본 이벤트가 수집되지 않아
근본 원인은 확인 불가다. 앱 코드·외부 연결·사용량·결제·권한 문제 중 하나라고 단정하지 않는다.
이후 실패 항목을 따로 재검사하고 원본 브라우저 이벤트 수집을 추가했지만,
재검사 통과만으로 이 간헐 현상의 원인까지 해결됐다고 간주하지 않는다.

최근에는 원본 이벤트를 브라우저 문서 안에만 보관하지 않고 검사 프로세스로
전달하여 페이지 이동 전의 오류도 남도록 보강했다. 개발 오버레이를 숨기거나
알 수 없는 오류를 임의로 무시하지 않았다. 이번 검사의 초기 도구 오류
`__name is not defined`는 TSX가 만든 보조 함수가 브라우저 초기화 코드에
포함된 문제로 확인하여 독립 JavaScript 초기화로 고쳤다.
이는 이전 `(unknown runtime error)`의 원인이 밝혀졌다는 의미가 아니다.

## 번역 상태

한국어 원문과 14개 언어의 번역 문구가 있다. 키가 모두 있다는 것은 번역 품질 검토 완료가 아니다.
번역은 내부에서 미검토 초안으로 표시하며 원어민 검토가 필요하다.
기존 초안의 동일 의미 번역은 보존했다. 공개 D-CAS 입력 adapter의 locale
처리는 확인했으나 현재 운영 제품 전체의 별칭 계약과 대조한 것은 아니다.
크메르어·아제르바이잔어 로그인/가입 주요 문구·공통 오류·접근성 문구에
번역 초안을 추가했고 공개 로그인 화면 표시도 확인했다. 모든 가입/복구/오류 단계의
실제 세션 검증은 아니다. SDK가 표시하는 영어 `Development mode` 배지는 유지된다.
서버가 제공하는 외부 연동 계약 요구사항은 한국어 원문임을 별도로 안내한다.
사용자 글·문항·메모는 언어 전환으로 바꾸지 않는다.
가상 예시 중 원본과 정확히 일치하는 문구는 표시용 번역을 사용하며 저장 원문은 변경하지 않는다.

## 실제 연결에 필요한 자료

`docs/nuvia-integration-contract.md` 참조.
실제 결과지·플래너 운영 URL/API 접근, 인증·소유권·버전·철회 규칙,
개인정보를 제거한 응답 예시, 기존 명칭/언어 별칭, 테스트용 접근 권한이 필요하다.
현재 작은 활동은 **기존 NUVIA PLANNER에 저장되지 않는다.**
외부 연결 버튼의 성공/원본 복귀를 검증한 것으로 표시하지 않는다.

## 남은 주의사항

- 로그인 후 실제 사용자 세션의 HTTP/UI 전체 흐름 검증 필요.
  이 환경에서 제공된 자동 로그인 검사 실행은 `Unknown config kind: testing`으로 거부됐다.
  이를 우회하는 토큰·인증 생략 경로는 만들지 않았다.
  서버 저장소 소유권/충돌 검사와 로그인 화면 표시 검사를 실제 세션 검증으로 대신하지 않는다.
- 실제 플래너의 생성 멱등성·소유권·버전 변경·삭제/권한 철회 연동은 계약 확보 후 구현·검증 필요.
- HWPX/DOCX 생성·기계 판독은 확인했으며 네이티브 편집기 시각 검증은 남았다.
- 빌드에 청크 크기 및 일부 UI sourcemap 경고가 있으나 빌드는 성공했다.
- Clerk 패키지의 React 패치 버전 peer 경고가 남아 있다. 공유 패키지를 임의 업그레이드하지 않았다.
- 공개 배포하지 않았다.
