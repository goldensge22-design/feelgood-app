# 자소서 화면 보강: 개발자 연결 준비 자료

이 문서는 연결 준비와 수용 요구사항이다. 실제 D-CAS·NUVIA PLANNER 연동, 인증·소유권·서버 저장 운영 검증의 완료 증거가 아니다. 외부 제품의 기존 필드명을 바꾸거나 아래 의미 항목을 확정 API 계약으로 사용하지 않는다. 개발자가 실제 계약을 제공한 뒤 명시적 매핑을 합의한다.

## 담당 경계

- 이번 작업: 경험 출처·실제/모의 구분, 선택 미리보기와 확인, 문항 매칭, 질문 코치, 직접 작성, 버전과 최종 사실 확인 화면, 합성 자료 기반 프런트엔드 검증.
- 별도 개발자: 실제 결과 조회와 플래너 읽기·계획 생성·선택 전송, 신원과 소유권 확인, 서버 저장 계약 확장, 원본 버전·공유 철회 조회, 운영 QA.
- 기존 인증·서버 검사를 우회하지 않는다. 현재 계정 저장 검증은 `planner` 출처와 외부 원본 URL을 `SOURCE_CONNECTOR_REQUIRED`로 거부한다. 클라이언트 출처를 `manual`로 바꿔 통과시키면 안 된다.
- 연결 준비용 브라우저 메타데이터는 서버 저장 완료가 아니다. 실제 사용자 작성문·기존 제출 버전은 원본 갱신으로 조용히 바꾸지 않는다.

## 결과지 보존

원래 점수·척도, 사용자·검사·결과 식별자, 81유형·IQ, 네 처리 영역과 해석, 전공 맥락, 직무 관련 설명, TOP5의 순서·근거를 기존 계약 그대로 유지한다. 순차 처리의 명칭·별칭은 실제 계약에 따라 매핑한다. 상위 두 강점으로 재계산하거나 누락 직무를 채우지 않는다. 개인 검사 원문과 식별자는 외부 URL·제출물에 넣지 않는다.

이번 대상은 대학생·취업 준비생이다. 청소년 진로 후보 수신은 별도 확장 요구이며 성인 TOP5와 동일한 것으로 취급하지 않는다. 직접 입력과 미정 상태를 지원하고, 청소년 제품 전체를 이번 범위에 포함하지 않는다.

## 연결 후 기대 출력과 동작

1. 사용자가 선택한 사실 필드와 동의 범위, 원본 참조와 당시 버전, 활동 유형과 경험 성격을 보존한 경험 후보.
2. 확인 전 후보와 확인 후 경험을 구분. 취소 시 새 경험이나 계획을 만들지 않음.
3. 반복 요청은 소유자+출처+원본 식별자+요청 식별자를 서버에서 검증해 중복 생성하지 않음. 구체 키/프로토콜은 개발자와 합의.
4. 원본 변경은 비교·재확인으로 처리. 원본 삭제·공유 철회는 조회 불가 안내와 원래 글 보존을 분리.
5. 연결 실패·자료 없음·권한 없음·만료를 서로 다른 상태로 보여 주고 재시도 동작을 실제 계약에 연결.
6. 근거 보완/작은 실천은 제안 미리보기→사용자 확인→개발자 계획 생성 API 순서. API 성공 전 저장 성공을 표시하지 않음.
7. 기존 버전 비교는 당시 출처 정보를 사용. 이전 버전에서 새 초안을 만들더라도 과거 제출 버전은 불변.
8. 내보내기 요청은 기업·직무·문항·사용자 본문만 전달. 본문에 사용자가 적은 “모의 활동에서”는 그대로 유지. 검사 원문·코치·비공개 메모·내부 메타데이터는 제외.

## 합성 예시와 수용 기준

- 일상 적용형/실제 수행: 교내 예약 안내를 직접 비교한 합성 경험. 실제 사용자 기록 또는 실제 연결이라고 표시하지 않음.
- 직무 상황형/모의 연습: 가상의 서비스 장애·예약 상황에서 확인과 판단을 연습한 합성 경험. 실제 근무·성과라고 추천하지 않음.
- 실제 행동·성과 요구 문항에는 모의를 실제 경력처럼 추천하지 않음. 탐색·준비 문항에는 활용 이유와 한계를 명시.
- 코치는 한 번에 질문 하나. 사용자 동의 없이 문장 생성·삽입·수정 금지.
- 출처 미확인·정보 누락·중복·원본 변경·삭제·권한 철회·연결 실패·취소/재진입을 확인.
- 15개 언어와 PC/태블릿/360px, RTL·긴 번역·태국어/크메르어를 변경 범위에서 점검. 기계 번역 초안/키 검사/화면 검증/원어민 검수를 구분.
- 계정별 운영 저장·실제 소유권·실제 제품 왕복은 개발자 통합 QA로 별도 확인.
- DOCX/HWPX 다운로드·본문 구조 검증과 Microsoft Word/한컴 실제 시각 검증은 별도 판정.

## 이번 프런트엔드의 임시 보관 방식

- 기존 `CareerState`와 서버 요청 계약은 바꾸지 않았다. 외부 출처를 직접 기록으로 위장하는 변환도 하지 않았다.
- 새 출처 확인 정보는 브라우저의 `nuvia:provenance:v1:<context>`에 별도 보관한다. context는 guest/demo 또는 현재 인증된 계정 문맥이다. 다른 기기·브라우저와 동기화되는 서버 저장이 아니다. 새 화면에 기기 전용임을 안내한다.
- `exps[경험 ID]`: 카드 유형과 실제/모의/미확인 성격, 출처, 합성 여부, 원본 버전, 선택한 전송 필드, 선택 동의, 직무·연습 행동·확인 기준·강점 전략·제공된 도움·본인이 정한 순서·관찰 근거.
- `apps[문항 ID]`: 실제 행동/준비·탐색/둘 다라는 문항 요구. 이전 버전 복원 시 당시 경험 메타데이터를 새 초안에 복사한다.
- `versions[버전 ID]`: 생성 당시 요구와 경험 출처를 한 번 복사한 불변 스냅샷. 이미 존재하는 스냅샷은 교체하지 않는다. 이번 보강 이전의 버전에는 출처 기록 없음으로 표시한다.
- 외부 플래너가 아닌 합성 자료는 반드시 `example` 출처로 신규 생성한다. 계정 모드에서는 합성 가져오기를 비활성화하고 연결 대기임을 표시한다. 기존 사용자의 실제 기록을 데모로 교체하지 않는다.
- 브라우저 보관 실패는 오류로 알리고 합성 경험을 성공한 것처럼 추가하지 않는다. 실제 버전은 기존 저장 경로로 생성되므로 출처 부가정보 저장 실패와 버전 자체 저장 결과는 별개다.
- 검증된 플래너 복귀 호스트는 아직 등록하지 않았다. 원본 복귀는 현재 비활성 상태이며 개발자가 실제 허용 대상을 연결해야 한다.
- 개발자가 서버 스키마를 확장할 때에는 이 부가정보를 그대로 신뢰하지 말고 소유권·공유 상태·원본 버전을 재검증하고, 기기 정보 이관 여부를 사용자에게 확인해야 한다.

## 재현 가능한 확인 방법

기존 관리 워크플로 웹/API를 실행한 상태에서 실행한다. 테스트는 폐기 가능한 합성 브라우저 문맥만 사용하며 실제 사용자 계정이나 운영 데이터는 읽지 않는다.

```sh
PORT=24976 BASE_PATH=/ pnpm --filter @workspace/nuvia-career run build
pnpm --filter @workspace/nuvia-career run typecheck
./scripts/node_modules/.bin/tsx --tsconfig artifacts/nuvia-career/tsconfig.json --test \
  artifacts/nuvia-career/src/lib/provenance.test.ts \
  artifacts/nuvia-career/src/lib/locales.test.ts \
  artifacts/nuvia-career/src/lib/career.test.ts \
  artifacts/nuvia-career/src/lib/workspace-scope.test.ts

NUVIA_TEST_ORIGIN="https://${REPLIT_DEV_DOMAIN}" pnpm --filter @workspace/scripts exec tsx src/nuvia-provenance-browser-qa.ts
NUVIA_TEST_ORIGIN="https://${REPLIT_DEV_DOMAIN}" pnpm --filter @workspace/scripts exec tsx src/nuvia-provenance-edge-qa.ts
NUVIA_TEST_ORIGIN="https://${REPLIT_DEV_DOMAIN}" pnpm --filter @workspace/scripts exec tsx src/nuvia-provenance-render-qa.ts
pnpm --filter @workspace/scripts exec tsx src/nuvia-provenance-document-qa.ts
```

결과 JSON·화면·다운로드 파일은 `generated-artifacts/provenance-qa/`에 두며 Git과 배포에서 제외한다. 결과물을 다시 검사할 때 현재 소스 해시·시각과 대조한다. 프런트엔드 자체 동작 결과와 실제 외부 인증·서버 운영 검증을 합산해서 완료라고 보고하지 않는다.
