## 중앙 연동 담당자에게 전달할 사항

기존 `Claude 협업·QA 연동 체계 구축` 검수 목록에는 청소년 LAB `/story`와 중앙 `/career/storyboard`가 구분돼 있고, LAB → 플래너 → 스토리보드의 저장·충돌·재로그인·내보내기가 포함돼 있다. 확인한 최근 실행은 학교급별 플래너 연결과 회원별 진입에 집중돼 있으며 이 Replit 최신 `fe7a9d3`까지 반영한 스토리보드 검수 완료 증거는 아직 없다. 기존 담당 작업에 최신 저장 커밋과 아래 사항을 인계한다.

1. 중앙 `apps/career` 등 기존 구현과 이 소스를 파일별로 비교한다. 운영 SSO·서버 어댑터·이후 WIP를 이 Replit의 Clerk 개발 설정으로 덮어쓰지 않는다. 특히 `storyboard`, `workspace`, `story-session-guard` 등 복구 경로의 변경을 대조한다.
2. 중앙 서버가 검증한 동일 사용자/학습자 ID를 결과지·LAB·플래너·스토리보드에 유지한다. 브라우저 자기설정이나 URL의 학교급/owner 값을 운영 권한으로 사용하지 않는다. 초등은 기존 플래너 경로, 청소년/성인은 해당 LAB·스토리보드 경로를 적용한다.
3. 결과지 원본·해석·직무 TOP5의 순서/근거·버전, 플래너 원본 ID/버전·행동·실제/모의·선택 확인/철회 상태를 승인된 중앙 API 계약으로 전달한다. 누락 정보를 공식 사실로 생성하지 않는다.
4. 본문·내 생각·출처·버전 저장/재조회와 revision 충돌, 요청 중복, 두 탭 복구, 이전 확정 버전 보존, 계정 전환·로그아웃 후 늦은 응답 격리를 동일 소유권 기준으로 검수한다. 개발 기기 저장과 중앙 서버 저장을 구분한다.
5. 실제 결과지 → LAB 선택 → 플래너 기록 → 중앙 스토리보드 → 저장 → 로그아웃/재로그인 → 복원 → TXT/PDF/DOCX/HWPX를 개인/소속회원, 청소년/성인 각각 검수한다. 합성 검수·실제 계정 검수·운영 배포를 분리한다. 실제 개인정보·토큰은 Claude 프롬프트나 증빙에 넣지 않는다.
6. Codex 수정·기본 검사 → Claude 독립 QA → Codex 문제 수정 → Claude 해당 버전 재검증 → 통과본 배포·운영 확인을 유지한다. 원격 소스 저장 자체를 운영 검수 통과로 승격하지 않는다.

현재 입력 계약은 `docs/NUVIA_ORIGINAL_APPS_ACCOUNT_INTEGRATION.md`, `docs/nuvia-account-integration-20261121.md`, `lib/api-spec/openapi.yaml`을 참고한다. 추가 수정·통합은 담당 중앙 작업에서 진행하고 같은 파일을 별도 작업에서 동시에 수정하지 않는다.
