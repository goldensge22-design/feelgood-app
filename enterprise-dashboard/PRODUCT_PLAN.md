# FeelGood 기업 인재전략 대시보드 전체 기획서

- 문서 버전: 1.0
- 기준일: 2026-10-20
- 대상: 기업 인사담당자, 채용담당자, 현업 면접관, 부서 관리자, 경영진
- 제품 구분: 15개 언어 데모판 → 결과지·조직 API를 연결하는 실사용판

## 1. 제품 목표

기업 인재전략 대시보드는 검사 점수를 단순 상·중·하로 나누는 도구가 아니다. 기업이 정의한 인재상과 직무·역할별 성공 기준을 기준으로 지원자와 재직자의 강점, 직무 적합 가능성, 역할 준비도, 성장 방향을 함께 검토하는 의사결정 지원 도구다.

핵심 목표는 다음과 같다.

1. 신입·경력 지원자의 직무 적합 가능성과 확인 근거를 제공한다.
2. 기업별 핵심가치와 직무별 역량 가중치를 반영한다.
3. 기존 직원의 결과와 검증된 업무성과를 활용해 직무·역할별 복수 성공 프로파일을 만든다.
4. 신입사원을 실무 수행형, 전문가 성장형, 프로젝트 책임자 후보, 리더 후보 등 역할 경로 관점에서 분석한다.
5. 재직자의 배치, 직무 전환, 온보딩, 육성 계획을 지원한다.
6. 조직·부서·직무별 인재 구성과 역량 공백을 확인한다.

PASS 결과는 참고 근거 중 하나이며, 단독으로 합격·탈락·승진·배치·리더 선발을 결정하지 않는다.

## 2. 제품 원칙

### 2.1 기업별 인재상

관리자는 기업 핵심가치, 공통역량, 직무별 필수·우대역량, 대상별 가중치, 적용 기간과 모델 버전을 관리한다. 같은 검사 결과라도 기업과 직무가 다르면 추천 결과가 달라질 수 있어야 한다.

### 2.2 사람의 등급이 아닌 역할 적합 신호

`고역량/중역량/저역량`, `우수/보통/미달`, `위험군`, `부적합 인재`와 같은 낙인 표현을 사용하지 않는다. 대신 다음 상태를 사용한다.

- 우선 검토: 직무 핵심 기준과 부합 근거가 충분함
- 면접 확인: 강점은 있으나 일부 역량의 추가 확인이 필요함
- 다른 직무 검토: 지원 직무보다 다른 역할에서 강점 활용 가능성이 큼
- 판단 보류: 데이터가 부족하거나 결과 간 불일치가 있음

### 2.3 복수 성공 프로파일

한 명의 우수 직원을 이상형으로 복제하지 않는다. 직무마다 전략기획형, 현장실행형, 관계조정형, 분석의사결정형 등 여러 성공 유형을 허용한다. 후보자는 가장 가까운 단일 유형뿐 아니라 복수 유형과의 부합 근거를 함께 확인한다.

### 2.4 사람에 의한 최종 검토

대시보드는 추천, 근거, 불확실성, 추가 검증 질문을 제공한다. 최종 인사 결정은 담당자가 구조화 면접, 과제평가, 경력과 실제 성과 자료를 함께 검토해 기록한다.

## 4. 직무·역할 기준 모델

기존 직원의 결과를 직무 분야, 직급, 역할, 근속기간, 리더·전문가·실무자 구분, 검증된 성과, 역량평가, 승진·직무전환 이력과 결합한다. 단순 전체 평균이 아니라 실제 직무성과와 관련성이 확인된 집단에서 복수 기준 프로파일을 도출한다.

역할 경로는 다음을 기본으로 한다.

- 실무 수행형
- 전문가 성장형
- 프로젝트 책임자 후보
- 리더 후보
- 다른 직무 우선 검토
- 추가 검증 필요

신입사원에게는 현재 준비도와 성장 가능성을 구분해 표시한다. `리더 후보`는 즉시 관리자로 임명한다는 의미가 아니라 향후 리더 트랙 검토 가능성을 뜻한다.

## 5. 리더 잠재력 분석

PASS 영역을 리더십과 동일시하지 않는다. 다음 자료를 결합한다.

- Planning: 목표 설정, 우선순위와 실행계획 수립 방식
- Attention: 핵심정보 선별과 집중 방식
- Simultaneous: 복합정보 통합과 전체 상황 판단 방식
- Sequential: 절차 관리와 단계적 실행 방식
- 기업 핵심가치 부합 근거
- 구조화 면접
- 상황판단 과제
- 협업·갈등조정 사례
- 프로젝트 수행 결과
- 경력직의 실제 리더 경험

화면에는 단정적 리더 점수 대신 `리더 후보 검토`, 근거, 확인되지 않은 항목, 권장 검증 방법을 표시한다.

## 7. 결과지·서버 연동 구조

```text
결과지/API
→ 프로그램 전용 adapter
→ 표준화된 인재 데이터
→ 기업별 인재상·직무·역할 모델
→ 화면 표시
→ 담당자 검토·기록
```

연결 필드는 다음을 포함한다.

- 검사자·결과지·사용자 ID
- 조직·부서·직무 ID
- 검사일과 결과 버전
- Planning, Attention, Simultaneous, Sequential
- 결과지 점수 요약과 인지특성
- 결과지의 추천 직무·진로군 Top 5
- 81유형 등 기존 외부 계약 필드
- 경력·직급·역할
- 데이터 완성도
- 기업 인재상 모델 ID와 버전
- 담당자 검토 상태와 근거

데모 데이터와 실데이터 adapter를 명확히 분리한다. UI에는 고정 점수를 직접 넣지 않고 normalized data만 전달한다.

## 8. 접근 권한과 정보주체 보호

상세 결과는 승인된 회사 담당자만 기본 열람한다.

- HR 최고관리자: 전체 설정·개인 결과·인재상 모델
- 채용 담당자: 담당 채용 후보자
- 현업 면접관: 면접에 필요한 요약·질문
- 부서 관리자: 소속 직원의 육성·배치 요약
- 경영진: 비식별 집단 통계
- 시스템 관리자: 시스템 운영, 평가 내용 접근 제한

별도의 결과 검토센터는 만들지 않는다. 개인정보처리방침이나 기존 문의 채널에서 피검자가 본인의 정보에 대한 열람·정정·결과 활용 설명을 요청할 수 있게 한다. 접근 이력, 다운로드·인쇄 권한, 보유기간과 삭제 예정일을 기록한다.

## 9. 편향과 오판 방지

- 성별, 연령, 출신지역, 학교 등 보호·비직무 정보는 적합도 계산에서 제외한다.
- 한 관리자의 주관적 평가만으로 성공 집단을 구성하지 않는다.
- 업무성과와 직무 관련성이 확인된 자료만 사용한다.
- 표본이 작은 직무는 자동 추천을 제한하고 경고한다.
- 직무마다 복수 성공 프로파일을 허용한다.
- 검사 결과만으로 자동 탈락·승진·리더 선발을 하지 않는다.
- 추천 근거와 추가 확인 항목을 함께 표시한다.
- 모델 버전, 변경 이력, 담당자의 최종 판단을 기록한다.

## 10. 다국어

지원 언어는 한국어, 영어, 일본어, 중국어 간체, 중국어 번체, 베트남어, 태국어, 크메르어, 몽골어, 러시아어, 아랍어, 아제르바이잔어, 프랑스어, 스페인어, 이탈리아어의 15개다.

- 언어 선택은 상단 드롭다운으로 제공한다.
- URL `lang`을 우선하고 저장 언어와 브라우저 언어를 순서대로 사용한다.
- 언어 변경 시 현재 메뉴, 선택 대상, 필터, 다른 query와 hash를 유지한다.
- 대상 locale을 준비한 후 화면을 한 번에 교체한다.
- 아랍어는 RTL을 적용한다.
- 메뉴, 표, 차트, 버튼, 툴팁, 알림, 접근성, 인쇄 문구를 번역한다.
- 한국어는 `ready`, 신규 외국어 번역은 원어민 검수 전 `ai-draft`로 추적한다.

- 로그인과 역할 기반 권한
- 실제 결과지·조직 API
- 기업 모델 저장과 버전 관리
- 접근·변경 이력
- 보유기간·삭제
- 담당자 메모와 승인 흐름
- 다운로드·인쇄 통제

## 13. 완료 기준

1. 9개 핵심 메뉴가 실제로 전환되고 현재 상태가 URL hash에 유지된다.
2. 15개 언어의 key, 빈 값, placeholder, RTL을 검사한다.
3. 모든 수치는 adapter 데이터에서 렌더링하며 UI에 개인 점수를 하드코딩하지 않는다.
4. 신입사원의 직무·역할 분석에 사내 복수 성공 프로파일을 사용한다.
5. 자동 선발로 오인될 표현이 없고 추가 검증 근거가 표시된다.
6. 데스크톱·태블릿·모바일과 긴 번역에서 핵심 콘텐츠가 잘리지 않는다.
7. 개발자가 실제 결과지와 조직 API를 연결할 수 있는 데이터 계약을 제공한다.
