# 최신 수정본과 운영 배포본 일치 규칙

개정일: 2026-11-20. 사용자 확정: 개발본에서 제거·수정한 내용이 운영에서 되살아나는 일을 반복하지 않도록 모든 프로그램의 작업·QA·배포 규칙으로 저장한다.

적용: K-PASS, D-CAS, NUVIA PLANNER, MY NUVIA 및 FeelGood의 수정·이식·배포 작업. 실제 변경 범위 밖 프로그램을 일괄 개편하는 근거로 사용하지 않는다.

## 반영 전에 최신 원본을 특정한다

1. 작업 대상의 원본 서비스/저장소/브랜치, 현재 개발본, 현재 운영본을 각각 확인한다. Replit 미리보기, 다운로드 ZIP, 로컬 소스, GitHub main, 실제 서버는 서로 다른 상태다.
2. 관련 전용 채팅·현행 규칙·최근 커밋·미커밋 변경을 확인한다. 다른 작업의 진행 상태를 추측하거나 완료 보고만 믿지 말고 실제 소스와 해당 화면을 대조한다.
3. 원본을 가져온 뒤 추가 수정이 있었는지 **이식 시작 전과 배포 직전** 다시 확인한다. 이전 다운로드의 파일명·날짜만으로 최신이라고 판단하지 않는다.
4. 원본 commit, 브랜치, 확보 시각, 파일/ZIP SHA-256, 포함한 미커밋 변경과 범위를 기록한다. commit만 같아도 미커밋 내용이 다를 수 있다.
5. 최신 원본을 확보하지 못하면 원인과 미확인 범위를 기록한다. 오래된 ZIP을 최신 완성본으로 대체하거나 전체 동기화가 끝났다고 말하지 않는다. 독립적인 최소 오류 수정은 가능하지만 최신 원본 이식과 구분한다.

## 차이와 운영 계약을 함께 보호한다

- 변경·추가·제거 항목을 목록으로 만들고 원본/반영 소스/운영 DOM을 대조한다. 사용자 요청으로 없앤 요소는 '미노출 검수 목록'에 기록한다.
- 예: 초등 작업대 내부의 박물관·정원 중복 버튼 제거와 상단 공간 메뉴 유지가 다른 요구임을 명시한다. 초등 화면에 기업LAB·AI자소서 등 잘못된 서비스 메뉴가 없는지도 검사한다.
- 최신 개발본 전체를 운영 폴더에 그대로 덮어쓰지 않는다. 기존 인증·권한·학습자 구분·서버 저장·점수/결과지 계약·locale·사용자 기록을 유지하며 변경분을 이식한다.
- demo/localStorage 전용 저장을 운영 서버 저장의 대체 구현으로 배포하지 않는다. 타인의 WIP, 구버전 번들, 테스트 fixture를 함께 배포하지 않는다.
- 개발본이 검토 중이거나 QA가 끝나지 않았다면 '최신'과 '출시 가능'을 구분한다. 시간상 필요하더라도 불완전한 개발본 전체를 최신 완성본으로 출시하지 않는다.

## QA는 실제 경로와 같은 빌드에서 수행한다

1. 소스 버튼 → 실제 로그인/선택 사용자 → 저장 응답 → 올바른 대상 화면 → 저장한 내용 표시 → 새로고침·재접속 복원을 확인한다.
2. 서로 다른 계정·학습자 분리, 중복 클릭/재시도, 로그인 만료 후 복귀, 저장 실패 시 입력 유지, 언어/학교급/URL 인자 유지, 기존 열린 탭과 캐시를 검사한다. 성공 알림·HTTP 200·화면 전환 하나만으로 저장 완료라고 판정하지 않는다.
3. 이미 제거한 요소가 사용자 DOM·접근성 트리·인쇄물에 다시 생기지 않는지 자동/실제 화면 검사에 포함한다. CSS로만 가려 통과시키지 않는다. 유지하기로 한 메뉴와 데이터는 별도로 회귀 검수한다.
4. 변경된 범위의 15개 언어, PC·태블릿·360px 모바일, RTL, 긴 문구, 인쇄/PDF를 검사한다. 기존 번역은 원문 의미가 같으면 그대로 보존한다.
5. QA 증거에는 검수한 소스 SHA/빌드와 실제 범위를 연결한다. 그 후 실행 소스가 바뀌면 영향 검수를 갱신한다. 구버전 검수 기록을 새 빌드의 통과 증거로 재사용하지 않는다.

## 운영 반영 완료 판정

- 배포 전 원격 HEAD와 동시 작업의 변경을 확인한다. 일반 push만 사용하며 충돌을 덮어쓰거나 force push하지 않는다.
- GitHub 저장, CI 성공, 실제 서버 asset/빌드 일치, 실제 운영 경로 QA를 각각 기록한다.
- 실제 운영 원본 화면에서 위 저장·이동·유지 경로를 확인한다. 개인 링크·토큰·점수·실명은 공개 QA 문서/Git에 넣지 않는다.
- 최종 체크리스트: `최신 원본 특정 / 차이 목록 대조 / 제거 항목 미노출 / 서버 계약 보존 / 15언어 및 화면 QA / 검수 빌드 일치 / 운영 저장·이동·복원`.
- 필수 항목이 미확인·실패이면 '완료' 대신 구현·검수·배포 상태와 남은 항목을 명시한다. P0/P1은 완료 불가다.

이 문서는 작업자가 매 패치마다 실행할 필수 절차다. 아직 구현하지 않은 실시간 동기화, 자동 소스 감시, 자동 커밋·배포가 있는 것처럼 표현하지 않는다. 패치와 함께 확정 규칙·체크리스트를 갱신하고 대체된 활성 지시는 교체한다. 원본 증거와 Git 이력은 보존한다.
