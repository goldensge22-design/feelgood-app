# 플래너 라이브러리 확장 수량과 개발자 인계

2026-10-23 기준. 결과지 목록을 읽기 전용으로 추출하고 일상 적용과 직무 상황의 라이브러리 초안을 추가했다. 저장 위치는 **필굿 공통규칙 → NUVIA PLANNER → library/expansion**이다. 기존 플래너·결과지·공개 서비스에 아직 적용하지 않았다.

## 1. 수량과 중복 기준

| 구분 | 대상 | 실제 원본 | 연결 수 |
|---|---:|---:|---:|
| 생활·학습 | 6개 행동 × 상황 3개 | 18 | 성인·청소년 연결표에서 1,011건 재사용 |
| 성인 직무 상황 | 직무 ID 311개 | 20개 편집 맥락 × 3개 = 60 | 933 |
| 청소년 진로 탐색 | 미리보기 명칭 26개 | 26 × 3개 = 78 | 78 |
| 기존 직무 대표 예시 | v1 맥락 6개 | 6 | 새 직무 매핑에는 자동 편입하지 않음 |
| 합계 | 337개 진로·직무 대상 | **162** | 상황 연결 **1,011** |

기존 12개 중 생활카드 6개를 재사용하고, 생활 12개·성인 60개·청소년 78개를 새로 작성했다. 신규 원본은 150개다. `18 + 933 + 78 = 1,029`는 당초 구성 단위를 합친 수치이며 저장된 서로 다른 원본 수가 아니다. 연령·언어·도움 변경도 새 상황 원본으로 세지 않는다.

933개 성인 연결은 직무마다 완전히 다른 전문 업무 사례 3개를 만들었다는 의미가 아니다. 같은 원본 직무군의 직무가 3개 공유 상황을 참조하는 **검토 후보 연결**이다. 20개 편집 맥락은 내부 설계 분류이며 결과지의 공식 분류를 대체하지 않는다. 직무별 적합성은 담당 편집자와 해당 분야 검토자가 확인하고, 맞지 않는 연결만 별도 카드로 분화한다.

## 2. 결과지 기준선과 예외

- 저장소: `goldensge22-design/feelgood-app`.
- 결과지 기준 커밋: `35a3216e980bd4dd0c0391e5c6790508bb9e72f7`.
- 원본 위치: `result-reports/dcas81/unpacked/APPLIED_FULL/DCAS_ADULT/`, `DCAS_TEEN/`.
- 상세 원본 파일별 SHA-256: `library/expansion/catalog.json`의 `sourceHashes`. OS checkout 차이를 없애기 위해 텍스트 줄바꿈을 LF로 정규화한 해시다.
- 성인: 고정 학과 61개, 전체 직무 풀 312개 중 해당 학과에서 도달 가능한 ID 311개. 명칭만 중복 제거하면 297개다. 동일 이름이어도 원본 ID는 합치지 않는다.
- `2237 항공보안교육담당자`는 현재 고정 학과 후보 필터에서 제외되어 `excludedJobs`에 보존했다. 삭제하거나 신규 노출시키지 않는다. 항공보안의 특수 후보 ID 9101~9110 필터를 그대로 반영했다.
- 청소년: 8계열·61학과, 직업 미리보기 노출 27개·고유 명칭 26개. `신사업아이디어컨설턴트`가 두 계열에 나온다. 청소년은 성인 직무 TOP5가 아니다.
- 청소년 직업 미리보기에는 공식 직무 ID가 없어 명칭에서 만든 안정 내부 ID와 계열·배열 위치를 함께 보존했다. 이를 공인 직업 코드라고 표시하지 않는다.
- 성인과 청소년 사이 공백 제거 후 이름이 정확히 일치하는 후보는 6종이다. `exactNameLinks`는 검토 대장이며 동일 직무 확정이나 자동 병합에 사용하지 않는다.
- 요구 PASS 벡터, 적합도, 검사 점수와 개인 데이터는 이 패키지로 가져오지 않았다. 결과지 순위 계산도 하지 않는다. 서버가 전달한 선택 직무와 결과지 버전을 adapter에서 확인한다.

이 목록은 위 커밋의 **결과지 후보 전체**다. 전 세계 직무 전체나 자유 입력 학과까지 포괄하지 않는다. 원본 갱신 시 재추출 diff를 검토한 뒤 새 버전을 발행한다.

## 3. 개발자가 읽을 파일

| 파일 | 용도 |
|---|---|
| `library/expansion/catalog.json` | 원본 목록·학과 연결·중복·출처 스냅샷 |
| `families.json` | 성인 편집 맥락 20개와 공유 상황 |
| `bindings.json` | 성인 311·청소년 26 대상에 상황 3개 및 일상 3개 연결 |
| `cards.json` | 신규 150개 구조화 카드와 행동 증거 필드 |
| `locales/ko.json` | 신규 한국어 문자열 810개 |
| `display-catalog.json` | 원본 명칭을 UI에서 표시할 번역 키 |
| `translation-plan.json` | 새 키별 원문 해시·15언어 상태 |
| `contracts.ts`, `lookup.mjs` | 추가 계약·서버 연동용 조회 정책 참고 구현 |
| `CATALOG.md`, `CARD_TEXTS.md` | 사람이 검토할 전체 연결표와 실제 카드 내용 |
| `extract-source.mjs`, `build.mjs`, `validate.mjs` | 읽기 전용 목록 추출·데이터 생성·검증 |

표의 첫 행 이외 경로도 모두 `library/expansion/` 아래다. 기본 카드와 공통 질문은 상위 `library/cards.json`, `library/locales/ko.json`을 함께 읽는다. 같은 언어의 기본·확장 resource를 결합하는 것이며 다른 언어 fallback이 아니다. v1의 동일 의미 목표·질문·완료 키를 재사용했고 기존 번역과 문자열은 바꾸지 않았다.

`catalog.json`의 한국어 `label`은 출처 확인용이지 사용자 화면 출력용이 아니다. 사용자 화면은 `display-catalog.json`의 키로 표시한다. 사용자 직접 작성 원문은 자동 번역하지 않는다.

## 4. 실행 앱에 붙이는 순서

1. 기존 결과지 adapter가 확인한 `population`, 원본 `sourceId`, `sourceVersion`을 조회에 전달한다. 성인 TOP5를 재계산하거나 청소년에게 성인 직무를 자동 연결하지 않는다. 명칭 유사 검색으로 출처 ID를 추정하지 않는다.
2. 검수 완료 연결·카드·선택 언어만 반환한다. `lookup.mjs`는 로컬 참고 구현이며 API·인증·DB 구현이 아니다. 입력되는 승인 정보는 클라이언트가 아니라 인증된 서버의 신뢰 가능한 배포 패키지여야 한다.
3. 사용자에게 일상 적용과 직무 모의 중 하나를 고르게 한다. 3개를 모두 해야 하는 할당량으로 만들지 않는다. 같은 일상카드는 여러 직무에 재사용해도 공용 원본을 복제하지 않는다.
4. 기존 과제에 연결하면 해당 과제 revision과 카드 snapshot을 저장한다. 시간·분야·날짜를 확인한 뒤 작업대에 올린다. 현재 실행·타이머·언어 변경·기존 개인 데이터를 초기화하지 않는다.
5. 기존 PASS 지원 adapter가 정한 목표와 강점 도움을 적용한다. 6개 행동을 PASS 4영역에 일대일 대응시키거나 직무명에서 인지 점수를 추정하지 않는다. 사용자는 도움을 바꿀 수 있다.
6. 실행 종료·과제 완료·목표 행동·외부 확인을 분리한다. 카드 답변만으로 목표 행동이 완료되었다고 기록하지 않는다. 같은 `practiceId/roundId`의 중복 수행을 중복 집계하지 않는다.
7. 실제 일상 경험과 모의 상황은 로드맵에서 분리한다. 자소서 쪽은 사용자가 선택·확인한 사실만 전달한다. 모의 응답을 실제 근무 경험으로 바꾸지 않으며 질문형 코치 계약을 유지한다.

### 연령별 입력 설계

| 대상 | 최초 도움과 입력 | 확장 선택 |
|---|---|---|
| 중학생 | 학습·준비 과제, 한 행동과 확인 질문, 짧은 선택·이유 | 예시 기준을 보고 두 가지 비교 |
| 고등학생 | 수행평가·발표·팀 과제, 스스로 기준 두 개와 마감 정하기 | 대안·중간 마감·근거 출처 추가 |
| 대학생·성인 | 실제 프로젝트 조건과 역할, 가용 시간, 대기·인계 | 담당자 확인·선행 작업·제약 비교 |

이는 연결해야 할 UI 요구사항이다. 이번 패키지는 연령별 화면 구현까지 완료한 것이 아니다. 성인 공유 상황의 `audiences`는 대학생·성인으로 제한하고 중고생에게는 학교 기반 78개를 사용한다. v1 직무 예시의 기존 audience 계약은 보존하지만 새 성인 매핑에서는 사용하지 않는다.

## 5. 비용과 개인 작성

정적 라이브러리 조회·선택·실행마다 생성 AI를 호출하지 않는다. 이번 생성 API 호출은 0회다. 개발 환경 이용료나 향후 호스팅·DB 비용까지 없다는 뜻은 아니다.

라이브러리에 맞는 카드가 없으면 직접 작성부터 제공한다. 사용자가 명시적으로 요청하고 서버 예산 정책이 있을 때만 AI 제안을 허용한다. 자동 fallback 생성은 금지한다. 직접 작성도 개인 카드로 저장되며 즉시 공용화하지 않는다.

공용 축적은 별도 동의 → 개인·민감정보 제거 → 권리와 중복 검토 → 분야·연령 검토 → 언어 검수 → 승인 버전 발행 순서다. 공유 동의가 없는 학생 기록은 수집하지 않는다. 실제 학생 답변·연락처·검사 원문을 GitHub에 저장하지 않는다.

## 6. 전문성·검토·출시 상태

카드 제목에 직무명이 연결되어도 해당 직무능력이 검증됐다는 뜻이 아니다. 보안·의료·심리·복지 등은 확인·전달·인계에 한정하고 임상 판단, 반입 허용 목록, 현장 검색·치료 절차를 만들지 않는다. 전문·안전 정보가 필요한 경우 관할·공식 출처·버전·적용일·분야 검토자·재검토일 없이는 배포하지 않는다.

현재 모든 카드와 337개 연결은 **draft**, 운영 제공 0개다. 한국어 원문은 초안, 나머지 14개 언어는 미작성 `needs-review`다. 15언어 번역 완료가 아니라 상태 추적과 제공 차단을 검증했다. 기존 한국어·외국어 번역은 재생성하지 않았다.

다음 출시는 직무 연결 및 내용 검토, 15언어 번역·검수, 서버 권한·개인 저장·동의 철회, 실제 플래너 통합과 브라우저 QA를 마친 뒤 승인한다. 기존 공개 데모 URL을 이 데이터만으로 교체하지 않는다.

## 7. 검증

아래 명령은 공통규칙 브랜치 저장소 루트에서 실행한다. Node 24에서 검증했다.

```text
node docs/programs/nuvia-planner/library/validate.mjs
node docs/programs/nuvia-planner/library/expansion/validate.mjs
node docs/programs/nuvia-planner/library/expansion/build.mjs --check
```

원본 재추출은 해당 기준 커밋의 별도 checkout 경로를 인자로 준다. 추출기는 HEAD와 결과지 경로의 변경 여부를 검사하고 원본을 수정하지 않는다. 새 결과지 버전을 적용할 때는 기준 커밋을 검토 후 변경하고 diff를 남긴다.

```text
node docs/programs/nuvia-planner/library/expansion/extract-source.mjs <결과지 기준 checkout 경로>
```

- v1 계약 검사 17개 통과.
- 확장 검사 31개 통과: 목록·수량·중복·깨진 참조·원본 보존·재생성 일치·15언어 제공 차단·승인/개인/만료/원문해시 오류 등.
- 기존 및 확장 TypeScript 계약 `--noEmit --strict --target ES2022` 검사 통과.
- 저장소 중앙 i18n 검사는 기존 HISTORY·proposal·proposal-v2·teacher-guide 오류 19개로 실패한다. 이번 라이브러리는 중앙 런타임 등록 대상이 아니며 별도 검증기를 사용했다. 다른 제품 오류는 수정하지 않았다.
- UI·배포 변경이 없으므로 브라우저·360px·인쇄·서버 권한 QA는 이번 검증에 포함하지 않았다. 앱 통합 시 반드시 별도 수행한다.

구조 검증 통과는 교육 효과·직무 전문성·번역 품질 검증을 뜻하지 않는다. 월간 이행률은 실행 지원 조정의 참고이며 인지능력 향상률이나 직무 적합도 증가로 바꾸지 않는다.
