# 항공보안학과 직무군 패치 (v2) — 적용 안내

## 1. 무엇이 바뀌는가

기존 D-CAS 성인 리포트의 "항공보안과" 직무 데이터는 4개(항공보안요원·공항운영관리자·
항공기 내 보안요원·출입국관리 지원직, id 911~914)뿐이었고, 지난 대조표(①~⑨ 직무군)
기준으로 7개 카테고리가 비어 있었습니다.

이번 패치는 요청하신 10개 직무로 전면 교체합니다.

| # | 직무 | 직무군 | entry_level |
|---|---|---|---|
| 1 | 공항보안 사무직 | ⑤ 보안기획·관리 | bridge |
| 2 | 항공사보안 사무직 | ④ 항공사 보안 운영 | bridge |
| 3 | 항공보안검색요원 | ① 보안검색 | direct |
| 4 | 항공경비요원 | ② 출입통제·항공경비 | direct |
| 5 | 대테러보안요원 | ③ 보안상황 감시·대응 | retool |
| 6 | 항공사보안요원 | ④ 항공사 보안 운영 | direct |
| 7 | 항공화물보안요원 | ① 보안검색 | direct |
| 8 | 산업보안 사무직 | ⑦ 국가중요시설·기업보안 | bridge |
| 9 | 산업보안 경비요원 | ⑦ 국가중요시설·기업보안 | direct |
| 10 | 산업보안검색요원 | ⑦ 국가중요시설·기업보안 | direct |

남은 카테고리(⑥ 보안교육·품질관리, ⑧ 경호·신변보호, ⑨ 공공치안·보안)는 이번 10개
목록에 해당 직무가 없어 이번 패치 범위에서 제외했습니다. 필요하시면 같은 패턴으로
`dcas-jobs-extra.v2.patch.js`의 `DEPARTMENTS[0].jobs`에 항목만 추가하면 됩니다.

## 2. 필수역량(pass_profile) 산정 근거

기존 파일과 동일하게 `attr_source: 'estimated'`, `attr_confidence: 0.5`(1차 추정치,
문수백 교수님 감수 전)입니다. 각 직무 객체의 `competency_note` 필드에 근거를 남겨뒀고,
큰 틀에서는 다음 두 자료를 참고했습니다.

- 인천공항공사 NCS 직무기술서(항공보안): "세밀한 관찰력", "예외 없는 검색을 실시하려는
  윤리의식", "위기관리 능력", "국가항공보안 기본계획·항공보안법 이해" 등을 필요지식·
  기술·태도로 명시 → 검색/경비/대테러 직무는 **주의력(A)** 을, 사무직 계열은
  **계획력(P)·순차처리(Q)** 를 상대적으로 높게 설정.
- "국가직무능력표준(NCS)에서의 산업보안 직무 및 직무능력 추출을 위한 탐색적 연구"
  (임동선 외, 2020, 한국융합보안학회) — 산업보안 사무직은 자산 식별·위험평가·법규
  분석 비중이 커 **분석·탐구형** 성향과 계획력·동시처리를 함께 높게 설정.

## 3. 다국어(11개 언어) 대응

기존에는 직무명이 `label_ko` 한 필드뿐이라 언어 전환 시에도 항상 한국어로 고정
출력되고 있었습니다(실제 코드 확인 결과, adult 리포트는 현재 ko만 구현되어 있고
teen 리포트만 ko/en 일부가 구현된 상태였습니다 — "12개 언어 이미 적용"은 teen
일부 콘텐츠에 한정된 이야기였고, 직무명 쪽은 아직이었습니다).

이번 패치는:
- `dcas-job-i18n-bank.js` — 직무 10개 + 학과명 1개를 **ko/en/ja/zh/es/ru/vi/th/ar/it/az**
  (한국어 포함 11개 언어) 로 번역해 채워둔 신규 파일.
- `job.label_ko`를 getter로 바꿔서, 기존 리포트 코드(`item.job.label_ko`를 참조하는
  약 10곳)를 한 줄도 안 고쳐도 `DCasJobsExtra.setLang('en')` 호출 한 번으로 전체가
  해당 언어로 바뀌도록 설계했습니다.
- 화면 상단 언어 스위처(`lang-btn`)의 `onclick="setLang('en')"` 같은 기존 함수 안에서
  `DCasJobsExtra.setLang('en')`도 같이 호출하도록 한 줄만 추가하면 연결됩니다.
- ⚠️ 참고: 적합도 판단 근거 문장(`buildReasonText`, "이 직무가 요구하는 핵심 축은
  계획력·주의력이에요...")은 이번 패치 범위가 아니라 여전히 한국어 하드코딩입니다.
  직무명은 즉시 다국어로 나가지만, 이 문장까지 다국어로 하려면 teen 쪽
  `dcas-i18n-bank.js`와 같은 방식으로 별도 문구 뱅크가 한 벌 더 필요합니다 — 다음
  작업으로 남겨둡니다.

## 4. 쉽게 확장되는 구조 (다음 학과 추가 시)

`dcas-jobs-extra.v2.patch.js` 상단 주석에 있는 대로, `DEPARTMENTS` 배열에 객체 하나
추가 + `dcas-job-i18n-bank.js`에 번역 블록만 추가하면 끝입니다. id 채번, NCS 매핑,
드롭다운 연결, fit% 계산 로직은 전부 자동으로 재사용됩니다.

## 5. 적용 순서 (script 태그)

```html
<script src="dcas-jobs-extra.js"></script>
<script src="dcas-job-i18n-bank.js"></script>
<script src="dcas-jobs-extra.v2.patch.js"></script>
<script src="dcas-job-engine.js"></script>
<script src="dcas-job-engine.v2.patch.js"></script>
```

`dcas-jobs-extra.js`(기존 원본)는 그대로 둡니다 — v2 패치가 런타임에 구 항공보안
4개(911~914)만 골라내 제거하고 새 10개로 교체하는 방식이라, 원본 파일 자체를 건드릴
필요가 없습니다.

## 6. 확인/테스트 결과 (Node로 시뮬레이션 완료)

- `항공보안과`(기존 드롭다운 값) / `항공보안학과`(요청하신 정식 명칭) 둘 다로 조회 시
  10개 직무가 모두 정상 매칭됨.
- 언어를 `en`/`ar` 등으로 바꾸면 `label_ko` 참조 지점이 전부 해당 언어로 바뀜(기존
  코드 무변경 확인).
- 기존 경찰행정과 등 다른 학과 매칭은 그대로 동작(하위호환 확인).

## 7. 확인이 필요한 부분

- **드롭다운 이름**: 현재 `adult.work.html`의 실제 옵션명은 `항공보안과`입니다.
  요청하신 "항공보안학과"가 정식 학과명이라면, `adult.work.html`의
  `<option>항공보안과</option>` 한 줄만 `<option>항공보안학과</option>`로 바꾸시면 됩니다
  (이 패치는 두 이름 모두를 이미 같은 데이터에 연결해뒀습니다).
- **"4~11번" 수정 범위**: 말씀하신 "4~11번"이 정확히 어느 문서(엑셀/결과지 행 번호
  등)의 번호인지 확인할 방법이 없어, 대신 요청하신 10개 직무 전체를 기준으로
  작업했습니다. 특정 행 번호 기준으로 범위를 좁혀야 한다면 그 파일을 공유해주시면
  대조해서 다시 맞춰드리겠습니다.
