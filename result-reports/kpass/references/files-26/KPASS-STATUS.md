# K-PASS 결과지 현황 보고서

## 결론부터

**K-PASS 결과지는 "버그를 고치는" 단계가 아니라 "예시 1건을 실제
시스템으로 완성하는" 단계에 있습니다.** D-CAS에 쓴 "수정사항"이라는
표현을 그대로 쓰면 개발자가 오해할 수 있어 따로 문서를 분리했습니다.

## 지금 파일(01_결과지_완성본.html)의 정체

**"송서우"라는 특정 아이 한 명을 위해 손으로 직접 쓴 예시 리포트**입니다.
- 점수: 계획력145 · 주의력131 · 동시처리117 · 순차처리95
- 유형: 밸런스4-H

81유형 중 이 1개만 실제로 존재하고, 나머지 80개는 콘텐츠 자체가
없습니다. "다른 아이 결과를 넣으면 자동으로 그 아이 것으로 바뀌는"
시스템이 아니라, **이 특정 아이의 리포트가 디자인 완성본으로 고정돼
있는 상태**입니다.

## 구체적으로 뭐가 하드코딩돼 있나

같은 점수 하나가 최소 5~6곳에 각각 따로 박혀 있습니다.

- 히어로 카드 텍스트 ("계획력 145점이에요" 같은 문장)
- 인지 나침반 SVG의 폴리곤 좌표 (점수를 좌표로 직접 계산해서 박아넣은 값)
- 막대그래프의 `width:87.5%` 같은 인라인 스타일
- 정규분포 그래프의 마커 위치

이 중 하나만 바꾸고 나머지를 안 바꾸면, 같은 리포트 안에서 숫자가
서로 안 맞는 상태가 됩니다. (D-CAS에서 "축 배열 순서 밀림"으로 발견한
것과 증상은 비슷하지만, 원인은 다릅니다 — D-CAS는 배열 순서가 꼬인
거고, K-PASS는 애초에 자동 계산 로직 자체가 없습니다.)

## 이미 설계된 것 — kpass-score-engine.js

점수 4개(P/A/S/Seq)를 넣으면 위 5~6곳이 전부 자동으로 계산되는 순수
함수들을 이미 설계해뒀습니다. `kpass-score-engine.js`에 정리했습니다.

- `scoreToPercentile` — 표준점수 → 백분위 (정규분포 누적확률)
- `scoreToBarWidth` — 표준점수 → 막대 너비 %
- `compassPoint` — 표준점수 → 나침반 SVG 좌표
- `classifyLevel` — 표준점수 → H/M/L 등급
- `normativeStatus` — 또래 대비 강/약
- `personalStatus` — 자기 자신 대비 강/약 (개인내적 강약)
- `computeTypeCode` — 위 넷을 조합해 81유형 코드 산출
- `renderScores` — 위 전부를 한 번에 호출하는 통합 함수

**이걸 적용하면** "예시 1건"이 최소한 "점수만 바꾸면 재사용되는 템플릿
1개"는 됩니다. 콘텐츠(문장)는 별개 문제입니다.

## 아직 설계만 되고 구현 안 된 것

과거 세션에서 "K-PASS 결과지 서버 연동 설계 명세서"라는 문서를 만든
적이 있습니다. 그 안에 아래 구조가 설계돼 있습니다.

```
검사 완료 → 점수 4개 입력
  → ① 점수→81유형 코드 변환 (계산, AI 불필요)
  → ② DB에 이 유형 콘텐츠가 이미 있는가?
      있으면 → 바로 불러와서 렌더링
      없으면 → AI에게 1회만 생성 요청 → DB 저장 → 렌더링
```

이 구조라면 AI 호출은 서비스 전체 수명 동안 최대 81번(유형 전체를
미리 만들어두면 0번)만 발생합니다. **다만 이건 설계 문서일 뿐, 실제
DB·API 구현은 개발자 영역이고 착수 여부가 확인되지 않았습니다.**

## 검증이 필요한 것

`personalStatus()` 함수의 `CRITICAL_VALUES`(순차/동시=7, 계획/주의=9)는
송서우 사례에서 쓰인 값을 그대로 가져온 것입니다. K-PASS 기술 매뉴얼
원본의 정식 척도별 임계값과 같은지 확인된 적이 없습니다. **문수백
교수님 감수 없이 그대로 서비스에 쓰면 안 됩니다.**

## 우선순위 제안

| 순서 | 작업 | 비고 |
|---|---|---|
| 1 | kpass-score-engine.js 적용 | 코드 작업, 지금 바로 가능 |
| 2 | CRITICAL_VALUES 검증 | 문수백 교수 감수 필요 |
| 3 | 81유형 콘텐츠 뱅크 채우기 | 콘텐츠 제작, 별도 일정으로 진행 가능 |
| 4 | DB·AI 파이프라인 구현 | 개발자 착수 여부부터 확인 |

1번은 지금 당장 개발자에게 넘길 수 있는 작업입니다. 2~4번은 콘텐츠·
감수·서버 작업이 섞여 있어서 D-CAS처럼 "패치 파일 적용"으로 끝나지
않습니다.
