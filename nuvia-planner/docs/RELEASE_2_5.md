# NUVIA PLANNER 2.5 릴리스 검수

기준 브랜치: `codex/recover-planner-dcas81`

이 릴리스는 D-CAS, 결과지, 구형 BrainMap Planner를 변경하지 않고 NUVIA PLANNER의 실제 핵심 루프인 계획 → 실행 → 조정을 보강한다.

## 변경 내용

### 예상·실제 시간 조정

- 완료 뒤 예상과 실제 차이를 N분 길었어요/짧았어요/같았어요로 중립적으로 표시한다.
- 점수·등급·순위·인지능력 판단 없이 시간을 줄이기 / 일을 나누기 / 같은 시간으로 하기 중 하나를 고른다.
- 선택은 완료 과제의 `timeAdjustment`에 저장하고 반복으로 생성된 다음 과제의 `planningReference`에도 연결한다.
- 최근 선택은 다음 계획 조립 화면에서 참고 정보로만 표시하며 자동으로 시간을 바꾸지 않는다.

### 미완료 과제 재배치

- 날짜가 지났거나 잠시 멈춘 과제에만 다시 배치하기를 제공한다.
- 오늘 / 내일 / 이번 주를 직접 선택하고, 선택적으로 예상 시간을 줄이거나 남은 일을 두 단계로 나눈 뒤 저장한다.
- 저장 버튼을 누르기 전에는 날짜·완료 상태를 바꾸지 않으며 실패·벌점·경고로 표현하지 않는다.
- `rescheduleChoice`, `rescheduledAt`과 변경된 시간·단계를 workspace 및 백업 JSON에 보존한다.

### 오늘·주간 2.5D 작업 공간

- 기존 평면 progress bar를 실제 과제의 영역·아이콘·시간을 보여 주는 2.5D 시간 선반으로 교체했다.
- 학습(파랑·▤), 생활(주황·⌂), 업무(보라·◆)를 색과 아이콘으로 함께 구분한다.
- 과부하는 실패가 아니라 오늘 공간이 거의 찼어요. 하나를 다른 날로 옮길까요?로 안내한다.
- 카드 배치·눌림·완료 피드백은 180~200ms로 제한하고 `prefers-reduced-motion`에서는 애니메이션을 제거한다.
- 모바일에서는 44px 이동 버튼, 단일 열 선택/재배치, 내부 시간 블록 스크롤을 사용한다.

### 연속 기록 표현

- 주 화면의 연속 N일 표현과 별 보상 블록을 제거했다.
- 이번 주 7일 중 N일 기록과 7개 경로 점으로 바꾸고, 누락일은 벌점·초기화·실패로 계산하지 않는다고 명시했다.

### B 프로필 연령별 독립 활동

| 단계 | 주요 조작 | 시작·복귀 조건 | 저장 구조 |
| --- | --- | --- | --- |
| 초1~3 | 그림 루틴에서 준비물 추가·확인, 첫 행동 확인 | 모든 준비물 확인과 준비됐어요 확인 | `picture_routine`, `routeConfirmed`, `materials`, `steps` |
| 초4~6 | 숙제 단계 카드 선택, 돌아올 위치 입력 | 현재 카드와 복귀 위치 확정 | `step_card`, `routeConfirmed`, `resumeNote` |
| 중학생 | 과목·범위·오늘 분량 입력, 중단 시 남은 범위·다음 10분 행동 입력 | 최초 시작은 세 계획 필드, 복귀는 두 중단 필드가 필수 | `subject_scope`, `learningScope`, `remainingScope`, `nextTenAction` |
| 고등학생 | 과제별 마감 입력 후 계속·나누기·다른 날 판단 | 계속 선택 또는 2개 이상의 실제 단계로 나누기 | `deadline_triage`, `deadlineDecision`, `deadline`, `steps`, `date` |
| 대학생·성인 | 즉시 행동·답변 대기·타인 확인 구분, 인계·후속 메모 | 대기 상태는 시작 차단, 즉시/확인은 메모 필수 | `handoff`, `handoffState`, `waiting`, `adjustment`, `resumeNote` |

타이머와 방해 줄이기는 보조 도구로만 남겼다. A 프로필도 초등 하/상학년, 중학생, 고등학생, 대학생·성인의 서로 다른 계획 화면과 저장 구조를 유지한다.

### 성장 서클 데모 완주

- 데모 모드에만 예시 전략 이력 불러오기를 표시한다.
- 버튼은 HISTORY 전략 연결과 `strategyApplied: true`인 완료 예시 과제/자기보고 기록을 데모 저장소에 추가한다.
- 다른 영역에 써보기에서 이전과 다른 영역, 완료 여부, 도움 횟수를 저장한다.
- 사용자가 입력한 과제·계획·결과 서술 원문은 저장하지 않고 `taskContentStored: false`와 범주형 측정치만 남긴다.
- 적용 기록은 `self_report`, 외부 확인은 `verification`으로 분리한다.

### 백업 복원

`exportWorkspaceJson` → `restoreWorkspaceJson` → `validateWorkspace`를 내려받기, 파일 가져오기, 자동 왕복 검증이 공유한다. 다른 프로필/학년 scope, 손상 JSON, 없는 이전 기록을 가리키는 재적용 기록은 복원을 거부한다.

## 자동 검증 결과

- Vitest: 12 files, 233 tests passed.
- `focusRoutes.test.ts`: 5개 연령 경로의 매핑과 시작/복귀 조건 검증.
- `backupRestore.test.ts`: 할 일·단계·준비물·완료·반복·성장 기록 JSON 왕복, 프로필/손상/연결 오류 거부 통과.
- `plannerEnhancements.test.ts`: 시간 차이 문구, 세 가지 조정 선택, 오늘/내일/이번 주 날짜 결정, 조정·재배치 저장 구조 왕복 검증.
- `lifeTools.test.ts`: 이번 주 고유 기록일을 누락일 초기화 없이 계산하는 검증 추가.
- TypeScript: `tsc --noEmit` 통과.
- 배포 빌드: 로컬 환경에 npm 실행기가 없어 `tsc --noEmit` → `vite build` → `node scripts/package-delivery.mjs`로 build:delivery와 같은 세 단계를 실행해 standalone 데모/실제 모드 HTML을 생성했다.

## 실제 브라우저 검수 결과

- 1280px 데스크톱과 360px 모바일에서 A/B × 초1~3·초4~6·중·고·대/성인 화면을 확인했다.
- B 초1~3 준비물/첫 행동, 초4~6 단계/복귀 위치, 중학생 과목/범위/다음 10분, 고등학생 마감 판단, 대/성인 인계/후속 메모가 서로 다른 입력과 시작 조건으로 표시됐다.
- 실제 할 일 입력 → 단계 2개·준비물 추가 → 실행 → 완료 → 예상 20분/실제 35분 차이 → 일을 나누기 선택 저장을 완주했다.
- 잠시 멈춘 과제를 내일로 옮기며 20분을 10분으로 줄이고 두 단계로 나눈 뒤 날짜·시간·단계 저장을 확인했다. 완료 상태는 자동 변경되지 않았다.
- 매일 반복 과제를 완료한 뒤 다음 날 과제가 생성되고 새로고침 후에도 완료·조정 선택·반복 카드가 유지되는 것을 확인했다.
- B 중학생 타이머의 접기/보기, 중단, 남긴 자리에서 재개를 조작했다. 타이머 종료와 완료·점수는 연결되지 않는다.
- 데모 예시 이력 → 생활 영역 재적용 → 완료 → 도움 2회 → 저장을 완주했다. 저장 후 다른 과제 재사용 자기보고 1회가 표시되고 입력 서술 원문은 표시되지 않았다.
- 브라우저 백업 내려받기에서 동일 JSON 복원 경로의 자동 왕복 검증 통과 알림을 확인했다.
- 360px의 10개 대표 화면에서 page `scrollWidth`가 viewport 360px를 넘지 않았다. 글자 겹침, 동작하지 않는 버튼, 콘솔 warning/error는 없었다.
- 키보드 Tab 이동 시 버튼에 주황색 focus-visible 외곽선이 표시되는 것을 확인했다.
- 실제 모드에서는 데모 이력 버튼을 표시하지 않는 기존 검증을 유지한다.

## 수동 QA 절차

1. 데모에서 프로필 A/B와 5개 연령 단계를 순서대로 열어 입력과 시작 조건이 달라지는지 확인한다.
2. 실제 할 일을 추가하고 영역·예상 시간·반복·단계·준비물을 편집한 뒤 실행·완료한다.
3. 완료 후 예상/실제 차이와 세 가지 조정 선택 중 하나를 저장하고, 다음 계획 참고가 유지되는지 확인한다.
4. 과제를 잠시 멈춘 뒤 다시 배치하기에서 내일·시간 줄이기·두 단계 나누기를 선택한다. 저장 전에는 원본이 유지되고 저장 후에만 값이 바뀌는지 확인한다.
5. 오늘/이번 주 화면에서 학습·생활·업무가 색과 아이콘을 함께 표시하는지, 가능 시간을 줄이면 과부하 제안이 실패 문구 없이 나타나는지 확인한다.
6. 성장 탭에서 데모 예시 이력을 불러온 뒤 다른 영역 적용의 영역·과제·계획·결과·도움 횟수를 입력해 저장한다.
7. 백업 내려받기를 눌러 내부 JSON 왕복 검증을 통과한 파일을 같은 프로필/학년에 가져온다. 다른 프로필, 손상 JSON, 끊어진 이전 기록 연결은 거부되는지 확인한다.

## 남은 한계

- 데모 예시 이력은 현재 데모 workspace에서만 의미가 있으며 실제 KIDS/HISTORY 성과로 해석하지 않는다.
- 외부 확인 기록은 연동 주체가 제공하며 standalone HTML은 검토자 인증을 수행하지 않는다.
- 타이머는 보조 도구로만 동작하며 화면을 다시 열면 새로 시작한다.
- 카드 순서는 위/아래 버튼으로 조정한다. 자유 드래그 배치는 이번 범위에 포함하지 않았다.
- 다크 모드와 알림은 이번 범위에 포함하지 않았다.
- 이 브랜치는 `main`에 병합·푸시·배포하지 않았다.
