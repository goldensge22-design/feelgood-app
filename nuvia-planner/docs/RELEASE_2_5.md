# NUVIA PLANNER 2.5 릴리스 검수

기준 브랜치: `codex/recover-planner-dcas81`

이 릴리스는 D-CAS, 결과지, 구형 BrainMap Planner를 변경하지 않고 NUVIA PLANNER의 P1 데모 완주 경로를 보강한다.

## 변경 내용

### B 프로필 연령별 독립 활동

| 단계 | 주요 조작 | 시작·복귀 조건 | 저장 구조 |
| --- | --- | --- | --- |
| 초1~3 | 그림 루틴에서 준비물 추가·확인, 첫 행동 확인 | 모든 준비물 확인과 `준비됐어요` 확인 | `picture_routine`, `routeConfirmed`, `materials`, `steps` |
| 초4~6 | 숙제 단계 카드 선택, 돌아올 위치 입력 | 현재 카드와 복귀 위치 확정 | `step_card`, `routeConfirmed`, `resumeNote` |
| 중학생 | 과목·범위·오늘 분량 입력, 중단 시 남은 범위·다음 10분 행동 입력 | 최초 시작은 세 계획 필드, 복귀는 두 중단 필드가 필수 | `subject_scope`, `learningScope`, `remainingScope`, `nextTenAction` |
| 고등학생 | 과제별 마감 입력 후 계속·나누기·다른 날 판단 | 계속 선택 또는 2개 이상의 실제 단계로 나누기 | `deadline_triage`, `deadlineDecision`, `deadline`, `steps`, `date` |
| 대학생·성인 | 즉시 행동·답변 대기·타인 확인 구분, 인계·후속 메모 | 대기 상태는 시작 차단, 즉시/확인은 메모 필수 | `handoff`, `handoffState`, `waiting`, `adjustment`, `resumeNote` |

타이머와 방해 줄이기는 필요한 단계의 보조 도구로만 남겼다. 시작 가능 여부는 공통 문구가 아니라 위 연령별 과제 구조로 결정한다. A 프로필도 초등 하/상학년, 중학생, 고등학생, 대학생·성인의 화면 입력과 저장 구조가 다른 기존 경로를 유지했다.

### 성장 서클 데모 완주

- 데모 모드에만 `예시 전략 이력 불러오기`를 표시한다.
- 버튼은 HISTORY 전략 연결과 `strategyApplied: true`인 완료 예시 과제/자기보고 기록을 데모 저장소에 추가한다.
- `다른 영역에 써보기`에서 이전과 다른 영역, 완료 여부, 도움 횟수를 저장한다.
- 사용자가 입력한 과제·계획·결과 서술 원문은 저장하지 않고 `taskContentStored: false`와 범주형 측정치만 남긴다.
- 적용 기록은 계속 `self_report`, 외부 확인은 `verification`으로 분리한다.

### 백업 복원

`exportWorkspaceJson` → `restoreWorkspaceJson` → `validateWorkspace`를 내려받기, 파일 가져오기, 자동 왕복 검증이 공유한다. 다른 프로필/학년 `scope`, 손상 JSON, 없는 이전 기록을 가리키는 재적용 기록은 복원을 거부한다.

## 실제 브라우저 검수 결과

- 1280px 데스크톱과 360px 모바일에서 A/B × 초1~3·초4~6·중·고·대/성인 화면을 열어 제목, 입력, 버튼 동작을 확인했다.
- B 초1~3 준비물 추가/확인 후 시작, 초4~6 단계/복귀 위치 후 시작, 중학생 중단/다음 10분/복귀, 고등학생 나누기/행동 복귀, 대/성인 대기 차단/확인 요청/메모 시작을 조작했다.
- 데모 예시 이력 → 생활 영역 재적용 → 완료 → 도움 2회 → 저장을 완주했다. 저장 후 재적용 자기보고 1회와 누적 기록 2개가 표시되고 입력 서술 원문은 표시되지 않았다.
- 360px에서 모든 10개 대표 화면의 `scrollWidth === clientWidth` 확인. 가로 넘침, 버튼 비활성 오류, 콘솔 warning/error는 없었다.
- 실제 모드 URL에서 데모 이력 버튼 0개를 확인했다.

## 수동 QA 절차

1. 데모에서 프로필 B를 선택하고 5개 연령 단계를 순서대로 연다.
2. 각 단계의 필수 입력 전에 시작 버튼이 잠겨 있고, 필수 조작 후에만 열리는지 확인한다.
3. 중학생은 시작 후 남은 범위와 다음 10분 행동을 입력하고 중단·복귀한다.
4. 성장 탭에서 데모 예시 이력을 불러온 뒤 `다른 영역에 써보기`를 열고 영역·과제·계획을 입력한다. 실행 후 결과·도움 횟수·완료 여부를 저장한다.
5. `백업 내려받기`를 누러 내부 JSON 왕복 검증을 통과한 파일을 저장한다. 내려받은 JSON을 같은 프로필/학년에 가져와 할 일·단계·준비물·완료·반복·성장 기록을 비교한다.
6. 같은 파일을 다른 프로필/학년에서 선택했을 때 복원이 거부되는지 확인한다. 파일 사본의 중간을 잘라 손상 JSON 거부도 확인한다.

## 남은 한계

- 데모 예시 이력은 오직 현재 데모 workspace에서만 의미가 있으며 실제 KIDS/HISTORY 성과로 해석하지 않는다.
- 외부 확인 기록은 연동 주체가 제공하며, standalone HTML은 검토자 인증을 수행하지 않는다.
- 이 브랜치는 `main`에 병합·푸시·배포하지 않았다.
