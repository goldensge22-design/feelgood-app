## 추가된 기능과 유지할 계약

독립 활동 10종에 5연령의 입력·범위를 적용한 50개 변형이다. 81개 독립 훈련이나 인지능력 측정기가 아니다. 계획, 주의, 관계 연결, 순서, 통합 목표에 각각 후보 2개를 제공한다.

추천 선택 → 시간·분량·도움 수정 → 명시적 할 일 추가 → 기존 작업대 → 실행·멈춤·깃발 복귀·종료 → 선택적 도움 자기보고로 연결한다. 추천 열람이나 추가만으로 수행률이 올라가지 않는다. 실행 종료와 과제 완료는 별개다.

결과지 adapter의 기존 공식 수준, 연령, 지원 순서, 강점, 회차 규칙을 재사용한다. 점수를 다시 분류하거나 새로운 임계값을 만들지 않는다. 강점은 목표 행동을 대신 수행하는 답이 아니라 도움의 제시 방식이다. 검사 없음·잘못된 결과·지원 순서 미확정 시 일반 활동으로 후퇴한다. 초등 경로는 내부 검토용이며 일반 출시 범위를 넓히지 않는다.

추천 출처·선택 당시 목표와 도움·연령·수정 입력을 보존한다. 검사/언어 변경으로 과거 활동을 재분류하지 않는다. 개인 원문을 자동 번역하거나 공용 라이브러리/AI/교사에게 자동 전송하지 않는다. 기존 월간 수행률 산식, 결과지 계약, 사용자 기록을 유지한다.

## 적용 전에 반드시 할 일

1. 개발자가 운영 중인 결과지 연동 브랜치와 Replit 기준을 비교하고 별도 적용 브랜치와 사용자 백업을 확보한다.
2. 아래 읽기 전용 검증을 실행한다. baseline은 저장소 최상단이 아니라 `artifacts`, `tools`, `docs`가 있는 Studio workspace다.

```sh
node nuvia-planner/patches/daily-practice-2026-11-09/verify-package.mjs
node nuvia-planner/patches/daily-practice-2026-11-09/verify-package.mjs --baseline nuvia-planner/studio-daily-note-demo
```

첫 검증의 종료 코드 0은 패키지 체크섬·15언어 key/placeholder 검사 통과만 뜻한다. 두 번째 검사에서 종료 코드 2는 기준 소스 불일치이며 **덮어쓰기 중단 조건**이다. 현재 GitHub 기준에는 Replit 공개 데모 보강 등 선행 변경이 빠져 있어 그대로 적용할 수 없다. 이 저장은 그 선행 변경까지 자동 병합한 것이 아니다.

3. 기준이 다르면 Replit의 해당 전체 소스 또는 필요한 선행 변경을 먼저 확보하고 개발자의 최신 연동본과 수동으로 병합한다. 이 ZIP은 46개 변경 파일만 담고 있어 단독 실행·설치가 불가능하다. `payload` 전체 복사나 `changes.patch` 강제 적용을 하지 않는다.
4. 전체 의존성이 갖춰지고 BEFORE 해시가 일치할 때만 동봉 적용 도구를 검토해 작업 브랜치에 적용한다. 운영 브랜치나 사용자 기록이 있는 환경에서 바로 실행하지 않는다.
5. 실제 결과 연동은 인증된 사용자/결과 식별자와 기존 adapter를 통해 전달한다. 합성 QA 프로필이나 공개 데모 입력을 정식 결과로 사용하지 않는다. 로그인·권한·서버 저장·동기화는 별도 개발과 검수가 필요하다.
6. 새 practice 필드를 포함한 백업은 구형 앱에서 거부될 수 있다. 필드를 삭제해서 맞추지 말고 새 백업과 원래 백업을 모두 보존한다. 소스 롤백은 격리된 브라우저에서 확인한다.

이번 인계는 패키지와 지시서 추가만 한다. 정식 HTML, D-CAS, 결과지, 구형 BrainMap, 기존 Studio 실행 소스, 기존 번역은 변경하지 않는다. 공개 배포는 사용자 인수와 별도 승인 후 진행한다.
