# NUVIA PLANNER 최종 규칙 v3.1

상태: 개발 기준선  
작성일: 2026-09-21  
적용 범위: 결과지 연동, 계획, 실행, 조정, PASS 개인화, 저장·서버 연동

## 1. 제품의 한 문장 규칙

> 결과지의 PASS 네 영역을 지원의 출발점으로 삼아 실제 할 일을 계획하고, 현재 한 블록을 실행한 뒤, 실제 시간과 남은 일을 보고 다음 계획을 조정한다.

학생은 PASS 이론을 알아야 사용할 수 있는 구조가 아니다. 점수는 상단에서 사실대로 확인할 수 있지만, 학생 화면의 행동 이름은 `할 만큼 정하기`, `지금 한 가지`, `전체 연결하기`, `단계대로 해보기`를 사용한다.

## 2. 절대 원칙

1. 실제 숙제·공부·생활·업무 과제를 사용한다.
2. 결과지는 보완 목표를 정하고, 강점은 도움을 보여주는 방식만 정한다.
3. 결과지의 점수·단위·공식 상중하를 그대로 사용하며 플래너가 임의의 점수 경계를 만들지 않는다.
4. K-PASS 표준점수·백분위와 D-CAS 정답률을 같은 척도로 취급하지 않는다.
5. 여러 블록을 계획할 수 있지만 실행은 현재 블록 하나만 가능하다.
6. 시작 버튼은 항상 누를 수 있고, 목표 행동을 건너뛰어도 실제 과제 실행은 가능하다.
7. 실행 종료와 과제 완료를 구분한다.
8. 타이머 만료는 완료·실패·점수로 처리하지 않는다.
9. 실제 행동, 자기보고, 외부 확인을 서로 다른 근거로 저장한다.
10. 수행 기록만으로 인지능력 향상이나 교육 효과를 자동 판정하지 않는다.
11. 점수·순위·스트릭 손실 대신 실제 시간 감각과 다음 조정을 보여준다.
12. 저장값은 번역 문장이 아닌 안정 ID를 사용한다.

## 3. 상단 PASS 결과 표시

- 플래너 헤더 바로 아래에 계획·주의·동시처리·순차처리 네 점수를 항상 표시한다.
- 각 점수에는 검사 종류, 점수 종류, 단위를 함께 표시한다.
  - K-PASS 예: `계획 92 표준점수`, `백분위 30`
  - D-CAS 예: `계획 72% · 영역별 정답률`
- D-CAS의 `%`는 또래 백분위로 표현하지 않는다.
- 공식 `상·중·하`와 현재 지원 영역은 숫자와 함께 표시하되, 빨간 경고·등수·능력 판정처럼 표현하지 않는다.
- 점수 해석 설명은 접을 수 있지만 네 점수 자체는 접힌 영역 안에 숨기지 않는다.
- 데모 점수는 `예시 결과`임을 명확히 표시하고 실제 결과지처럼 저장하거나 전송하지 않는다.

## 4. 점수에서 지원 활동을 정하는 규칙

### 4.1 데이터 책임

결과지 서버가 검사별 규준과 해석 버전을 적용해 다음을 전달한다.

- 네 영역의 표시 점수와 단위
- 네 영역의 공식 상·중·하
- 보완 목표 순서 `supportOrder`
- 강점 활용 순서 `strengthOrder`
- 검사 종류와 점수 종류, 해석 버전

플래너는 이 값을 검증하고 표시·배정한다. 플래너가 K-PASS 또는 D-CAS의 절단점, 백분위, 정답률을 다시 계산하지 않는다.

### 4.2 보완 목표

| 공식 결과 | 플래너 배정 |
|---|---|
| 하 영역 1개 | 해당 영역을 이번 회차 목표로 배정 |
| 하 영역 2개 이상 | `supportOrder` 순서대로 회차별 한 영역씩 순환 |
| 하 영역 없음 | 계획 → 실행 → 조정의 통합 기본 흐름 |
| 지원순서 없음 | 같은 단위의 점수가 모두 있을 때 낮은 표시값 우선, 그렇지 않으면 안정 ID 순서로 안전하게 처리하고 서버 보완 로그 생성 |

낮은 영역이 여러 개여도 한 회차에서 여러 훈련을 동시에 강제하지 않는다. 목표 행동을 실제 수행하고 실행을 종료해야 다음 새 회차로 넘어간다. 건너뜀·새로고침·일시정지·타이머 종료만으로 순환하지 않는다.

### 4.3 강점 지원

| 활용 강점 | 보여주는 방식 |
|---|---|
| 계획 | 목표와 완료 기준을 먼저 보여줌 |
| 주의 | 핵심 정보 강조, 주변 정보 축소 |
| 동시처리 | 전체 지도와 관계 묶음을 먼저 보여줌 |
| 순차처리 | 현재 단계와 다음 단계를 한 단계씩 보여줌 |

강점은 학생 대신 답을 정하거나 약점 활동을 완료하지 않는다. `strengthOrder`가 있으면 첫 강점을 우선 사용하고, 없으면 같은 단위의 최고 표시값을 참고한다.

## 5. PASS 영역별 실제 행동과 완료 근거

| 목표 | 실제 행동 | 회차 완료 근거 |
|---|---|---|
| 계획 | 우선순위·예상 시간·오늘 범위를 직접 결정 | `이대로 좋아요` 또는 시간·범위·순서 변경 + 실행 종료 |
| 주의 | 현재 행동 하나 선택 | 현재 행동 선택 + 실행 종료. 생각 보관·깃발·복귀는 발생했을 때만 기록 |
| 동시처리 | 목표·마감·준비물·관련 과제 2개 이상 연결, 관계 확인 | 연결 항목과 관계 확인 기록 + 실행 종료 |
| 순차처리 | 단계 2개 이상을 순서대로 놓고 1단계 이상 진행 | 단계 작성·순서·진행 기록 + 실행 종료 |
| 통합 | 계획 확정 또는 변경 후 실행 | 계획 근거 + 실행 종료 |

`해당 없음`은 주의 영역의 상황별 행동을 종료 성찰에서 선택할 때만 사용한다. 확인하지 않았으면 내부 `unobserved`, 건너뛰면 `skipped`, 실제 수행은 `performed`, 자기보고 해당 없음은 `not_applicable`로 구분한다.

## 6. 핵심 사용자 흐름

1. 직접 입력·최근 과제·저학년 그림 카드로 할 일을 추가한다.
2. 과목/영역, 범위, 날짜·시각, 예상 시간을 정한다.
3. 여러 블록의 순서와 오늘 가용 시간을 본다.
4. 한 블록을 시작한다. 필요한 목표 행동이 비어 있으면 질문 하나만 제시하며 `바로 시작`할 수 있다.
5. 실행 중에는 과제명, 현재 행동, 남은 시간, 멈춤, 끝내기를 우선한다.
6. 다른 생각은 현재 블록을 바꾸지 않고 보관한다.
7. 잠깐 멈추면 복귀 깃발을 남기고 같은 과제·목표·단계·남은 시간을 유지한다.
8. 실행 종료 뒤 과제 완료 여부를 따로 묻는다.
9. 미완료이면 `5분 더`, `다음 블록`, `오늘은 여기까지` 중 하나를 고른다.
10. 완료 후 예상·실제 시간을 비교하고 `줄이기`, `나누기`, `같게 유지`를 고른다.

## 7. 시간·보상·리포트

- 시간 선반은 완료한 계획 시간, 미실행 예정 시간, 미배정 시간의 3색 막대 하나로 표시한다.
- 실제 시간은 일시정지를 제외하고 기록하되 사용자가 수정할 수 있는 참고값이다.
- 완료 블록은 오늘의 색띠에 채우고, 주간 화면은 `이번 주 7일 중 N일 기록`으로 표현한다.
- 사용자 간 점수·순위, 스트릭 초기화, 실패 연출, 인지 향상 배지를 사용하지 않는다.
- 리포트는 다음에 이어갈 일과 다음에 바꿀 한 가지를 먼저 보여준다.
- PASS 점수는 결과지 출처이고, 플래너 실행 기록과 섞어 새로운 인지 점수를 만들지 않는다.

## 8. 연령별 활동 범위

| 단계 | 활동 범위 |
|---|---|
| 초1~3 | 그림 과제 1~2개, 준비물, 현재 행동 하나 |
| 초4~6 | 숙제 순서, 준비물, 예상 시간, 다음 시작 위치 |
| 중학생 | 과목별 숙제·수행평가·마감·주간 분량 |
| 고등학생 | 시험·수행평가·장기 목표의 중간 마감과 역산 |
| 대학생·성인 | 실제 가용 시간, 프로젝트, 담당자, 선행 작업, 대기·인계 |

정식 모드에서 학생이 연령이나 PASS 프로필을 직접 선택하지 않는다. QA 패널은 데모에서만 제공한다.

## 9. 결과지 연동 안전 규칙

- 프로덕션은 유효한 결과지 payload가 없으면 플래너를 열지 않는다.
- `subjectId`, `assessmentId`, `profileVersion`, `interpretationVersion`이 바뀌면 별도 프로필 저장공간을 사용한다.
- 손상되거나 불완전한 payload는 기존 정상 상태를 덮어쓰지 않는다.
- 로그아웃·사용자 변경 시 다른 사용자의 결과와 기록이 남지 않게 한다.
- 결과지 원문, 검사 문항, 토큰을 로컬 플래너 기록에 복제하지 않는다.
- 학생 화면에는 내부 규칙 버전·source hash·QA 상태를 노출하지 않는다.

## 10. QA 승인 기준

- 상단에서 네 영역 점수와 단위가 모바일·데스크톱 모두 보인다.
- K-PASS와 D-CAS의 서로 다른 점수 종류가 잘못 표기되지 않는다.
- 공식 지원순서가 우선되고, 복수 하 영역은 회차별로 순환한다.
- 강점은 표시 방식만 바꾸고 정답·완료를 대신하지 않는다.
- PASS 네 영역의 조작과 저장 근거가 서로 다르다.
- 건너뛰어도 과제는 실행되며 훈련 완료로 오인되지 않는다.
- 결과지 교체·로그아웃·손상 payload에서 사용자 데이터가 섞이지 않는다.
- 360px에서 점수 카드·버튼·본문이 겹치거나 가로로 넘치지 않는다.
