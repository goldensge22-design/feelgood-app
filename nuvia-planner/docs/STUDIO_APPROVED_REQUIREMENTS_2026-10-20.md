## 1. 누구를 위한 플래너인가

중학생·고등학생은 실제 학습 과제를, 대학생·성인은 실제 수업·생활·업무·진로 과제를 다룬다. 특강·캠프에서는 사용법을 익히고 이후 개인이 일상에서 지속적으로 활용한다. 특강 시간표나 교사의 운영 화면이 개인 작업대의 중심이 되어서는 안 된다. 초등용은 별도 후속 설계이다.

계획을 잘 세우지 못하거나 사용을 쉬었다 돌아온 사람도 한 가지 행동부터 시작할 수 있어야 한다. 계획 누락·미완료·미접속을 실패나 손실로 표현하지 않는다.

### 시각·조작 원칙

파일의 윗면·옆면·종이 층과 얕은 그림자로 절제된 입체감을 준다. 승인 이미지를 배경 이미지로 붙여 실제 UI를 대체하지 않는다. 의미 없는 빈 파일·가짜 완료 예시로 사용자의 성과를 꾸미지 않는다.

색뿐 아니라 과목·상태 텍스트와 아이콘을 함께 제공한다. 파일이 겹쳐도 이름표와 전체 제목을 확인할 수 있게 한다. 클릭하여 선택·작업대 배치·보관·복귀할 수 있으며, 선택이나 이동만으로 타이머가 시작되지 않는다.

버튼은 최소 44px, 보이는 키보드 포커스, 의미 있는 접근성 이름을 제공한다. 이동·놓임·완료 모션은 짧게 하고 `prefers-reduced-motion`을 존중한다. 실행 중 반복 모션은 넣지 않는다.

## 3. 추가 → 실행 → 조정

1. 할 일을 추가할 때 제목·활동 영역·예상 시간을 정한다. 과목은 필요한 경우 선택한다.
2. 예상 시간은 10 / 25 / 45분, 직접 입력 또는 미정으로 선택한다. 미정을 임의의 25분으로 바꾸지 않는다.
3. 날짜·시작 시각·범위·준비물·단계 등은 접힌 선택 항목에서 설정할 수 있다.
4. 작업대에 올라온 뒤에는 현재 행동·시간·시작을 우선 보여준다. 상세 편집·도움·설정이 기본 화면을 긴 양식으로 만들지 않게 한다.
5. 최근 과제를 재사용해도 기본값·복사만으로 목표 연습 수행을 인정하지 않는다.
6. 시작은 항상 가능하다. 필요한 질문은 시작 흐름 안에서 하나만 묻고 「바로 시작」을 제공한다.
7. 실행은 한 블록만 가능하다. 같은 카드 안에서 과제명·현재 행동·남은 시간 또는 미정의 경과 시간·중단·종료를 보여준다.
8. 중단·보관 후에는 같은 과제·범위·행동·복귀 위치·시간으로 이어간다. 자신의 일시정지 기록을 다른 과제 실행으로 잘못 안내하지 않는다.
9. 시간 만료는 계속 여부만 묻는다. 실행 종료와 과제 완료는 별도 선택이다.
10. 미완료는 5분 더 / 다음 블록 / 오늘은 여기까지를 제공한다. 자동 완료·자동 강제 이동은 하지 않는다.
11. 종료 후 짧은 진도·다음 위치와 선택형 전략 성찰을 받는다. 예상 대비 실제 실행 시간을 중립적으로 보여주고 다음 시간 줄이기 / 두 블록 / 같은 시간 유지 중 선택하게 한다.

실제 실행 시간은 정지 시간을 제외한 실행 참고값이다. 집중력·인지능력·교육 효과의 측정값이 아니다. 계획 시간 미정은 배치 합계와 예상·실제 차이 계산에서 제외한다.

## 4. 결과지와 개인화 행동카드

81가지 공식 인지특성을 81개 별도 앱이나 학생 유형으로 고정하지 않는다. 결과지의 공식 4영역 수준·지원 순서·강점 순서를 사용해 다섯 가지 목표 활동과 강점 지원 방식을 조합한다. 점수에서 임의의 상·중·하 기준을 재계산하지 않는다.

| 목표 | 직접 수행하는 행동 | 상황에 따라 기록하는 행동 |
| --- | --- | --- |
| 할 만큼 정하기 | 시작 전 명시적 계획 확인 또는 시간·범위·순서 변경 | 실행 후 다음 분량 조정 |
| 지금 한 가지에 머물기 | 현재 할 행동 선택 | 다른 생각 보관, 깃발 남기기, 복귀 |
| 전체 연결하기 | 실제 연결 항목 2개 이상과 관계 확인 | 발견한 충돌 수정 |
| 단계대로 해보기 | 실제 단계 2개 이상과 1단계 이상 직접 진행 표시 | 단계 순서 변경 |
| 계획 → 실행 → 조정 | 계획 확인 또는 변경과 실행 종료 | 선택형 성찰 |

목표 행동의 증거와 실행 종료를 확인한 뒤 회차가 진행된다. 날짜 변경·타이머 만료·새로고침·건너뜀만으로 목표 수행을 인정하거나 다음 약점으로 순환하지 않는다. 여러 지원 목표가 있으면 보존하고 순환한다.

동시처리 강점은 관계·전체 묶음, 순차처리 강점은 현재·다음 단계, 계획 강점은 목표·완료 기준, 주의 강점은 핵심 강조로 지원한다. 답이나 계획을 대신 결정하지 않는다. 학생 기본 화면에는 이론 용어보다 행동 이름을 사용한다.

행동카드는 목표 / 나에게 맞는 방법 / 첫 행동 / 실행 조건 / 막힐 때 대안 / 돌아보기로 연결한다. 최초 계획과 수정 이력을 구분하고 목표·지원 방식에 따라 실제 입력과 활동이 달라져야 한다.

검사 결과 미보유자는 일반 도움을 사용할 수 있으나 이를 결과지 연동 또는 공식 개인화 완료로 표시하지 않는다. 공식 결과지 연동은 인증된 데이터 공급과 검증이 필요하다.

## 5. 월간 수행과 다음 달 제안

수행률은 합의한 연습의 수행 비율이며 인지능력 향상률이 아니다.

- 분모: 해당 기간에 사용자가 동의한 목표별 연습량.
- 분자: 실제 목표 행동과 실행 종료 증거가 있는 중복 제거된 회차.
- 구간: 정확히 100%, 70% 이상 100% 미만, 50% 이상 70% 미만, 0% 이상 50% 미만. 반올림한 표시값으로 구간을 결정하지 않는다.
- 자료 부족·분모 없음은 별도 상태로 처리한다. 누락을 자동으로 0% 판정하지 않는다.
- 초과 수행은 별도 정보로 보여주며 분모 변경·삭제로 성과를 부풀리지 않는다. 합의 변경 이력을 보존한다.
- 전체 비율은 목표별 합계를 기준으로 계산하고 비율의 단순 평균을 사용하지 않는다.

| 수행 구간 | 다음 달 제안 방향 |
| --- | --- |
| 100% | 유지, 원하면 다른 실제 과제로 전이 |
| 70–99% | 대체로 유지하며 한 가지 조정 |
| 50–69% | 분량·입력·단계를 줄이고 도움 강화 |
| 0–49% | 상황을 확인하고 강점을 활용한 더 작은 시작 제안 |

검사상 지원 목표는 활동 기록만으로 사라지거나 점수가 올라가지 않는다. 제안은 초안이며 사용자가 수락·수정·보류하기 전 다음 달 일정에 자동 적용하지 않는다. 반복 수락으로 중복 계획을 만들지 않는다.

리포트는 고정된 검사 결과 / 이번 달 실제 행동 / 사용자가 선택한 다음 전략을 시각적으로 구분한다. “나아짐”은 비교 가능한 실제 기록이 있을 때만 보여준다. 필요하면 실행 시작·복귀·계획 조정 등 각각의 변화와 자료 수를 제시하되 종합 인지 향상 점수는 만들지 않는다.

## 6. 「검사 결과와 내 경험」 비교

「맞아요 / 달라요 / 모르겠어요」는 구체적인 추천이나 설명에 대한 자기보고로 저장한다. 초기 응답·변경·시점·상황을 구분한다. 사용자가 선택한 도움의 유용성과 실제 사용 기록을 참고할 수 있지만 앱이 제공한 도움을 수행했다는 이유로 검사 결과가 맞았다고 판정하지 않는다.

응답이 없는 경우와 도움이 되지 않았다는 응답도 구분한다. 검사 일치율·진단 정확도·인지 향상률을 활동 기록에서 역산하지 않는다. 외부 확인은 실제 확인자가 제공한 별도 출처가 있을 때만 표시한다.

## 7. 보관함의 앱 진입 안내

보관 후 7일 이상 지난 작업을 앱을 열 때 한 번 확인하도록 제안한다. 푸시·소리·앱 외 알림은 이번 범위가 아니다. 여러 작업은 묶어 안내하고 사용자는 작업대로 / 계속 보관 / 이번 계획에서 빼기를 고른다.

같은 보관 회차의 새로고침·매일 진입마다 재촉하지 않는다. 미래 예정일이 남은 작업과 완료·제외된 작업은 부적절하게 재촉하지 않는다. 알림 끄기를 제공하며 어떤 선택도 실패로 표시하지 않는다.

## 8. 나의 로드맵

한 달의 실제 목표·시도·전략·수정·결과와 사용자가 연결한 결과물을 경험 카드로 모은다. 개인 메모·다른 생각 보관함은 자동 공개하거나 자기소개서에 자동 포함하지 않는다.

학생이 선택한 기록으로 상황 / 어려움 / 직접 한 행동 / 바꾼 방법 / 확인 가능한 결과 / 배운 점을 정리한다. 자기소개서 자료는 사실 기반 초안이며 사용자 확인·편집 후 내보낸다. 존재하지 않는 성취·역량·인과 효과를 생성하지 않는다. 검사 점수 자체를 역량 증명으로 쓰지 않는다.

각 내용의 원본 기록을 추적하고 원본 변경·삭제 시 재확인을 요구한다. AI 서버가 없다면 템플릿 초안을 실제 AI 작성 기능으로 표시하지 않는다.

## 9. 개발·저장·연동 보호

- 기존 assessment 계약의 식별자·버전·점수 종류·단위·공식 수준·연령·지원 순서·강점 순서를 보존한다. Studio와 기존 adapter가 다르면 명시적인 변환 계층과 테스트를 둔다.
- 데모 데이터는 예시로 표시하고 개인 기록과 분리한다. 비교용 예시를 사용자 기록에 덮어쓰지 않는다.
- 상태는 언어 독립 ID, 문구는 번역 키로 관리한다. 기존 검수 번역은 재생성하지 않는다. 신규·변경 키와 미검수 상태를 추적하고 fallback을 번역 완료로 세지 않는다.
- 언어 변경으로 과제·타이머·현재 탭·결과지를 초기화하지 않는다.
- 로컬 저장·백업과 실제 서버 저장·권한·인증·동기화는 구분한다. 클라이언트의 결과지 JSON 주입은 인증이나 권한 검증을 대신하지 않는다.
- 최신 소스·잠금 파일·빌드 설정·테스트·정확한 인계 문서를 함께 제공한다. ZIP만 있고 재현 소스가 없는 상태를 인계 완료로 표시하지 않는다.
- 수정 이력·원본 참조·개인정보 분리 및 기존 백업의 호환 한계를 문서화한다.

## 금지
