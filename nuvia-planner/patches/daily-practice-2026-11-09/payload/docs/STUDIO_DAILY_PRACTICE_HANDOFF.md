# 연령별 일상 추천 연습 — 개발자 인계

## 상태와 범위

- 수정 전 Replit 소스 기준: `e1209da854493369e664d8922509390d55a7f34f`.
- 기존 Studio에 추가하는 검토용 패치다. 정식 플래너·D-CAS·결과지·BrainMap·GitHub/main·공개 게시를 변경하지 않는다.
- 현재 개발 진입: `/library-demo.html?demo=university` → 계획 → 할 일 추가 근처 **추천 연습**.
- 5연령 합성 비교: `/practice-compare.html`. 개발 서버 전용이다. 연령/목표 전환은 그 비교 공간만 초기화하지만 강점만 바꾸면 입력·과제를 유지한다. 저장/실제 결과 입력/서버 전송이 없고 생산 빌드 입력에도 포함하지 않는다.
- 대학/학교/기업 가상 데모의 기존 경고·15언어 선택기·독립 브라우저 저장소를 유지한다.
- 실제 결과 서버, 로그인, 기기간 동기화, 개인정보 서버, 외부 AI 추천을 새로 연결하지 않았다.

## 기존 기능 점검과 재사용

기존 코드에는 `routeFor`의 공식 수준·지원/강점 순서·회차 해석, `TaskCreator`와 `updateStudio(create)`의
과제 생성, 기존 타이머/일시정지·깃발 복귀/실행 종료·완료 구분, 월간 근거·로드맵·메모·백업이 있었다.
직무/일상 라이브러리는 한국어 검토 전용 미승인 콘텐츠였으며 일반 사용자에게 공개할 수 없었다.
새 추천은 이 카탈로그를 우회 공개하지 않는 별도 일상 활동 템플릿이다.

`practice.add`가 기존 create를 호출하므로 별도 플래너·타이머·월간 산식을 만들지 않는다.
카드 선택/미리보기/추가로 실행을 시작하거나 완료·목표 수행을 인정하지 않는다.
원래 기본 분량·시간은 `timeChosen=false`, `scopeChosen=false`, `planReviewed=false`다.
사용자의 실제 편집 또는 기존 행동 확인 뒤 실행 종료가 있어야 기존 회차 근거에 반영된다.
중복 requestId는 같은 기존 과제를 돌려주며 추가 클릭으로 복제하지 않는다.
최초 추가의 세부 설정/도움 선택은 최초 계획·최초 도움으로 기록한다. 이를 실행 중 방법 변경이나
사후 계획 수정으로 부풀리지 않는다. 이 보정은 새 과제 생성에만 적용하며 기존 저장 기록은 다시 쓰지 않는다.

## 콘텐츠 수와 검토 상태

- 독립 원본: **10개**, 목표별 2개.
- 연령: **5개**, 각 원본의 연령별 입력/범위 변형 **50개**.
- 새로운 진단 유형 50개나 81개 독립 훈련이 아니다.
- 계획: 작은 준비 계획 / 한 구역 정리 범위.
- 주의: 지금 볼 대상 하나 / 필요한 정보 하나.
- 관계 연결: 익숙한 위치·쓰임 / 준비물·목표.
- 순서: 평범한 사건 재구성 / 실제 준비 과정.
- 통합: 작은 일 계획·실행 / 다음 준비.
- 콘텐츠·번역은 AI 초안이다. 전문가/원어민 검수 또는 효과 검증 완료로 승격하지 않는다.

첫 화면은 현재 목표 후보 1개를 보여주고 **다른 추천 보기**로 두 번째 후보를 고른다.
사용자는 직접 작성/추천 없이 시작으로 기존 입력을 사용할 수 있다.
시간·분량·사례·6개 도움 선택은 명시적 추가 전 미리보기에서 변경한다.

### 실제 연령별 입력 차이

| 연령 | 범위와 선택 입력 |
| --- | --- |
| 초1~3 | 익숙한 그림/물건, 2개 그림 표찰·짧은 입력(40자), 행동 하나 |
| 초4~6 | 학교 준비·간단한 이유, 3개 짧은 입력(80자) |
| 중학생 | 공부 준비/일상 사건/준비물, 3개 입력(160자)과 짧은 설명 안내 |
| 고등학생 | 일정·최종 마감 날짜 입력 2개와 조건/분량 입력 |
| 대학·성인 | 책임자·선행작업·인계 입력, 대기 선택, 전이 설명 |

순서 활동에서 달력 날짜·담당·선행작업·인계 값은 실행 단계가 아니다.
고등학생은 날짜 뒤의 행동 필드, 성인은 역할 필드 뒤의 행동 필드만 단계 후보로 넘긴다.
후보 단계도 기존 단계 확정과 직접 진행 표시를 거쳐야 한다.

초등은 기존 일반 진입을 확대하지 않고 review 모드 비교에서만 추천한다.
일반 후보를 만들기 위해 성인 실제 프로필을 초등으로 재분류하지 않는다.
모든 추가 입력은 접힌 선택 영역이며 기본 제목·행동만으로 미리보기를 진행할 수 있다.

## 결과·도움·기록 경계

검증된 기존 결과의 선언된 수준/순서와 기존 `routeFor`를 사용한다. 점수 컷이나 점수 단위를 새로 만들지 않는다.
공식 복수 지원 순서가 없거나 결과가 무효이면 통합 일반 활동과 자기선택 도움으로 후퇴한다.
검사 미연결도 검사 추천처럼 표시하지 않고 통합 일반 활동을 준다.
강점 순서가 없으면 기존 공통 도움을 사용한다. 강점 없음/동률에서 강점을 꾸미지 않는다.
도움은 목표·완료 기준 / 한 가지 강조 / 관계 묶음 / 현재·다음 순서 / 공통 / 줄이기다.
활동 목표와 강점 정보 제시를 구분하며 정답·연결·완료 체크를 대신 만들지 않는다.

추천 출처, 선택 당시 검사 스냅샷·회차·목표·강점 도움·사용자 도움·연령·언어·초기 입력을 보존한다.
검사/언어 변경으로 기존 기록을 재분류하지 않는다.
저장 원문은 번역하지 않는다. 제품 기본값은 provenance와 편집 이력을 확인한 표시 경계에서만 현지화한다.
같은 말을 직접 입력/수정한 경우는 보수적으로 원문으로 표시한다.
미리보기 언어 전환도 수정하지 않은 제품 기본값만 갱신하며 학생이 적은 문장·날짜·시간·도움 선택은 유지한다.

열람 기록 / 과제 추가 / 종료한 실제 실행 / 선택적 도움 자기보고는 서로 다른 기록이다.
응답 변경 이력을 남기되 보고서 응답 수는 실행별 최신 응답 1개이며 미응답도 따로 표시한다.
실행 횟수는 목표 수행 횟수가 아니다. 월간 수행률/분모/다음 달 초안 승인 규칙은 바꾸지 않는다.
로드맵은 기존 원본 연결·버전·재확인 규칙을 재사용하며 일상 연습 문맥만 붙인다.
메모·생각 보관함 전문은 새 리포트나 공용 라이브러리에 넣지 않는다.

## 안전과 다국어

눈을 감고 이동하는 활동은 없다. 앉아서 익숙한 위치를 적거나 그린 뒤 비교하고,
불편하면 관찰하면서 연결하는 선택을 제공한다. 기억 점수·PASS 점수·능력 향상률을 만들지 않는다.
사건은 평범한 2~5단계만 다루고 타인 정보·사적인 사건·힘든 기억은 요구하지 않는다.

신규 103키×15언어를 별도 locale 파일로 추가했다. 기존 번역값은 재생성하지 않았다.
상태는 `src/practice-recommendations/translation-status.json`에 내부 기록하며 일반 화면에 검수 메타데이터를 넣지 않는다.
기술 검사는 문법/키/문자권/표시/동작 검사이며 원어민의 자연스러움 검수를 대체하지 않는다.

## 적용·중단·되돌리기

1. 개발자 최신 결과/서버 연동 브랜치와 이 기준을 비교한다. 현재 Replit과 최신 GitHub가 같다고 가정하지 않는다.
2. 현재 소스·원본 브라우저 백업을 별도로 보존하고 작업 브랜치에서만 적용한다.
3. 패치의 BEFORE 해시 또는 신규 파일 경로가 다르면 중단한다. 통째로 덮어쓰지 않는다.
4. 신규 폴더와 Studio의 최소 연결 변경을 검토한다. 공식 결과 파일은 변경 목록에 있으면 안 된다.
5. 기존/신규 회귀와 실제 브라우저 검수를 실행한 뒤 사용자 검토를 받는다. 공개 게시 별도 승인.
6. 되돌릴 때 변경 파일을 보존한 원본으로 되돌리고 신규 파일만 제거한다. localStorage를 삭제/이관하지 않는다.
7. 신규 practice 필드가 생긴 백업을 필드 미지원 과거 앱에 그대로 넣으면 거부될 수 있다.
   과거 앱을 위해 데이터를 자동 삭제/변환하지 말고 이 패치와 함께 보존한다. 구형 필드 없는 백업은 새 앱에서 계속 지원한다.
8. 소스 롤백 검증은 별도 빈 브라우저 프로필에서 한다. 호환성을 확인하기 전에 신규 기록이 있는 같은
   저장 공간을 구형 앱으로 열지 않는다. 현재 백업과 구버전용 원래 백업을 모두 보존하고 임의 변환하지 않는다.

검수 상세와 미확인 사항은 `STUDIO_DAILY_PRACTICE_QA.md`를 따른다.
