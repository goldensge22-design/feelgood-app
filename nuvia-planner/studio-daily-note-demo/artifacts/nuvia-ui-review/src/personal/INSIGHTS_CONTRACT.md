# 개인 플래너 기능 보강의 경계

- 현재 디자인을 유지한다. 기능 보강 승인은 전면 3D 디자인 교체 승인이 아니다.
- 기존 저장 키와 스키마 버전을 바꾸지 않고 선택적 insights 필드로 확장한다. 필드가 없는 이전 자료와 백업을 허용한다.
- 검사값·상중하·지원/강점 순서는 입력 그대로 보존한다. 점수컷, 공식 81유형 해석표, 서버 인증을 만들지 않는다.
- 원본 결과 계약은 출처 이력에 보존한다. 기존 합성 실험 공간의 고정 식별정보 계약을 약화시키지 않기 위해 내부 실행용 식별정보와 원본 식별정보를 분리한다. 이는 실제 서버 어댑터나 소유자 인증이 아니다.
- 검사 출처는 명시적 예시 또는 로컬 계약 입력이다. 이전 자료의 출처·검사일을 추정하지 않는다.
- 종료 실행마다 과제·분량·종류·예상시간·도움 사용·일시정지 제외 시간·출처를 별도 보존한다. 현재 검사를 과거 실행에 소급 연결하지 않는다.
- 설명 응답은 설명/과제/검사 문맥별 추가 이력이다. 방법 후기는 종료한 실제 사용 건별이며 변경 전 응답을 삭제하지 않는다. 미응답을 동의나 실패로 세지 않는다.
- 방법 사용 건수와 최신 응답 건수는 별개다. 자기보고를 외부 확인이나 검사 정확성의 근거로 승격하지 않는다.
- 다음 달 초안은 도움 선호를 참고하되 공식 목표/점수와 기존 일정은 수정하지 않는다. 실제 반영에는 학생 수락이 필요하다.
- 보고서는 고정된 검사 출발점 / 실제 실행 변화 / 다음 달 제안으로 구성한다. 공유에서 검사 상세는 기본 미선택이며 원문 생각 보관·개인 메모는 자동 포함하지 않는다.
- 같은 과제·과목·분량·종류의 기록만 시간 차이 참고 그룹으로 묶는다. 환경과 난도를 독립 검증한 비교나 능력 향상률이 아니다.
- 신규 문구는 한국어 기능 검토 상태다. 기존 검수 번역은 수정하지 않으며 미완료 번역을 완료로 표시하지 않는다.

검수 스크립트는 tools/nuvia-personal/insights-check.ts, insights-browser.mjs,
insights-report-smoke.mjs이며 기존 check.ts/browser.mjs/supplemental.mjs도
회귀 확인에 사용한다. 실제 참가자의 독립 사용·효과성·장기 추적 검증은 별도다.
