# NUVIA PLANNER · B 통합 UI 후보 검토 및 요구사항 점검

## 판단 범위

- **기준:** `goldensge22-design/feelgood-app`의 `codex/recover-planner-dcas81`, 커밋 `defa19d7c7601157b47ddb10cf4d62fdf9bebf82`, `nuvia-planner/source/src`.
- **비교 대상:** 위 소스의 기준 UI와, 이를 별도로 복제해 수정한 검토 UI. `src/before` 및 기존 `NUVIA_PLANNER_UI_patch_defa19d.zip`은 보존했다. **이전 패치와 새 후보 모두 적용 보류.**
- **절대 범위 밖:** 담당 개발자의 최신 결과지 연동 브랜치, 공개 데모, main, 정식 서비스, 실제 학생 계정/기록. 현재 검토본의 브라우저 결과를 이들에게 일반화하지 않는다.
- **판정:** 이 문서의 `확인`은 지정 커밋과 독립 샘플/브라우저 조작에만 해당한다. `부분`은 UI만 있거나 대표 경로만 검수했음을, `미완료`는 공식 규칙에 비추어 실제 기능·검증이 빠졌음을 뜻한다.

## 전후 비교를 재현하는 방법

미리보기의 `/compare.html`에서 **동일 장면**(첫 진입, 순서 변경, 실행, 잠시 보관, 복귀, 종료 기록, 리포트, 책상색, 빈 계획, 긴 제목, 시간 초과)을 선택한다. `모바일 360px로 보기`로 양쪽 iframe의 실제 내부 너비를 360px로 바꾼다. 각 독립 링크로 확대해 조작할 수 있다. 비교 전용 프레임은 실제 `localStorage`와 `sessionStorage`를 읽기 전에 메모리 저장소로 교체한다. 교체가 실패하면 앱을 부팅하지 않는다. 샘플의 네 과제·과목·분량(10/25/35/45분)·시각(16:00~)·날짜·가용 시간(120분)·상태는 양쪽이 같고, `scene`별 상태 변경도 같은 방식으로 만든다. 실제 학생 저장값을 초기화하지 않는다. `?student=1`은 QA 띠만 숨기는 캡처용 표시로, 샘플 자체는 바꾸지 않는다.

| 동일 조건에서 측정 | 기존 기준본 | 개선 검토본 |
|---|---:|---:|
| 시작까지 필요한 클릭 (B, 샘플의 첫 과제) | 1회 | 1회 |
| 시작 버튼의 화면 위에서부터 하단 위치 · 360×800 | **1,911px** | **751px** |
| 시작 버튼의 화면 위에서부터 하단 위치 · 1440×900 | **1,571px** | **706px** |
| 첫 화면의 과제·시작 조작 | 아래로 스크롤 필요 | 같은 첫 화면에서 과제명·분량·시작 노출 |
| 구조 | 결과/프로필/학년 선택과 탭 선행, 계획과 실행 분리 | 결과 축약 표시 + 하나의 세로 과제 목록, 선택한 과제 상세를 데스크톱 오른쪽/모바일 해당 행 아래에 표시 |

위 위치 값은 브라우저에서 `getBoundingClientRect()`로 측정하고 Replit 개발 도구 모음 높이를 제외한 값이다. 결과는 예시 데이터·지정 크기의 브라우저에서만 재현한 것이며, 클릭 횟수 감소를 주장하지 않는다. 기존본은 선택/시작을 스크롤로 찾아 클릭할 수 있고, 새 본은 첫 화면에서 같은 1회를 할 수 있다는 차이다.

## 검사 방법과 적용 안전성

- 2026-09-30 기준 Vite 빌드와 TypeScript 검사 통과. 브라우저 자동화는 `tools/nuvia-patch/qa-browser.mjs`로 실행했다. 스크린샷 단독으로 조작을 검증했다고 하지 않는다. 모바일 터치는 CDP 입력 에뮬레이션이다.
- 캡처: `screenshots/nuvia-baseline-mobile-clean.jpg`, `nuvia-candidate-mobile-clean.jpg`, `nuvia-baseline-desktop-clean.jpg`, `nuvia-candidate-desktop-clean.jpg`, `nuvia-comparison-desktop.jpg`; 실행/중단/리포트 및 768px 보조 캡처는 `screenshots/candidate-*.png` (자동화 브라우저에서는 한국어 글꼴이 네모로 보일 수 있어 레이아웃·상태 증거로만 사용).
- 수정한 **공식 소스는 다섯 파일**: `src/adaptive/AdaptivePlanner.tsx`, `PlannerEnhancements.tsx`, `TimeBlockBoard.tsx`, `planner-2-5.css`, `time-blocks.css`. 기준 엔진, Assessment 검사/점수, 결과지 계약, 저장 키는 후보 패치에서 건드리지 않았다. 책상색 별도 키만 추가. 비교 띠/메모리 샘플/`App.tsx`는 미리보기 전용이며 ZIP에 들어가지 않는다.
- 새 후보 ZIP 압축 검사 통과. **임시 기준 소스 사본**에서 `--check`는 pending 5/conflict 0, 적용은 5, 재검사·재적용은 pending 0/already 5, 롤백은 대상 5개 경로가 기준 바이트와 일치했다. 한 대상 파일을 임의 수정한 충돌 사본에서는 검사/적용 모두 종료 코드 2였고 대상 파일들의 해시는 전후 동일했다. 이전 ZIP은 삭제/수정하지 않았다.

## 승인 전 남은 일

담당 개발자가 **최신 결과지 연동본에서** 충돌을 수동 검토·병합한 다음, 공식 Assessment v1.1의 K-PASS/D-CAS 실제 입력, 복수 low 회차 순환, 강점 표현만 변경되는지, 오류 payload·로그아웃 격리, 이벤트 근거, 백업/복원, 다른 탭/언어, 다섯 연령 단계 및 실기기 키보드·터치를 재검수해야 한다. 충돌을 강제 덮어쓰거나 이번 후보의 UI 완료를 전체 규칙 승인으로 해석하면 안 된다. **디자인 승인 전에는 새 후보도 적용 보류**한다.
