# NUVIA 개인 사용·월간 조정 추가형 후보 — 적용 전 확인

이 산출물은 **검토용 후보**입니다. 기존 플래너를 통째로 덮어쓰거나 운영 배포하는 패키지가 아닙니다.

- 공식 소스 출처 기준: `defa19d7c7601157b47ddb10cf4d62fdf9bebf82`.
- 개발자의 실제 최신 결과지/인증/서버 연동 체크아웃은 제공받지 못했습니다. 그 최신본과의 호환성은 **미검증**입니다.
- Replit에서 보존한 공식·B형·기존 enhancement와 새 후보를 비교해 검수했습니다. 이것이 최신 GitHub 통합 검증을 대체하지 않습니다.
- 패키지는 새 진입점, 새 개인 기능, 독립 호환 코어만 추가합니다. 기존 파일 자동 수정은 0개입니다. 원래 엔진·브랜드 파일은 해시로 검사하며 일치하지 않으면 중단합니다.

## 개발자 확인 순서

1. 현재 공식 저장소의 실제 최신 브랜치·결과지 계약·점수 척도·상중하·지원/강점 순서·인증/저장 계약을 확인합니다. 실데이터를 검토본에 복사하지 않습니다.
2. 사용자 승인 뒤, 별도 검토 브랜치/작업 복사본을 만들고 변경과 데이터를 별도로 백업합니다. main/master와 작업 중인 변경이 있는 트리에서는 설치기가 중단합니다.
3. ZIP을 소스 트리 밖에 풉니다. 검토를 마친 현재 HEAD 전체 SHA를 지정합니다.

```
python /패치압축해제경로/install.py check --root /별도/소스 --reviewed-head 정확한현재HEAD
```

4. 의존 해시 불일치, 파일 충돌, 패키지 손상, 미검토 SHA면 **중단**합니다. `--force`, 파일 전체 복사, 기존 파일 삭제로 우회하지 않습니다. 개발자가 최신 변경과 수동 대조한 뒤 새로운 패치를 만들어야 합니다.
5. 검토 승인한 추가 파일만 설치하려면:

```
python /패치압축해제경로/install.py apply --root /별도/소스 --reviewed-head 정확한현재HEAD --ack-latest-review
```

6. 설치기는 기존 Vite 설정을 건드리지 않습니다. 개발자가 별도 브랜치에서 기존 다중 진입점 목록에 `personalMonthly: resolve(import.meta.dirname, "personal-monthly.html")` 한 항목만 검토 추가합니다. 해당 프로젝트의 설정 구조에 맞게 조정하며 기존 엔트리를 제거하지 않습니다. 자동 서버 연결·DB 변경·push·배포는 하지 않습니다.
7. 타입·빌드·새 후보·기존 플래너·결과지·HISTORY·서버 연동 회귀를 실제 최신 소스에서 다시 수행합니다. 이 패치의 core는 검토 시점 복사본이며 개발자의 최신 계약과 자동 동기화되지 않습니다.

## 데이터와 연동 경계

새 후보는 독립 브라우저 저장 공간입니다. 이전 검토본/공식 사용자 기록을 읽거나 이관하거나 초기화하지 않습니다. 기존 기록을 옮기는 마이그레이션은 포함하지 않습니다.

검사·유형 식별정보는 실제 서버가 연결될 때 별도 검증해야 합니다. 공식 81유형별 해석표, 실제 교사 권한, 로그인, 기기간 동기화는 구현되지 않았습니다. 이 후보는 상중하 3^4 조합의 목표/도움 조합을 검토합니다.

개인 백업은 같은 개인 공간 복원용 평문 JSON이며, 보고서가 아닙니다. 전체 합성 공간 백업은 검토 모드에서만 허용합니다. 실제 학생 정보를 입력/반입하지 마세요.

## 복구

```
python /패치압축해제경로/install.py rollback --root /별도/소스
```

복구 명세에 기록된 **이번 추가 파일 중 해시가 그대로인 파일만** 삭제합니다. 설치 뒤 수정된 파일이 있으면 중단하며 강제 삭제하지 않습니다. 기존 파일·개인 기록·DB는 삭제하지 않습니다. 수동 추가한 Vite 진입점은 개발자가 자신의 해당 변경만 되돌립니다. 브라우저 기록을 지우거나 과거 백업으로 강제 교체하지 마세요.
