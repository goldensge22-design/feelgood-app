# FeelGood 전자교사 가이드 B안 본제작 프롬프트

아래 지시사항에 따라 FeelGood의 K-PASS·D-CAS·NUVIA 전자교사 가이드를 제작해줘.

## 1. 프로젝트 목표

학교 교사가 K-PASS와 D-CAS 결과를 단순히 확인하는 데서 그치지 않고, 학생의 인지처리 특성을 이해하여 수업·상담·자기관리 지원과 NUVIA 가정 훈련으로 연결할 수 있는 반응형 웹 가이드를 만든다.

- 배포 방식: GitHub Pages 링크형 웹 가이드
- 저장소: `goldensge22-design/feelgood-app`
- 권장 경로: `/teacher-guide/`
- 기존 페이지와 파일은 삭제하거나 덮어쓰지 말고 새로운 폴더에 독립적으로 구현한다.
- 첨부된 통합기획 MD와 브로셔, FeelGood 로고, B안 디자인 이미지를 먼저 모두 확인한 뒤 작업한다.

## 2. 최종 디자인 방향 — B안 Cognitive Map

디자인은 **B안 Cognitive Map**으로 확정한다. A안·C안 또는 추가 디자인 시안은 만들지 않는다.

### 핵심 콘셉트

- 학생의 인지처리 방식을 한 장의 ‘인지 지도’처럼 이해하게 한다.
- 교육·심리 분야의 신뢰감과 디지털 서비스의 명료함을 함께 전달한다.
- 전문적이되 차갑지 않고, 학생용 게임처럼 유아적으로 보이지 않게 한다.
- 정보량이 많아도 교사가 빠르게 탐색할 수 있는 카드형·경로형 구조를 사용한다.

### 시각 언어

- 메인 배경: 부드러운 크림색
- 핵심 히어로 영역: 깊은 네이비
- 카드: 흰색, 얇은 청회색 테두리, 충분한 여백, 부드러운 모서리
- 인지 지도를 연상시키는 원·궤도·연결선 그래픽을 절제해 사용한다.
- PASS 네 영역은 다음 색으로 일관되게 구분한다.
  - Plan·계획: 퍼플
  - Attention·주의: 블루
  - Simultaneous·동시처리: 스카이블루
  - Successive·순차처리: 오렌지
- FeelGood 브랜드 기준색을 활용한다.
  - Orange: `#F4A418`
  - Blue: `#2E75CC`
  - Gray: `#676767`
- FeelGood 로고의 비율과 여백을 유지하고 임의로 변형하지 않는다.
- 과도한 그라데이션, 네온 효과, 무거운 글래스모피즘, 장식 위주의 애니메이션은 피한다.
- 미세한 깊이감과 제한적인 2.5D 요소만 사용한다.

## 3. 여는 글 — 문구 그대로 사용

홈 화면의 히어로 또는 첫 번째 소개 영역에 아래 문구를 그대로 사용한다. 이 영역에는 ‘성인’이라는 표현을 추가하지 않는다.

> **점수에서 이해로, 이해에서 성장으로.**
>
> # 다르게 생각하는 힘을, 다르게 성장하는 기회로.
>
> 결과지에 나타난 인지 강점과 지원 필요를 읽고, 학생마다 다른 정보처리 방식을 이해합니다. 그리고 그 이해를 각자에게 필요한 수업·상담·자기관리와 NUVIA 훈련의 방향으로 연결합니다.
>
> 이 가이드는 학생을 점수나 유형으로 규정하기 위한 것이 아닙니다. 학생이 어떤 방식으로 배우고 생각하는지 이해하여, 강점은 더 잘 발휘하고 어려움에는 적절한 도움을 제공하기 위한 교사의 인지 지도입니다.

### 여는 화면 구성

- 상단 키커: `COGNITIVE MAP · 교사용 인지 지도`
- 위 여는 글의 핵심 문장과 CTA를 배치한다.
- 1차 CTA: `검사별 가이드 보기`
- 2차 CTA: `결과를 수업에 연결하기`
- 오른쪽 또는 하단에는 PASS 네 영역 컬러 카드와 인지 지도 그래픽을 배치한다.
- 첫 화면만 보고도 ‘검사 결과를 교육적 지원으로 연결하는 교사용 가이드’임을 알 수 있어야 한다.

## 4. 정보 구조

한 개의 대표 링크 안에서 다음 경로를 명확히 분리한다.

1. K-PASS 아동용
2. D-CAS 청소년용
3. D-CAS 성인용
4. NUVIA 인지훈련 시리즈

여는 글과 맺음말에서는 학생 중심 언어를 사용하되, 전체 서비스 구조에서는 통합기획서에 정의된 D-CAS 성인용 경로를 유지한다.

### 주요 메뉴

- 인지 지도
- 대상별 경로
- 검사 소개
- 근거와 신뢰성
- 결과 읽기
- 81가지 특성
- 교사 활용
- 학급 대시보드
- NUVIA 연결
- 보호자 소통
- 도움 요청 기준

## 5. 반드시 구현할 핵심 콘텐츠

### 5.1 검사 소개와 개발 전문성

- K-PASS와 D-CAS가 교육심리학, 심리측정, 응용통계, 디지털 기술을 결합한 인지처리 검사임을 설명한다.
- PASS 인지처리 이론을 계획·주의·동시처리·순차처리의 네 영역으로 이해하기 쉽게 소개한다.
- 심리검사 표준화 경험을 보유한 전문가가 검사 설계, 점수 산출, 해석, 규준 설계에 참여했다는 내용을 담는다.
- 카우프만 검사의 국내 최초 도입 및 문수백 교수 관련 표현은 제공된 근거 자료에서 확인된 범위 안에서만 사용한다.
- ‘아시아 최초’ 등 확인되지 않은 우월성·최초성 표현은 사용하지 않는다.
- 검사 문항을 단순히 화면으로 옮긴 것이 아니라, 게임형 상호작용과 디지털 반응 데이터를 결합한 검사임을 설명한다.

### 5.2 신뢰도·타당도·표준화

- 제공된 연구자료에 있는 신뢰도, 타당도, 기존 검사와의 비교 결과를 교사가 이해할 수 있는 언어로 시각화한다.
- 메인 화면에서는 `전국 단위 연령·성별·지역을 고려한 한국 규준`처럼 의미를 먼저 전달한다.
- 표준화 인원수는 삭제하거나 숨기지 말고, 상세 근거 화면에서 표본 설계의 맥락과 함께 제시한다.
- 통합기획서에 확인된 경우에만 다음 맥락을 사용한다: 15개 지역, 27개 연령 구간, 연령별 300명, 성별 50:50, 전체 2,700명.
- 숫자는 크기 경쟁이 아니라 표본의 대표성·연령별 규준 설계·검증 절차를 설명하기 위해 사용한다.

### 5.3 디지털 상시 표준화 기술

- 기존 검사와 FeelGood 체계를 단정적으로 우열 비교하지 않는다.
- `디지털 데이터 수집과 정기 검수 체계를 통해 국가별 규준을 지속적으로 점검하고 고도화할 수 있다`고 설명한다.
- 국가별 유효 표본이 2,000명 이상 축적되면 자동으로 규준이 바뀐다고 표현하지 않는다.
- 표본 대표성, 신뢰도, 타당도, 문항 기능 차이, 버전 동등성 등을 전문가가 검토하고 검증된 경우에만 새 규준을 반영한다는 절차를 명확히 한다.
- `어느 검사보다 정확하다`, `자동으로 정확도가 높아진다` 같은 검증되지 않은 표현은 금지한다.

### 5.4 결과 해석과 81가지 특성

- 상·중·하 조합을 낙인이나 성격 유형이 아니라 현재 관찰된 인지처리 경향과 지원의 출발점으로 설명한다.
- 각 특성별 페이지 또는 카드에 다음 항목을 제공한다.
  - 인지처리 특징
  - 교실에서 관찰될 수 있는 모습
  - 강점이 드러나는 상황
  - 어려움이 나타날 수 있는 상황
  - 수업 설계 팁
  - 과제 제시 방법
  - 피드백·상담 문장 예시
  - NUVIA 권장 훈련 방향
  - 보호자 안내 포인트
- 81가지 특성 데이터는 화면 코드와 분리된 JSON 구조로 설계한다.
- 검색, PASS 영역 필터, 상·중·하 필터, 즐겨찾기 또는 인쇄 기능을 고려한다.

### 5.5 모두 ‘하’ 또는 광범위한 어려움이 나타나는 경우

- 불안감을 과도하게 높이지 않으면서도 추가 확인이 필요하다는 점을 명확하게 안내한다.
- 검사 한 번으로 장애나 질환을 진단하지 않는다.
- 검사 환경, 컨디션, 지시 이해, 언어·문화적 배경, 반복 관찰 자료를 먼저 함께 확인한다.
- 여러 영역의 낮은 수행이 지속되고 학습·생활의 어려움이 함께 관찰되면 보호자와 협의하여 전문기관의 종합검사나 상담을 권고한다.
- 위기·의료 판단을 교사가 단독으로 내리도록 유도하지 않는다.

### 5.6 교사의 실제 활용

- 개인 결과를 수업 난이도, 설명 방식, 자료 형태, 과제 분량, 시간 구조, 모둠 구성, 피드백 방식에 연결하는 예시를 제공한다.
- 학생을 유형으로 고정하지 않고 관찰 기록과 함께 가설을 세우고 조정하도록 안내한다.
- 결과 확인 → 관찰 → 수업 조정 → NUVIA 과제 → 변화 확인의 흐름을 보여준다.

### 5.7 학급 두뇌 데이터 대시보드

- 개인 식별 정보 노출을 최소화하고 학급 수준의 경향을 우선 보여준다.
- 교사가 다음 결정을 내릴 수 있도록 설계한다.
  - 어느 설명 방식이 필요한 학생이 많은가
  - 시각자료·단계화·반복·주의 환기 중 무엇을 강화할 것인가
  - 모둠 구성에서 어떤 강점을 조합할 것인가
  - 보충 설명이나 추가 관찰이 필요한 영역은 무엇인가
- 점수 순위나 학생 서열화 화면은 만들지 않는다.
- 실제 학생 데이터가 없으면 명확히 표시된 가상 데이터만 사용한다.

### 5.8 NUVIA 인지훈련

- NUVIA는 정규 수업을 대체하거나 수업 중 일괄 적용하는 프로그램이 아니라, 검사 결과와 연결해 가정에서 짧게 수행하는 개인별 훈련 과제로 설계한다.
- 권장 흐름: 교사 또는 상담자 배정 → 가정에서 짧은 훈련 → 수행 기록 확인 → 필요 시 난이도·빈도 조정.
- 교사는 치료자 역할이 아니라 학습 지원의 조정자 역할을 맡는다.
- 과도한 효과를 약속하지 말고, 기대 효과는 제공된 연구·제품 근거 범위 안에서 표현한다.
- 화면에는 권장 빈도, 예상 소요 시간, 보호자 안내, 지속이 어려울 때의 조정 방법, 재점검 시점을 포함한다.

## 6. 다국어 설계

- UI 선택지는 **한국어 + 외국어 12개(캄보디아어/크메르어 포함), 총 13개 언어**로 구성한다.
- 기존 11개 외국어를 유지하고 캄보디아어를 추가한다. 정확한 언어 목록과 언어 코드는 기존 결과지 및 통합기획서를 기준으로 확정한다.
- 한국어를 기준 원문으로 먼저 완성한다.
- 번역문을 임의로 생성해 ‘검수 완료’로 표시하지 않는다.
- 각 번역의 상태를 `초안 / 전문가 검수 중 / 승인`으로 관리할 수 있게 한다.
- 언어 전환 시 현재 보고 있던 페이지와 맥락이 유지되어야 한다.
- 긴 문장, 줄바꿈, 모바일 폭, 폰트 미지원 가능성을 고려한다.
- RTL 언어가 포함된 경우 방향성과 정렬을 별도로 검증한다.

## 7. 맺음말 — 문구 그대로 사용

가이드의 마지막 장 또는 푸터 직전의 독립 섹션에 아래 문구를 그대로 사용한다. 배경은 깊은 네이비 또는 부드러운 크림색을 사용하고, 원과 연결선으로 ‘다음 성장의 장면’을 표현한다.

> # 이해가 달라지면, 성장의 길도 달라집니다.
>
> 검사 결과는 학생을 판단하는 결론이 아니라, 더 잘 이해하고 지원하기 위한 출발점입니다.
>
> 점수 너머에 있는 학생의 인지 강점과 가능성을 발견하고, 필요한 도움을 수업·상담·자기관리와 인지훈련으로 연결할 때 학생은 자신에게 맞는 방식으로 성장할 수 있습니다.
>
> 모든 학생이 같은 방식으로 배우지는 않지만, 모든 학생에게는 성장할 수 있는 자신만의 길이 있습니다. 이 가이드가 교사와 학생이 그 길을 함께 발견하고, 다음 성장의 장면을 설계하는 지도가 되기를 바랍니다.
>
> **발견되지 않은 가능성이 없도록, 발견한 가능성이 성장으로 이어지도록.**

## 8. 기술·접근성 기준

- 기존 저장소의 기술 스택과 배포 방식을 먼저 확인하고 그 구조를 따른다.
- 정적 GitHub Pages에서 오류 없이 동작해야 한다.
- 모바일 360px, 태블릿, 데스크톱을 모두 지원한다.
- 키보드 탐색, 명확한 포커스, 충분한 색 대비, 대체 텍스트, 의미 있는 HTML 구조를 적용한다.
- 인쇄 및 PDF 저장 시 핵심 내용이 잘리지 않도록 print CSS를 제공한다.
- 모든 버튼, 탭, 필터, 앵커 링크, 언어 전환을 검증한다.
- 개인정보·실제 학생 데이터·검사 원문 문항·점수 산출 알고리즘·비공개 규준표는 포함하지 않는다.

## 9. 제작 순서

1. 저장소와 통합기획서, 브로셔, 로고, B안 이미지를 분석한다.
2. 구현 구조와 콘텐츠 데이터 구조를 간단히 보고한다.
3. B안 디자인으로 한국어 홈, 대상별 경로, 결과 읽기, 81특성 대표 상세, 교사 활용, 대시보드, NUVIA, 맺음말까지 연결되는 한국어 MVP를 구현한다.
4. PC·모바일 화면 캡처와 변경 파일 목록을 제시하고 1차 검토를 요청한다.
5. 승인 후 81가지 전체 데이터와 나머지 콘텐츠를 확장한다.
6. 한국어 기준본 승인 후 12개 외국어 번역 구조와 검수 흐름을 적용한다.
7. 반응형·접근성·인쇄·링크·다국어 QA를 완료한 뒤 GitHub Pages 배포 준비를 마친다.

## 10. 1차 결과물

첫 작업에서는 설명만 하지 말고 실제 실행 가능한 화면을 구현한다. 다음을 함께 제출한다.

- 구현된 파일 목록
- 실행 또는 미리보기 방법
- 데스크톱 및 모바일 캡처
- 적용한 브랜드 컬러·타이포그래피·컴포넌트 규칙
- 현재 실제 콘텐츠와 자리표시자 콘텐츠의 구분
- 추가 확인이 필요한 근거 문장 목록
- 다음 단계에서 확장할 항목

추측으로 통계, 효과, 전문가 이력, 최초성, 공신력 표현을 만들어내지 말고, 근거가 없는 항목은 `[근거 확인 필요]`로 표시한다.
