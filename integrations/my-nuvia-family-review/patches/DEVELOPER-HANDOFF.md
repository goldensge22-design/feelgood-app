## 적용 순서와 재검사
1. 원본 운영 소스·계약·담당 관계·정책을 확보하고 승인된 별도 개발 브랜치를 만든다.
   아래 패치는 이 검토본의 시작 커밋에만 적용한다. 운영 FeelGood에는 바로 git apply 하지 않는다.
2. 별도의 비운영 저장소에서 시작 커밋 `1db2358d5858d5ee67456a86936a792fe435e432` 체크아웃 후 새 브랜치를 만든다.
   `git apply --check MY-NUVIA-review-only-1db2358-to-eac632a.patch` 후 `git apply MY-NUVIA-review-only-1db2358-to-eac632a.patch`.
   기존 운영 저장소의 다른 파일/번역/기록을 덮어쓰거나 강제 초기화하지 않는다.
   소스 ZIP은 최종 스냅샷 대안이다. 패치와 ZIP을 중복 적용하지 않는다.
3. `pnpm install --frozen-lockfile`, `pnpm run typecheck`,
   `PORT=24836 BASE_PATH=/ pnpm --filter @workspace/my-nuvia run build`,
   `pnpm --filter @workspace/api-server run build`로 확인한다.
   이 인계에서는 새 설치/빌드를 수행하지 않았고 기존 성공 로그를 제공한다.
4. 승인된 빈 가상 전용 PostgreSQL과 외부 비밀 설정을 준비한다. .env.example을
   서비스가 자동 로드한다고 가정하지 말고 필요한 런타임 환경으로 주입한다.
   스키마는 lib/db의 기존 Drizzle 정의/명령을 검토한 뒤 이 새 DB에만 적용한다.
   운영 DATABASE_URL, 기존 DB 교체, push-force, DB/세션 덤프 반입은 금지한다.
5. Replit에서는 기존 관리 워크플로와 artifact.toml 라우팅을 사용한다.
   외부 환경은 프론트/API 동일 출처 개발 프록시 및 라우팅을 별도로 구성해야 한다.
   API PORT=8080, 웹 PORT=24836/BASE_PATH=/를 각각 사용하고 새로 배포하지 않는다.
6. 실제 인증·관계·프로그램 어댑터를 검토본과 비교해 필요한 기능만 이식한다.
   원본/공유/비공개 계약, 원어민 미검수 상태, 미연결 AI 안내를 보존한다.
7. 140파일 지문은 SOURCE-FINGERPRINT.json에 기록된 **순서대로 경로 문자열 다음 파일 바이트**
   를 SHA-256에 공급해 검증한다. 개별 파일/ZIP 해시는 UTF-8 MANIFEST/체크섬을 참고한다.
   향후 수정하면 이 지문과 달라지므로 새로운 기준을 고정하고 영향 범위를 재검사한다.
8. 서버 권한/API 회귀와 새 고유 QA_RUN을 사용하는 15언어×3뷰포트×3역할의 실제 클릭,
   입력/시간/대상/언어/복귀 보존·503/409·중복·두 세션·원본 변경·인쇄/접근성 회귀를 실행한다.
   `scripts/src/nuvia-qa-static.mjs`, `nuvia-api-check.mjs`, `nuvia-sharing-check.mjs`,
   `nuvia-browser-recovery.mjs`, `nuvia-qa-matrix.mjs`, `nuvia-qa-report.mjs`와
   docs/MY-NUVIA-FULL-QA.md의 정확한 명령/필수 도구(Chromium, pdftotext)를 참고한다.
   현재 QA 스크립트는 Replit 개발 도메인과 제공된 Chromium 경로를 전제로 하므로 외부 환경은 먼저 점검한다.
9. 변경 후 source fingerprint·실행 시간·실제 통과/미실행·원본 증거를 새로 남긴다.
   사람/실기기/운영 검사 미완료를 브라우저 통과로 대체하지 않는다.
10. 개발자가 승인된 GitHub 대상 저장소에서 수동 등록한다. 이 인계 작업은 remote 추가,
    OAuth/권한 변경, commit/push/PR 생성 또는 운영 배포를 하지 않았다.
    패치·경량 증빙은 등록용이고 큰 원본 ZIP은 별도 첨부/승인된 공유 방법으로 전달한다.

## 파일 구성과 개인정보 제외
- source ZIP: 실행/빌드/검사 소스, 고정 의존성·설정, 기존 인계 문서, 최종 QA 요약.
- evidence-lite ZIP: 최종 집계/원본 JSON/로그, 45조합 대표 화면·15언어 대표 출력·RTL 등,
  전체 최종 증거 목록/개별 SHA-256. 원본 전체의 대체물이 아니다.
- evidence-full-part01~05 ZIP: 각각 ko/en/ja, zh-CN/zh-TW/mn, th/vi/ar,
  ru/km/es, fr/it/az의 최종 done-1~5 원본 화면/PDF/결과 전체.
  모두 같은 MY-NUVIA-EVIDENCE 루트에 풀면 전체 최종 증거를 합칠 수 있다.
- 원본 전체는 **최종 done-1~5와 명시한 회귀/기준/로그**를 뜻한다.
  중단된 파일럿/과거 부분 실행/인쇄 수정 전 전체 이미지를 최종 원본에 섞지 않았다.
  수정 전 실패 집계만 역사 자료로 명시해 보존했다. 기존 앱 데이터 저장본은 포함하지 않는다.
- 각 ZIP의 MANIFEST는 자기 자신을 제외한 수록 파일의 길이/해시를 담는다.
  ZIP 전체 SHA-256이 MANIFEST까지 포함하므로 자기 참조 해시를 만들지 않는다.
- 실제 환경파일/자격증명/세션 쿠키·토큰/DB 덤프/사용자 저장 기록/의존성 설치물/
  Git 내부/개인 메모/첨부 학생 자료는 제외했다.
  증거 이미지의 활동 문구는 자동화가 생성한 가상 검토 자료이며 실제 학생 기록이 아니다.
- 보안 검증은 허용 목록·비밀 패턴·JSON 민감 필드·PDF 텍스트 검사다.
  사람의 보안 감사/스크린샷 OCR 전수 검사나 운영 보안 인증이라고 부르지 않는다.
- 상세 제외 및 검증 결과: EXPORT-VERIFICATION.json. ZIP별 SHA-256: SHA256SUMS.txt.
