1. 제품 목적과 승계 규칙
교사가 결과지 → 플래너 연습 → 기업·직무LAB/진로탐색LAB → 개인 직무 활동카드 → 실제 수행과 기록 → AI자소서 → 면담·수정본 완성 흐름을 운영하는 별도 교사용 앱이다.
한서대 캠프는 학과 혼합·개인 미션 사례 하나이다. 대학·학과·기관을 고정하지 않는다.
v1.2 대상별 자료·개인 인쇄·81유형 지원·언어 규칙과 v1.4 하루 특강/장기 과정 구분을 승계한다.
중고생용 / 대학생용 탭, 중고생 안에서 중학생 / 고등학생 구분. 읽는 자료·수행 과제·도움 수준·제출 결과물을 모두 바꾼다.
하루 3/4/5시간은 개인 미션 중심으로 필수 프로그램을 전부 거친다. 공동 과제·직무 분반 합동 프로젝트는 1개월/2개월/사용자 설정 과정의 선택 옵션이다.
좌석 분단, 원래 소속반, 직무 분반, 합동 조는 별개다. TOP5 원순위 보존, 오늘 탐색할 직무는 학생이 선택한다. TOP5 밖 관심도 선택 이유와 함께 허용한다.
81유형은 과제 접근 방법·도움의 조절에만 활용한다. 유형으로 직무·조장·성취 수준을 확정하지 않는다.
기존 18개 기본 수업과 36개 대상별 활동지 설계 수는 유지한다. 이번 시간표 변형·학생별 생성본·면담 부속지는 새 기본 수업 수로 중복 집계하지 않는다. 실제 구현 수는 별도 목록에서 검증한다.
기존 15개 언어와 작성 상태 보존을 유지한다. 학생 원문은 언어 변경만으로 번역하거나 덮어쓰지 않는다.

2. 확인한 기존 프로그램의 범위와 상태
GitHub feelgood-app 기본 브랜치의 enterprise-demo/enterprise-dashboard 앱 소스, 가상 데이터, 데이터 어댑터, 한국어 메시지를 확인했다. 9개 실제 메뉴의 표시·계산 경로를 정적으로 검토했다. 복사본과 파일별 SHA는 함께 저장했다.
기업대시보드는 기업 HR 분석 화면이다. 학생의 기업 검색·출처 조사 기능은 별도 기업·직무 탐색LAB에서 담당한다. 두 프로그램을 하나의 검색 서비스처럼 설명하지 않는다.
현재 공개 기업대시보드는 기업·지원자·직원·점수·성과가 모두 가상인 데모다. 운영 서버 데이터와 접근권한은 검증되지 않았다.
개인 상세에는 PASS 4점수·결과지 식별자·직무 TOP5가 있다. 81유형 코드를 반환하는 경로는 이 데이터 모델에서 확인되지 않았다. 유형은 결과지 엔진의 확정 출력을 별도로 연결해야 한다.
이력서 업로드는 파일명과 시각을 브라우저에 저장한다. 업로드한 이력서 본문 분석이나 실제 직무 매칭 계산으로 볼 수 없다. 화면의 매칭은 기존 예시 데이터다.
개인 면접 질문은 계획·우선순위, 협업·갈등조정, 불확실성에서 실행의 공통 3개다. 학생별 자소서 기반 질문 생성 기능은 추가 개발 대상이다.
업무역량 모델의 작성/검토/확정은 화면과 브라우저 저장 흐름이며 서버 검토 승인 증거가 아니다.
데이터 어댑터는 일부 운영 데이터 누락 시 가상 역량 모델/가중치를 보충한다. 수업 연결 시 해당 보충값을 실제 기업 기준으로 사용하지 않는다.
11월 4일 classroom-flow v3 연동 인계 패키지는 운영 미배포 상태이다. 탐색→선택 활동→플래너→선택 경험 공유→AI글쓰기 맥락의 흐름을 재사용하되 운영 인증·권한·공통 저장소·AI 연결을 별도 검증한다.

3. 기업대시보드 9개 메뉴를 수업에 옮기는 방법
경영 요약: 분석 인원·PASS 평균·역할 분포·검토 흐름 → 교사용 수업 진행 현황과 누락 단계 안내의 참고 구조. 기업 채용 지표를 학생 성적에 복사하지 않는다.
기업 인재상: 역할별 패턴, PASS와 직무·가치·작업표본 평가의 결합 → 기업이 요구하는 행동을 읽는 자료로 변환. 데모의 가중합·정합도·우선면접 점수는 교육 추천에 사용하지 않는다.
채용 인재 분석: 명부 연결·직무·검토 상태 → 수강 명부 연결과 학생별 진행 관리의 참고 구조. 채용 우선/보류 라벨을 학생에게 부여하지 않는다.
사내 기준 비교: 재직자 성과·역할 근거·집단 비교 → 장기 과정에서 직무의 증거를 이해하는 익명 교육 사례로만 선택 활용. 실제 직원 원자료는 연결하지 않는다.
개인 상세 분석: PASS·결과지·TOP5·근거·확인 질문 → 학생 요약과 탐색 출발점, 면담 질문의 주요 참고. 학생 결과지 원본을 정본으로 삼는다.
역량개발: 30/60/90일 계획·업무 방식·우선 과제 → 하루의 다음 행동, 1개월/2개월의 주차별 실천 계획으로 기간을 다시 설계한다.
조직·팀 분석: 부서·인재 풀·직무 배치 → 장기 수업의 학생 선택 직무 분포, 조별 관심·과제 구성을 확인하는 참고 구조. 기업 승계/리더 적합도로 조를 편성하지 않는다.
실행계획: 담당자·기한·상태·확인 단계 → 활동 수행, 교사 피드백, 면담 예약, 수정본 제출 관리에 적용한다.
업무역량 모델: 역량명·범위·목표수준·가중치·확인 방법·행동 기준 → 활동카드 목표, 수행 과제, 산출물, 면담 질문으로 연결하는 핵심 자료이다. 학생용 난이도는 교육단계와 시간에 맞춰 별도로 정한다.

4. 연결할 정보와 정보의 출처
학생 요약은 PASS 4개 점수와 유형명/코드를 간단히 표시한다. TOP5는 별도 영역에서 원래 순위를 그대로 보여 준다. 점수에 추가 종합점수·합격률·학생 등급을 만들지 않는다.
표시 뒤에는 검사 식별자·시행일·결과지 버전·점수 단위·출처·동기화 상태를 보관하고 필요할 때 펼쳐 본다.
현재 로컬 결과지 계약은 P/A/S/Q 0~100 정답률이며 유형 계산은 결과지 엔진 책임이다. 이를 기업 데모의 0~100 정규화 예시 점수와 동일 척도로 취급하지 않는다.
기업 대시보드 planning/attention/simultaneous/sequential과 결과지 P/A/S/Q의 의미 대응은 어댑터에서 명시하고 검사 버전에 맞게 확인한다. 수업설계LAB이 H/M/L 경계와 81유형을 독자 재계산하지 않는다.
원본 결과가 없으면 관심 기반 탐색으로 진행하되 점수와 유형을 추정하지 않는다. 수동 입력은 원본 대조 여부를 표시한다.
기업/직무 자료는 기업·직무 식별, 공고 또는 자료 제목, 업무, 필요 지식·기술·태도, 요구 행동, 출처 URL, 확인일, 자료 버전, 출처 구분을 가진다.
출처 구분: 기업 공식 공개자료 / 기업이 교육용 공유를 승인한 모델 / 교사 제작 수업 예시 / 학생 조사 / 가상 데모. 교사가 확인했다는 사실만으로 공식 기업 자료로 바뀌지 않는다.
같은 직무명이면 자동으로 같은 직무로 합치지 않는다. 직군·직무 사전의 대응과 근거를 확인한다. 매핑 불확실 시 교사가 확인할 항목으로 남긴다.
기업 모델 중 교육 공유가 허용된 직무 행동만 읽기 전용으로 받는다. 지원자 평가·직원 성과·개인 인사정보는 가져오지 않는다.
기업별 공개 자료가 없으면 일반 직무 연습 카드로 진행하며 특정 기업 공식 미션이라는 이름을 붙이지 않는다.

5. 수업 전 준비와 수업 중 확정의 분리
교사가 수업 전에 만드는 것: 대상·시간·문항·산출물 목표, 읽을 자료 후보, 활동 틀, 허용 도구, 난이도·시간 범위, 도움 자료, 출력 서식, 상담 가능 인원.
학생이 수업 중 만드는 것: 오늘의 선택 직무/기업, 조사 질문·출처·선택 이유, 활동 후보 선택, 자신의 목표·첫 행동·완료 기준, 플래너 등록, 실제 기록, 자기 글.
모든 학생의 최종 직무 카드를 수업 전에 확정하지 않는다. 결과지와 TOP5를 불러왔다고 5개 활동을 자동 등록하지 않는다.
교사는 예시/빈 활동지를 미리 인쇄하고, 현장에서는 선택된 학생별 카드를 추가 출력할 수 있다.
강사용 수업안은 단계마다 어느 프로그램의 어떤 화면을 열고, 무엇을 안내하며, 무엇을 제출받고, 완료·도움 요청을 어떻게 확인하는지 보여 준다. 아직 없는 버튼은 현재 사용법으로 단정하지 않고 제작 기능으로 구분한다.

6. 즉석 활동카드 추천·확정 규칙
입력: 오늘의 선택 직무, 기업/진로 조사 내용, 요구 행동 1~2개, 교육단계, 남은 시간, 사용할 도구, 학생이 선택한 지원 방법.
선행 조건: 탐색 질문, 업무/학습 내용, 선택 이유, 최소 하나의 출처 또는 명시된 교사 수업 자료.
추천 순서: 대상·시간·자료·도구에 맞지 않는 후보를 먼저 제외 → 선택 직무와 요구 행동이 연결되는 후보 → 가능한 산출물과 완료 기준 → 학생에게 2~3개 후보와 추천 이유 표시.
PASS는 선택 가능한 도움의 제안에 활용한다. 예: 목표를 나누는 계획표, 집중을 돕는 체크리스트, 전체 관계도, 순서 안내. 낮은 점수만으로 쉬운 과제에 고정하거나 직무 후보를 제외하지 않는다. 지원 방법을 학생·교사가 바꿀 수 있다.
각 후보는 “이 업무의 어떤 행동을 연습하는지 / 무엇을 읽는지 / 무엇을 할지 / 제출물 / 예상 시간 / 도움”을 포함한다.
학생이 하나를 선택·수정 → 허용된 템플릿·시간 안이면 수업 규칙 검증 → 예외인 경우 교사 검토 → 학생이 플래너에 담기 실행.
교사는 템플릿과 기본 출력 형식을 미리 확인하며, 개별 내용 변경·범위 초과·출처 부족 카드는 검토 대기열에서 확인한다. 수업 전체가 모든 학생의 수동 승인 대기로 멈추지 않게 한다.
상태: 탐색 중 / 후보 준비 / 학생 선택 / 검토 필요 / 확정 / 플래너 등록 / 수행 중 / 일부 수행 / 수행 완료 / 경험 확인. 교사 화면에 상태와 도움 요청 표시.
수업 중 과제를 바꾸면 이전 카드·기록은 남기고 새 버전/후속 활동으로 연결한다. 이미 수행한 증거를 새 과제로 옮겨 완료 처리하지 않는다.
플래너 등록 재시도는 중복 활동을 만들지 않는다. 연결 실패는 미등록으로 표시하며 임시 저장/다시 시도/종이 기록 방법을 제공한다.

7. 활동지와 활동카드, 인쇄
활동지: 결과 해석·탐색·비교·생각·경험 확인·글쓰기·면담 수정의 작업 공간.
플래너 활동카드: 목표, 실제 할 일, 날짜·시간, 준비물, 요구 행동, 완료 기준, 제출물, 도움, 실행·회고를 관리하는 단위.
둘은 같은 학생·수업·활동과 연결되지만 서로 다른 출력물이다.
개인 1명/선택 학생/전체 반별 출력, 활동지만/카드만/묶음 출력. A4 활동지, A5 카드 2장 배치, 학생 구분과 쪽 나눔, 미리보기, 교사 확인 후 인쇄.
현장 선택 후 학생별 맞춤 내용으로 다시 출력 가능. 수정 전/후 카드에는 버전과 시각을 표시한다.
공용 인쇄 묶음은 학생 코드 기본, PASS 점수·유형·자소서 원문은 기본 제외. 본인용 결과 요약은 별도 선택 출력, 상담자료는 해당 학생/상담자에게만 제공한다.
새 부속 출력물: 면담 준비표, 상담자 질문·피드백표, V1→V2 수정 확인표, 모의면접 질문·회고표. 기존 활동지 가족에 부속하거나 별도 부속지로 집계한다.
인쇄 중 오류·네트워크 장애에는 빈 카드와 활동 코드로 기록하고 이후 학생이 확인하여 입력한다.

8. 같은 활동명의 대상별 차이: 고객 문제 해결 카드 예시
중학생: 쉬운 직업 소개와 교사가 준비한 생활 사례 1개. 사용자가 불편해할 점 하나와 해결 아이디어 하나를 찾는다. 그림·선택지·문장 시작 도움 제공. 그림과 짧은 이유 3문장 제출. 진로탐색LAB 중심.
고등학생: 서비스 사례와 직무 소개, 출처 1~2개. 원인 두 개 비교 후 개선안 선택. 비교표·확인 질문·단계 안내 제공. 개선안 한 쪽과 판단 이유 제출. 진로/학과 탐색과 기업 역할 연결.
대학생: 공식 직무 자료와 공개 서비스 자료. 고객 문제 가설, 대안, 우선순위, 검증 방법을 제안. 스스로 근거를 고르고 가정·한계를 기록. 문제–근거–제안–확인 방법의 한 쪽 보고서 제출.
모두 수업용 모의 미션임을 표시하며, 기업에서 실제 성과를 낸 경험으로 바꾸지 않는다. 산출물 비교 기준도 대상에 맞게 다르게 한다.

9. AI자소서 → 면담 → 최종 수정본
첫째, 경험 선택: 플래너에서 실제 수행한 행동·결과·배운 점 중 본인이 활용할 항목을 선택하고 사실을 확인한다. 수업 전 실제 경험을 추가할 수도 있다. 조사한 역량은 보유 역량과 분리한다.
둘째, V1: 문항·대상 직무·분량을 정하고 초안을 작성한다. AI는 빠진 사실 질문과 구성·표현 제안을 제공한다. 초안 생성 요청이 있으면 선택 사실만 사용해 제안하고 학생이 미리보기 후 반영한다. 기존 원문을 자동 교체하지 않는다.
셋째, 면담 준비: 학생이 “가장 고치고 싶은 점”을 고르고 V1의 상담 공유 범위를 정한다. 상담자는 해당 학생에게 허용된 문항·경험·선택 기업 행동 기준·V1을 한 화면에서 본다.
넷째, 면담: 글에 쓴 행동을 말로 풀어내게 하고 본인 역할, 행동 순서, 근거, 결과, 배운 점, 직무 연결을 묻는다. 면담은 학생이 말하지 않은 성과를 만들어 주는 단계가 아니다.
다섯째, 사실 확인: 상담자가 추가 사실 후보와 해석·표현 제안을 구분해 기록하고 학생이 추가 사실을 확인한다. 미확인 내용은 질문으로 남긴다.
여섯째, V2: 학생이 수정 제안을 선택해 글에 반영한다. V1/V2 차이, 추가한 사실 근거, 남은 질문을 확인하고 최종본 저장·내보내기를 확인한다. 상담자는 학생 최종본을 대신 확정하지 않는다.
완료 상태: 초안 저장 / 면담 예약 / 면담 완료 / 추가 사실 확인 / 수정 중 / 학생 최종 확인. 상담을 받았다는 것과 자소서가 완성됐다는 것을 별개로 표시한다.
최종 기준: 문항 응답, 본인 행동, 실제 근거, 직무와 연결, 사실 확인, 학생 검토, 버전 저장. “합격 보장”이나 자동 점수 통과를 완성 기준으로 삼지 않는다.
중학생은 나의 활동 소개, 고등학생은 진로·성장 이야기, 대학생은 직무 문항 자소서로 글의 목적과 분량을 구분한다.

10. 면담과 모의면접의 구분
자소서 면담: 글의 사실과 구체성을 보완하기 위한 상담이다. 질문→사실 확인→글 수정이 결과다.
모의면접: V2와 직무 기준을 근거로 말로 설명하고 꼬리질문에 답하는 연습이다. 답변 기록→피드백→재답변/글 재확인이 결과다.
질문 묶음 제안: 직무·기업 탐색 이유 / 실제 행동 / 결과·근거 / 어려움과 수정 / 상황 대처. 각 질문에는 어떤 학생 문장·경험·직무 행동을 확인하려는지 연결한다.
예: “개선안을 제시했다고 썼는데 직접 확인한 자료는 무엇인가요?”, “세 대안 중 하나를 고른 기준은 무엇인가요?”, “수업 연습을 실제 업무에 적용한다면 무엇을 더 검증해야 하나요?”
경험 질문과 가정 상황 질문을 분리한다. 가정 답변을 과거 실제 경험으로 자소서에 옮기지 않는다.
피드백: 질문 이해, 본인 행동의 구체성, 근거, 논리, 직무 연결, 다음 개선 행동. 얼굴·감정·음성으로 성격이나 채용 가능성을 추론하지 않는다.
텍스트/대면이 기본이며 녹음·영상은 선택 및 별도 공유 범위 확인 후 제공한다.
AI자소서 V2가 기준이며 면접에서 추가한 사실은 학생 확인 후 V3로 저장한다. 면접 답변과 원문이 달라진 이유를 기록한다.
PASS 점수나 81유형은 자소서 문장·면접 역량의 자동 증거가 아니다. AI 글쓰기·면접 요청에 원점수를 기본 전달하지 않는다.

11. 시간표와 상담 수용량
하루 기본형은 v1.4의 180/240/300분 시간표를 유지한다. 검사 사전 완료가 전제다. 현장 검사 시간은 실제 소요 시간을 추가하며 임의로 필수 활동에서 빼지 않는다.
3시간 기본형의 AI자소서 40분 예: V1 20분 / 자기·짝 점검 8분 / 수정·저장 12분. 이 과정은 전원 1:1 상담으로 표시하지 않는다.
5시간 면담형 별도 프리셋 제안:
안내 10 / 결과 해석 25 / 플래너 기본 연습 15 / LAB 탐색 35 / 직무 카드 선택·등록 15 / 수행·기록 35 / 경험 확인 10 / V1 35 / 면담 순환 60 / V2 수정·확인 25 / 다음 실행·마감 15 / 휴식 합계 20 = 300분.
휴식 10분은 LAB 탐색 뒤, 10분은 경험 확인 뒤를 기본으로 하며 이동·출력은 해당 단계에 포함한다.
면담 슬롯 기본 예시는 대화 8분+기록/교대 2분이다. 이는 짧은 집중 피드백이며 심층 상담을 뜻하지 않는다.
수용량 = 상담자별로 사용 가능한 면담 블록에서 확보한 온전한 슬롯 수의 합. 동일 조건이면 상담자 수 × 내림(면담 블록 분 / 슬롯 분).
30명, 60분, 10분 슬롯이면 상담자 5명 필요. 1명은 6명만 가능. 전체 진행·질문을 맡는 강사는 동시에 전담 상담자로 중복 계산하지 않는다.
예약은 학생의 V1 완료 후, 최종 수정 시간 전에 배치한다. 결석·이동·휴식·상담자 부재·중복 예약을 검사한다. 운영 인원과 상담 시간은 교사 입력 후 확정한다.
수용량 부족 시 상담자 추가 / 분반 시차 / 상담 블록 연장 / 별도 후속 면담 중 운영안을 고른다. 선택 상담만 제공하면서 전원 면담 완료라 표시하지 않는다.
상담 대기 학생은 질문 준비·근거 보완·동의한 범위의 짝 점검을 수행한다. 면담이 끝난 학생은 수정한다.
5시간에 모의면접까지 전원 심화 진행하려면 별도 시간·상담 인원을 계산한다. 기본은 짧은 선택 연습 또는 장기 과정으로 배치한다.

12. 장기 과정·분반
1개월 기본 4회×90분: 1회 해석·플래너 / 2회 탐색·미션 / 3회 수행·공유 또는 선택 공동 과제 / 4회 글쓰기·면담·수정.
상담 수용량이 부족하면 3회 말에 준비된 학생의 V1 면담을 배치하거나 추가 면담 회차를 잡는다. 4회에 전원을 몰아넣지 않는다.
2개월 기본 8회×90분: 1해석·플래너 / 2탐색 / 3개인 미션 / 4~6개인 확장 또는 선택 분반 공동·합동 / 7V1·면담 / 8V2·모의면접·마감. 실제 시간 검증 후 일부 상담을 분산한다.
달력 기간과 시수는 분리하여 입력한다. 학생 선택 직무·미션·시간·공간에 따라 분반 초안을 만들고 교사가 확정한다.
같은 직무 다른 기업 비교, 서로 다른 직무 공동 프로젝트, 탐색 박람회/교차 피드백을 장기 옵션으로 제공한다.
공동 산출물과 별개로 각 학생의 역할·실제 행동·기록·자소서는 개별로 저장한다.

13. 교사용 화면 구성
가. 수업 만들기: 대상 탭, 기간·시수, 필수 흐름, 학습 목표, 개인/장기 공동 방식.
나. 학생과 결과 요약: 명부, PASS4+유형, TOP5, 연결 여부, 오늘 선택 직무. 점수로 학생을 서열화하지 않는다.
다. 기업·직무 수업자료: 공유 가능한 요구 행동, 자료 출처·버전, 교사 수업용 변환과 대상별 도움.
라. 시간표·강사용 진행안: 프로그램·화면·교사 안내·학생 행동·결과물·완료 기준·문제 시 대응.
마. 현장 수업 운영: 탐색→카드→수행→경험→글→면담→수정 상태, 도움 요청, 카드 예외 검토.
바. 개인 활동지·카드 출력: 미리 배포 / 현장 추가 / 개별·선택·전체 인쇄.
사. 자소서·면담: 공유된 V1, 질문, 예약·대기열, 추가 사실 확인, V2 차이·학생 최종 확인.
아. 모의면접·후속 계획: 개인 질문과 피드백, 재답변, 후속 플래너 활동.
자. 규칙·연동 상태: 규칙 버전, 변경 이유, 실제 연결/미연결/예시 자료 상태. 기술 세부사항은 운영자 설정에 둔다.

14. 개발 연결과 권한
기존 classroom-flow v3의 탐색 기록·활동 선택·플래너·경험 공유·AI맥락 흐름을 재사용하는 방향이다. 새 앱 안에 같은 경험을 중복 저장하는 독립 플래너를 만들지 않는다.
기존 교사 현황은 진행 건수만 보며 검사·회고·자소서 본문을 제공하지 않는다. 이번 요청의 결과 요약과 상담 열람은 새 기능이다.
담당 수업의 결과 요약 열람과 학생이 상담용으로 선택한 글·경험 열람을 분리한다. 일반 교사에게 전역 기업 운영자/채용 담당자 권한을 주지 않는다.
학생·교사·상담자·기업 모델 공유자 권한을 분리하고 서버에서 검사한다. 공개 데모에는 가상 학생만 사용한다.
같은 로그인과 실제 데이터 공유는 다른 조건이다. 실운영 계정 식별·수강 명부·공통 저장소 또는 중앙 연결 서비스를 확인해야 한다.
이번 기획으로 추가할 연결: 읽기 전용 결과 요약, 교육 공유용 직무 행동, 수업 내 활동 후보·확정, 개인 출력, 면담 예약·공유·확인, 글 버전 차이, 모의면접 기록.
결과지·기업 자료·활동·경험·글·면담은 원본 식별자와 당시 버전으로 연결한다. 자료 수정/철회는 새 AI 사용 전 재확인하며 기존 제출본의 보존 상태를 표시한다.
AI 서비스 미연결이면 수동 작성·규칙 기반 질문을 사용할 수 있으나 AI가 작성했다고 표시하지 않는다. 기업 모델 미연결이면 교사 확인 교육 자료로 수업 진행 가능하다.
화면과 운영 흐름은 실제로 동작하게 구현하되 인증되지 않은 실제 학생 데이터 입력을 권장하지 않는다. 실자료 연동 완료를 가상 시연으로 대신 증명하지 않는다.

15. 제작 순서와 검수
1차: 대상 탭·기간 설정·필수 시간표·학생 요약·자료 출처와 연결 상태.
2차: 학생 탐색 후 활동 후보→선택·수정→등록→실행·기록, 교사 대기열, 개인 인쇄.
3차: 경험 확인→V1→면담 예약·질문·사실 확인→V2·내보내기.
4차: 장기 분반·합동 옵션, 모의면접, 운영 인증·외부 서비스 연결 검증.
확인할 시나리오:
- 동일 활동명의 중학생·고등학생·대학생 자료·과제·도움·결과물이 실제로 다르다.
- TOP5 수입만으로 카드가 생성/등록되지 않으며 학생 선택을 거친다.
- 결과지 원순위·척도·유형이 보존되고 누락을 임의 보완하지 않는다.
