# 개발자 연결 명세와 추가 수용 시험

2026-11-05. 실제 서비스 연결은 개발자가 수행한다. 아래 새 필드와 연결은 제안 계약이며 현재 운영 API로 존재한다고 가정하지 않는다.

## 1. 원본과 권한

- 학교 대시보드의 `schoolId/classId/departmentId/organizationId/assessmentCycleId/assessmentType/lang`을 수업 생성의 필터로 매핑한다. 기관 이름을 식별자로 사용하지 않는다.
- 교사에게 허용된 명부를 서버가 반환한다. `courseId`, `enrollmentId`, 검증된 개인 ID의 관계를 별도 저장한다. 이름·이메일 일치만으로 프로그램 계정을 병합하지 않는다.
- 기업별 과정은 `companyId` 등 안정 식별자를 개발자가 확정해야 한다. 현재 대시보드 객체에 있다고 추정하지 않는다. 학교와 기업 권한 범위는 분리한다.
- v3 공통 흐름의 인증 issuer+subject/검증된 연결표, revision 충돌, idempotency를 유지한다. 로컬 역할 전환·URL의 교사 ID는 권한 증거가 아니다.

## 2. 결과 요약의 무손실 계약(신규 제안)

`reportReference`: 원본 reportId/resultId/testId, version, testedAt, assessmentKind, scoreScale, population, source, 네 축 `{key,value,unit}`, 원본 typeCode/typeLabel, `topJobSlots[{rank,jobId?,label?,reason?,status}]`.

원래 2순위·5순위만 있으면 슬롯 1/3/4는 missing으로 유지한다. 원본 배열 순서/rank가 충돌하면 오류로 반환하고 재정렬하지 않는다. 없는 직무 ID/사유/유형을 만들어 채우지 않는다. K-PASS 표준점수에서 D-CAS81을 계산하지 않는다. 정확한 원본 키는 결과지 팀과 매핑 확정 후 사용한다.

현재 v3의 `feelgood-result-reference-v2`는 점수·원래 rank·빈 슬롯을 전달하지 않는다. 하위 호환 버전/별도 교사용 참조 계약을 합의해야 한다. 현 v2를 임의 확장하고 기존 소비자가 처리한다고 가정하지 않는다.

보고서 변경 시 최신 요약은 갱신하되 과거 활동의 근거 보고서 버전은 유지한다. 새 근거로 재확인한 시각과 당시 버전을 별도로 기록한다. 존재하지 않는 과거 스냅샷을 현재 값으로 소급 생성하지 않는다.

## 3. 프로그램별 연결

| 연결 | 재사용 | 개발자 추가 작업 |
|---|---|---|
| 대시보드→교사 과정 | 학교 adapter 필터/명부 식별자 | 담당 권한, 수강 명부, 합동 과정 범위, 검사 척도 확인 |
| 교사→LAB | v3 워크북/출처/비교/선택 이유 | course/enrollment 연계, 담당 수업 권한, 허용된 진입 링크 |
| LAB→플래너 | v3 선택 등록·멱등성·계획/회고 | 기존 플래너 저장·캘린더/작업대 연결. 두 플래너에 중복 생성 금지 |
| 플래너→AI자소서 | 선택 경험·사실 확인·활용 동의, 조사 맥락 별도 동의 | 기존 AI bridge 및 문항/언어 연계, 원본 수정/철회 확인 |
| 교사 진행 현황 | v3 진행 건수·피드백 API | 본문은 별도 제출/열람 권한. 미제출·열람 거부를 미수행으로 단정 금지 |
| 글쓰기→면담→V2 | 교사 앱 로컬 V1/V2·사실 확인 흐름 | 서버 제출 버전, 교사 피드백·학생 확인, 동시 수정 및 변경 이력 |
| My NUVIA | v3 대상별 허브 장착 모듈 | 실제 프로필·서비스 이용권·라우팅. 대상 선택이 권한을 늘리지 않도록 함 |
| 기업 자료→학생 수업 | 공개 허용 자료의 별도 카탈로그 | 기업 평가/직원 데이터 제외, 모델 버전·출처·공개 범위 확인 |

`plan → active → paused/partial/completed` 상태와 실제 `action/result/learning/change/artifact`를 분리한다. 완료 클릭·시간 만료·교사 관찰만으로 학생이 하지 않은 행동을 채우지 않는다. 파일 업로드는 v3에 없으며 결과물 위치 텍스트 기록과 구분한다.

## 4. 추가 구현 우선순위

P0: 검사종류/척도 보존, TOP5 무손실 매핑, 명부·담당 권한, 선택 등록/중복 방지, 현재 앱의 자료/카드가 실제 외부 저장과 구분되도록 연결 상태 표시.

P1: 세 수업 목적·기간 조합, 대상별 네 요소 콘텐츠, 승인 자료만 후보 제공, 구형 자동 편성 엔진을 장기 과정 Studio에 연결, 학생별 출력 묶음·제출 흐름, 면담 인력 계산.

P2: V1/V2 서버 이력, 선택한 본문만 교사에게 제출, 모의면접 기록과 후속 미션, 실제 15언어·모바일·인쇄 통합 검수.

후속: 기업 HR 과정/기업 공유의 만료·철회·업무역량 기준 검토. 현재 학교 수업 출시의 필수 조건으로 묶지 않는다.

## 5. 새 수용 시험(모두 아직 미실행)

1. 학교 표준점수 110과 D-CAS 정답률 73을 각 원래 척도로 표시. 누락 척도는 계산 차단·확인 요청.
2. 2·5순위만 있는 결과의 화면/미션 후보/출력에서 원래 rank와 빈 슬롯 유지. 같은 보고서 ID/버전에 다른 값 입력은 충돌 처리.
3. 결과지 없음/TOP5 밖 선택/직무 미정 모두 개인 미션 진행 가능. 81유형 미확인은 임의 산출하지 않음.
4. 탐색만 저장하면 플래너 카드 0개. 학생 선택 후 1개. 재시도·새로고침·이중 클릭에도 1개.
5. 등록 뒤 원본 탐색 수정은 과거 카드의 근거를 덮어쓰지 않음. 변경된 비교 자료는 재확인.
6. 타이머 종료·부분 완료·공동 결과물이 개인 경험 자동 완성을 만들지 않음.
7. 같은 활동명에 중학생/고등학생/대학생의 읽을 자료·수행 과제·도움·제출물이 실제로 다름.
8. 하루 과정은 분단 공동 결과물을 필수로 만들지 않음. 장기 과정 자동 제안은 정원·중복·누락·고정 배치 검증 후 교사 확정.
9. 소속 반이 다른 교사·기관은 조회/인쇄/수정/직접 링크 접근 불가. 합동 명부는 허가된 학생만 포함.
10. 교사 진행 API는 회고·자소서 본문을 기본으로 노출하지 않음. 선택 제출·철회·재제출을 각각 시험.
11. 조사 맥락 동의 해제 시 AI 입력 facts만 전달. 없는 성과·기업 기준·숫자를 생성하지 않는지 사람 검토 포함.
12. V1 보존, 면담 사실 확인 전 V2 확정 차단, 수정된 경험 재확인, 출처 철회 후 새 AI 활용 차단.
13. 학생별 개별/선택/일괄 출력에서 다른 학생 내용 혼입 0건, 페이지 구분·언어·활동 버전 확인.
14. 180/240/300분 합계(휴식 포함), 당일 검사 별도 시간, 상담 인력 부족 표시 검증.
15. 15개 언어의 UI/자료/카드/오류/인쇄/AI 출력 언어·RTL, 원문 보존·전환 중 입력/타이머 보존. 신규/변경 key만 번역하고 기존 승인 번역 유지.
16. 서버 미연결·네트워크 실패·권한 만료·동시 수정은 성공으로 표시하지 않음. 샘플 데이터로 조용히 대체하지 않음.
17. 기업 직원·지원자 평가가 학생 화면/인쇄/AI 입력에 섞이지 않음. 기업 모델 누락은 실제 기준 없음으로 표시.
18. 같은 플래너 근거를 자소서에 재인용해도 독립 실적 두 건으로 집계하지 않음.

기존 앱 564개 기술 검사, v3 패치 38개 검사, 플래너 검토판의 QA를 합쳐 ‘전체 운영 연동 QA 통과’라고 보고하지 않는다. 각 소스 버전/범위/환경/미실행 항목을 별도 보존한다.
