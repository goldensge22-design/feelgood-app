# 수업설계LAB 연동 데이터와 저장 원칙

이 문서는 개발자가 기존 서버와 합의할 논리적 데이터 계약입니다. 실제 API 주소나 기존 서버 필드명을 확인한 명세가 아닙니다. 기존 필드·경로를 임의로 바꾸지 말고 변환 경계에서 대응시킵니다.

## 원본과 연결 단위

| 정보 | 보존할 내용 | 원본 관리 |
|---|---|---|
| 학생과 반 | 학생 식별자, 기관·반 식별자, 교육단계, 교사 접근 범위 | 기존 계정·학생 시스템 우선 |
| 검사 결과 | 검사 종류·버전·척도, 결과 식별자, 네 영역, 81유형, 항목 제목·번호, 원본 버전 | 결과지 시스템 |
| 진로 선택 | 학과·전공, 관심 직군·직무, 학생의 선택 이유, 공식 자료 출처·확인일 | 해당 탐색 도구와 학생 선택 |
| 수업 | 수업 식별자·버전, 목표, 시간·휴식, 방식, 참여 학생, 사용 콘텐츠 버전 | 교사용 LAB |
| 활동지 | 템플릿·버전, 학생 배부본 식별자, 자료·질문·도움·완료 기준, 학생 답과 수정 이력 | 교사용 LAB의 배부본 |
| 활동카드 | 연결 활동지, 학생, 목표·일정·범위·단계·도움·완료 기준 | 등록 전 LAB, 등록 후 플래너 원본과 대응 |
| 실행과 경험 | 실제 행동·조정·결과물·피드백, 모의/실제 구분, 학생 확인 | 플래너·경험 원본 |
| 글과 내보내기 | 선택 경험·원본 버전, 문장 수정·확인, 공유 범위 | 기존 글 작성 서비스 |

검사 결과의 원점수·표준점수·수준을 구분하고, 순차처리 명칭 차이는 명시적으로 대응시킵니다. 기존 결과지의 IQ 등 계약 필드가 있으면 사용하지 않는다는 이유로 삭제하지 않습니다.

## 활동카드 등록

1. 학생과 교사의 접근 권한 및 대상 플래너 계정을 확인합니다.
2. 등록할 내용과 연결된 활동지·자료를 미리 보여주고 확인합니다.
3. 재시도와 중복 클릭이 같은 활동을 여러 개 만들지 않도록 식별 기준을 합의합니다.
4. 저장 성공 응답과 원본 활동 식별자가 확인된 뒤 등록 완료로 표시합니다.
5. 실패·재시도·연결 해제를 구분하고 원본 기록을 삭제하지 않습니다.
6. 이미 있는 활동과 연결할 경우 관련 학생과 내용·버전을 확인합니다.

미연동 때는 복사·내보내기·수동 등록으로 작동하며 자동 연동인 것처럼 표시하지 않습니다. 개인 활동지가 등록되었다는 이유로 과제 완료·경험 확인을 자동 생성하지 않습니다.

## 기록과 충돌

학생이 확인한 실제 행동만 경험에 반영합니다. 활동지 한 개와 실행 카드 여러 개의 연결을 허용합니다. 입력·실행·결과물·글 버전을 구분합니다. 원본 변경 시 기존 글이나 수업의 스냅샷을 자동 덮어쓰지 않고 변경을 알립니다. 언어 전환과 수업방식 변경으로 학생 기록을 초기화하지 않습니다.

종이 기록은 본인 또는 권한 있는 교사의 확인을 거쳐 입력합니다. 문서 스캔·자동 인식·종이와 온라인의 자동 동기화는 이번 확정 규칙만으로 구현된 것으로 간주하지 않습니다.

## 권한과 출력

교사는 허용된 기관·반·학생만 조회하고 생성·출력합니다. 학생 본인의 다운로드와 교사의 일괄 출력 권한을 구분합니다. 공유 컴퓨터의 임시 출력 파일 처리와 접근 범위도 운영자가 정해야 합니다.

학생 배부본은 학생 코드·자료 제목·버전·연결 표시를 기본으로 하고 이름은 교사가 선택합니다. 점수·유형·약점 명칭은 기본 제외합니다. 학생의 개인 기록을 동의 없이 외부 공유하지 않습니다. 저장소에는 실제 학생 정보·비밀값을 포함하지 않습니다.

## 서버 연동 전 확인할 사항

공통 로그인과 역할, 반·학생의 소유권, 결과지 API와 버전, 플래너 등록·조회·수정 방식, 경험 확인 방식, 자기소개서 원본 관리, 실패·재시도 처리, 보관·삭제·공유 정책을 담당 개발자가 확정해야 합니다. 기존 서버 활용을 우선하며 새 서버를 무조건 추가하지 않습니다.
