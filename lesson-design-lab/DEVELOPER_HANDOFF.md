# 수업설계LAB 개발자 인계 안내

수업설계LAB은 기존 대시보드 보강판을 덮어쓰는 작업이 아니라 별도로 제작하는 범용 교사용 앱입니다. 이 인계 폴더의 확정 규칙 1.2를 구현 기준으로 사용해주세요.

## 현재 인계 범위

확정 규칙과 변경 이력, 기존 교사용 프로그램 분석 수량, 데이터 연결 원칙, 검수 항목을 전달합니다. 앱 전체 소스·의존성 잠금 파일·빌드 결과·실제 브라우저 검수 결과는 이 인계 묶음에 포함되지 않았습니다. Replit 제작 요청이 전달된 상태와 기능 검수 완료는 구분해야 합니다.

제작 프로젝트는 README의 Replit 링크입니다. 최신 소스를 확보한 뒤 저장한 커밋과 제작 기준 버전을 함께 기록해주세요. Replit 편집 링크는 서비스 운영 주소가 아닙니다.

## 먼저 진행할 작업

1. Replit 프로젝트의 현재 소스와 빌드 상태, 기존 Git 연결 여부를 확인합니다. 기존 연결을 임의 교체하거나 다른 프로그램을 덮어쓰지 않습니다.
2. 전체 실행 소스, 의존성 및 잠금 파일, 빌드·실행 설명, 필요한 환경변수 이름만 확보합니다. 비밀값·실제 학생 데이터·인증 링크·로컬 저장 백업은 저장소에 넣지 않습니다.
3. 이 저장소의 별도 작업 브랜치에서 lesson-design-lab/app 아래로 원본 소스를 가져오는 방안을 검토합니다. 경로·빌드·정적 자원 참조를 검수하고 Replit 원본 커밋 또는 내보낸 시각을 남깁니다. 기존 저장소 루트를 Replit 앱으로 대체하지 않습니다.
4. 규칙별 구현 현황을 매핑하고 누락 기능을 채웁니다. 18개 수업안과 36종 활동지는 이름만 있거나 빈 양식이면 미완료로 표시합니다.
5. 기존 서버의 계정·학생·소속반·결과지·플래너·자소서 연결 가능 항목을 확인한 뒤 실제 연동 계약을 확정합니다.
6. 자동검수와 화면·인쇄 검수를 수행하고 증거, 실행일, 테스트 데이터가 가상임을 기록합니다.
7. 공개 배포는 별도 운영 확인 후 진행합니다. 이 문서를 저장하는 행위는 운영 사이트 교체 지시가 아닙니다.

## 반드시 유지할 사용자 결정

- 중고생용·대학생용 두 탭이며 중고생 안에서 중학생·고등학생을 구분합니다.
- 한서대는 일반 제품의 여러 활용 사례 중 하나이며 **개인별 미션**으로 진행합니다.
- 소속반은 명단 관리 단위이고 동일 조·동일 미션을 뜻하지 않습니다.
- 1:1 지도와 여러 학생의 개별 수행을 구분합니다. 조 편성은 조별 단계에서만 작동합니다.
- 개인 활동지와 플래너 활동카드는 각각 생성하며 상호 연결합니다.
- 학생 한 명·선택 학생·반 전체에 대해 활동지만·카드만·학생별 묶음을 출력합니다.
- 81유형은 도움 방식을 조절하며 학과나 직무를 제한하는 분류로 사용하지 않습니다.
- 교육단계별 학습 목표·자료·수행 행동·도움·제출 기준을 실질적으로 다르게 작성합니다.

## 구현 우선순위

| 순서 | 작업 | 완료 확인 |
|---|---|---|
| 1 | 범용 수업 설정과 반·학생 선택 | 기관 예시 없이 수업을 만들 수 있음 |
| 2 | 대상별 콘텐츠와 개인 미션 | 서로 다른 전공 학생에게 서로 다른 과제 제공 |
| 3 | 활동지와 카드 연결 및 출력 | 한 학생·선택 학생·반 전체의 자료가 섞이지 않음 |
| 4 | 81유형 지원과 교사 편집 | 복수 지원·동점·균형·미입력에 대응 |
| 5 | 조별·혼합 수업 | 교사 검토 후 편성, 개인 기록 보존 |
| 6 | 기존 서버·플래너 연동 | 권한·저장 성공·중복 방지·원본 버전 검증 |
| 7 | 다국어와 반응형 및 인쇄 | 실제 콘텐츠와 15개 언어의 검수 상태 확인 |

## 기존 프로토타입에서 주의할 점

분석한 초기 프로그램은 240개 항목과 81유형 표, v9는 400개 항목·80개 활동명·18종 생성 형식을 갖습니다. v9의 6명 데모 학생에 대한 63개 비어 있지 않은 선택은 순서 있는 프로그램 ID 기준 19개 수업 묶음으로 집계됐습니다. 이 수량을 신규 앱의 완료 수량으로 사용하지 않습니다.

초기 표의 동점 우선순위로 하나의 영역만 남기는 방식, 균형 유형의 동일 기본 처리, v9의 20세 이상 초등 연령대 기본값, 인원수 때문에 난이도가 상승하는 선택 방식, 같은 조건에서 첫 프로그램만 반복 선택하는 방식을 새 앱에 이식하지 않습니다.

## 전달 후 상태 갱신

HANDOFF_STATUS.json에는 소스 확보, 커밋, 콘텐츠 검수, 브라우저·인쇄 검수, 외부 연동, 언어별 검수, 배포를 각각 기록해주세요. 완료 근거 없이 상태를 승격하지 않습니다. 상세 판정은 ACCEPTANCE_CHECKLIST.md를 사용합니다.
