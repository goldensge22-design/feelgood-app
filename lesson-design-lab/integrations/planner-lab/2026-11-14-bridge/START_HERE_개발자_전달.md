# 플래너 → 기업 LAB 추천 카드 연결 패치 2026-11-14.1

학생이 플래너에서 결과지 TOP5/검증된 관심 직무를 선택하면 기업 LAB에 요청하고, 받은 추천 카드를 보여 줍니다. 후보 중 하나를 선택·저장하면 같은 플래너 화면에서 판단·실행 요약·느낌·메모를 작성하고 서버에 수정 이력을 남깁니다.

**이번 패치는 로컬 구현·합성 QA 완료본입니다. nuvia.feel-good.io 배포 완료본이 아닙니다.** 운영 인증·원본 결과 DB·LAB SSO·공유 DB를 연결하는 작업은 아래 개발자 항목에 남아 있습니다. 기존 타이머·일기·라이브러리·15개 언어 패치를 대체하지 않는 추가 패치입니다.

## 전달 파일

- `payload/artifacts/nuvia-ui-review/src/planner-lab`: 실제 React 추천·선택·활동 작성 화면.
- `payload/artifacts/nuvia-ui-review/src/studio/StudioApp.tsx`: 최종 보관 소스 기준 추가 진입점. 호스트가 검증된 로그인 세대 키를 전달하면 ‘지금’ 화면에서 표시합니다.
- `payload/server/planner-lab`: LAB 실 HTTP 호출, 응답 확인, 공개 필드 제한, 계정별 카드·활동 저장, HTTP API, PostgreSQL 저장소, SQLite QA 저장소, 조합 모듈.
- `payload/library/competency`: 수정 운영규칙서·기준 카탈로그·실행 규칙·동기화·검증기. 새로운 학과 매핑이나 기업 근거를 임의로 추가하지 않았습니다.
- `qa`: 합성 HTTP 테스트, 새 컴포넌트 타입 검사·번들 검사, 브라우저 저장 화면과 검증 범위. 합성 QA 서버는 제품 배포 대상이 아닙니다.
- `developer-issues.json`: 운영 연결 문제, 소유 담당자, 개발자 수정 항목, 완료 판정 기준.

## 확인한 기존 동작과 단절

플래너 최종 보관 소스의 운영 호스트는 `null`이고, 추가 요청은 IndexedDB의 `connection_pending` 기록에 머뭅니다. `ExistingTools.tsx`의 오늘 추천은 생성된 카드 목록이 아니라 기존 라이브러리·전략·회고로 이동하는 세 경로입니다. 따라서 운영 LAB 호출 → 후보 표시 → 선택 카드 서버 등록은 별도로 필요했습니다.

기업 LAB에는 `/api/lab/daily` 생성·재사용·번역·추가 요청이 이미 있고, `/select`도 있습니다. 하지만 `/select`의 `waiting_connection`은 LAB 내부 선택 승인이고 플래너에 저장됐다는 영수증이 아닙니다. 이번 모듈은 LAB 선택 승인 뒤 플래너 DB 등록까지 수행하고, DB 저장 확인 후에만 저장 성공을 표시합니다.

## 캠프 코드 없이 연결되는지

확인한 LAB 보관 소스 `1b2429a08aedea943a8e2499a30137805d3e77d0`에는 이미 다음 경로가 있습니다.

1. 새로운 로그인에 선택한 캠프가 없으면 `accessFor()`가 `personal-workspace`를 조회합니다.
2. `/api/lab/personal`은 명시적인 개인 공간 전환입니다. 참여 코드 입력은 없습니다.
3. 시작 화면의 개인 공간 버튼은 `/lab/personal`을 호출합니다.
4. `requireCamp`라는 함수명은 남아 있으나 개인 공간도 허용합니다. 여기서 요구하는 `x-lab-camp`는 서버가 확인한 **공간 ID**이며 학생이 입력하는 참여 코드가 아닙니다.
5. DB에 `personal-workspace` 행이 있어야 합니다. 기존 `2026-11-12-daily-practice.sql`의 개인 공간 초기화가 운영에도 반영됐는지 확인합니다.

이번 패치는 LAB 세션을 먼저 조회하고 반환된 공간 ID를 헤더에 붙입니다. 클라이언트에서 `campCode`, `subject`, 임의 공간을 받아 권한으로 사용하지 않습니다. 만료·철회된 캠프 세션은 자동 우회하지 않고 개인 공간으로 명시적으로 전환하도록 안내합니다.

이는 **소스 확인 + 합성 개인 공간 HTTP QA 통과**입니다. 운영 DB의 개인 공간 행·Clerk 로그인 주체 연결·현재 배포 버전까지 이번 작업에서 검증한 것은 아닙니다.

## 개발자 적용 순서

1. `apply_patch.py --target <플래너 작업폴더>`로 먼저 충돌 검사를 합니다. 파일을 쓰려면 `--apply`를 추가합니다. StudioApp 원본 SHA가 다르면 멈춥니다. 최신 소스를 강제로 덮어쓰지 마세요.
2. 기존 중앙 NUVIA Node 서버에 `server/planner-lab/planner-lab-mount.mjs`를 연결합니다. Next App Router의 Web Request 환경이라면 해당 런타임의 요청·응답 방식으로 HTTP 진입부를 감싸야 합니다. 브라우저 번들에 서버 모듈·SQLite·DB·SSO 자격증명을 넣지 마세요.
3. 운영 환경에서는 기존 PostgreSQL pool과 `createPlannerLabPgStore()`를 사용합니다. `plannerLabMigration`을 DB 변경 절차에서 실행합니다. 이 패치는 운영 DB 마이그레이션을 자동 실행하지 않습니다. SQLite는 단일 호스트·합성 QA 대안입니다.
4. 다음 호스트 함수를 실제 서비스에 연결합니다. 테스트용 헤더 인증을 배포하면 안 됩니다.

| 호스트 항목 | 실제 연결 내용 |
|---|---|
| `authenticate(req)` | 기존 중앙 로그인으로 검증한 `{subject, sessionId}`. 브라우저 입력값으로 만들지 않습니다. |
| `assertSessionCurrent(principal)` | 긴 LAB 생성 후 같은 세션이 유효한지 다시 확인합니다. |
| `loadOwnedContext(principal)` | 현재 소유자의 원본 결과지 `{report:{id,version}, jobs:[{id,label,rank,source,profileId,verifiedMapping:true}]}`. rank·label을 재산출하지 않습니다. 미검증 매핑에는 true를 넣지 않습니다. |
| `credentialFor(principal)` | 같은 사용자의 LAB 인증을 검증한 기존 SSO 브로커 자격증명. 중앙 계정과 LAB 계정의 주체 대응을 확인해야 합니다. 관리자 공용 토큰으로 모든 학생을 처리하면 안 됩니다. |
| `verifyMutation(req,principal)` | 기존 Origin/CSRF 정책. 프런트가 별도 CSRF 토큰을 쓰는 환경에서는 `httpApi`에 그 헤더 공급도 연결합니다. |
| `labOrigin` | 실제 기업 LAB의 HTTPS 원점. `/api/lab/*` 경로를 받는 주소입니다. NUVIA 화면 URL이라고 무조건 같은 API 원점은 아닙니다. |
| `registeredProfileIds` | 제공한 기준 라이브러리의 등록 프로필 ID. 실제 매핑은 소유 결과와 확인된 대응표로 제한합니다. |

5. 중앙 서버에서 `/api/planner/lab/*`를 제공하고 기존 플래너에 `PlannerLabRecommendations`를 렌더링합니다. 포함된 StudioApp에는 `labSessionKey` prop을 추가했습니다. 중앙 로그인/로그아웃/계정/수업 공간 전환 때 바뀌는 검증된 세대 키를 전달해야 합니다. 합성 검토 화면에는 자동 연결하지 않습니다.
6. 이 키는 인증 수단이 아닙니다. HTTP 진입부는 실세션과 화면 바인딩을 별도로 검사합니다. 로그인 계정이 바뀌면 이전 화면의 요청·기록을 재사용할 수 없습니다.
7. `openPath`의 `/planner?labActivity=...`는 호스트 플래너 실제 경로에 맞춰 연결합니다. 포함 컴포넌트는 이 매개변수로 저장 활동을 엽니다. 기존 달력·할 일 DB·통계까지 합치려면 소스 카드·버전·교육용 표시를 유지하는 별도 매핑이 필요합니다.

## 학생 화면 흐름

로그인 → TOP5 또는 검증된 관심 직무 중 직접 선택 → 오늘 추천 1~3개 요청 → 직무/인지전략/회고 후보 확인 → 카드 하나 선택·플래너 저장 → 카드의 권장 시간으로 시작 → 우선순위·근거·미확인 사항·회신 전 행동 작성 → 서버가 중간 시점에 공개한 추가 정보에 대한 판단 → 실제 행동·결과·직무 연결·배운 점·느낌·메모 저장 → 다시 열고 수정·저장.

추천 후보는 자동 실행·완료 처리하지 않습니다. 첫 오늘 추천의 직무를 당일 바꿔 LAB가 409를 반환하면 이유를 표시하고 선택 직무로 추가 요청하도록 합니다. 추가 요청은 하루 3개로 제한하지 않습니다. 동일 요청의 실패 재시도는 같은 요청 ID를 유지합니다. 카드 버전별 중복 등록은 DB 고유키로 막습니다.

## 다른 수신 계약과 구분

이 패치가 직접 처리하는 원본은 기존 `/lab/daily` 연습 카드입니다. `/lab/daily/:id/select`의 `lab-daily-selection/1.0` 승인과 대응합니다. `timed-decision-card/1.3` 원문·서명 영수증을 처리하는 기존 시나리오 송수신기를 임의 변환하거나 덮어쓰지 않았습니다. 기존 1.3 수신기의 운영 연결도 필요하면 `developer-issues.json`의 별도 항목을 완료해야 합니다.

기존 플래너 일기·요약·타이머·판단형 엔진은 유지합니다. 이번 LAB 연습 활동은 새 패널의 서버 기록으로 보관됩니다. 같은 기존 할 일 테이블·달력·공유 통계로 통합하는 작업과 AI자소서 STAR 전달·학생 동의·첨부파일·강사 확인은 이번 패치에서 운영 완료됐다고 표시하지 않습니다.

## 검증 결과와 한계

- 합성 LAB HTTP → 실제 연결 모듈 → SQLite 서버 저장: **24개 테스트 통과**. 개인 공간·권한·중복·버전·재시도·상황 공개·수정 이력·재시작 복구·계정 변경 차단을 포함합니다.
- 4개 항공 관련 프로필 × 15개 언어 코드 라우팅 60조합 통과. **합성 응답으로 전송값을 확인한 검사이며 실제 AI 60회 생성·번역 품질·15개 언어 화면 QA가 아닙니다.** 새 화면 문구는 한국어입니다.
- 새 React 컴포넌트 strict TypeScript 검사와 번들 생성 통과. 기존 플래너 전체 빌드·전체 회귀 QA를 대신하지 않습니다.
- 브라우저에서 캠프 코드 없는 개인 공간 → 직무 선택 → 후보 3개 → 1개 등록 → 직접 기록 → 시작·서버 저장 → 새로고침 → 저장본 복원 → 수정·재저장 확인.
- 브라우저에서 시작 직후 남은 시간이 1분 크게 보이는 문제를 발견해 권장 시간 이내로 표시하도록 수정했습니다.
- 기준 라이브러리 sync/verify 통과: 124프로필·47학과·2232구성. 구조 검증이며 전문가 검증이 아닙니다. 기존 출처·NCS KSA 공백을 유지했습니다.
- ZIP을 풀어 포함된 실행 모듈로 HTTP 테스트 24개 재통과. 적용 전 검사·실제 적용·중복 적용 검사·충돌 거부·원본 복원까지 패치 도구 검증을 통과했습니다.
- ZIP을 풀어 포함된 실행 모듈로 HTTP 테스트 24개 재통과. 적용 전 검사·실제 적용·중복 적용 검사·충돌 거부·원본 복원까지 패치 도구 검증을 통과했습니다.
- PostgreSQL 저장 구현은 포함했으나 실제 PostgreSQL 서버 통합 실행은 하지 않았습니다. 운영 적용 전에 개발자가 반드시 DB·SSO·원본 TOP5·실 LAB 생성·기존 일정 통합·계정 격리를 검증해야 합니다.
