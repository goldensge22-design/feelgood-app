# NUVIA HISTORY 실행 순서 상위 참조 부록 v1.1.1

작성일: 2026-09-19. 상태: 사용자 승인 완료 / FINAL BASELINE / 동결. 이번 산출물은 문서 계약이며 코드 적용 완료를 뜻하지 않는다.

## 1. 적용 범위와 효력

최초 예측 → 핵심 활동 → 변경 결과 공개 순서를 NUVIA HISTORY의 공통 실행 원칙으로 명시한다. 설계 적용 범위는 48미션·96조건·6연령 경로, 대표 6미션 의미 기준본과 이후 제작하는 모든 실행 콘텐츠다. W24만의 예외가 아니다.

실행 단계 순서에 한해 이 부록을 기존 마스터와 엔진보다 먼저 참조한다. 그 밖의 역사 조건, 출처, PASS 배정, 핵심 행동, 인과 범위, 연령 규칙, 이야기책·리포트 계약, 비AI 원칙은 변경하지 않는다. 동결 마스터·의미 기준본·연간 및 역사 기준본은 수정하지 않는다.

현재 코드 적용 및 실제 검수의 예정 범위는 W24 C1·C2 × 6연령 12경로다. 이번 작업은 후보 부록 작성까지만 하며 코드를 수정하지 않는다. W24 통과 전 W01 및 나머지 대표 미션의 화면 구현을 시작하지 않는다.

## 2. 정규 8단계

| 번호 | 정규 단계 | 의미 | 기존 이벤트와의 대응 / 저장 경계 |
|---|---|---|---|
| 1 | `conditionUnderstanding` | 실제 역사 확인, 바꿀 조건 선택 및 이해 | `historyViewed`와 `conditionSelected`를 서로 다른 하위 이벤트로 보존. 두 화면을 사용할 수 있으나 정규 단계는 하나다. 이해도 평가·추론을 만들지 않는다. |
| 2 | `prediction` | 결과 공개 전 최초 예측 | `predictionRecorded`의 실제 선택·말·글·그림 또는 명시적 모름·보류를 저장하고 원본 스냅샷을 잠근다. |
| 3 | `coreActivity` | 승인된 PASS 핵심 인지 활동 | `cognitiveActionRecorded`의 유효 입력 또는 명시적 `activityDeferred`를 영속 저장한다. 결과 공개 전 완료/보류 상태를 잠근다. |
| 4 | `alternateResult` | 변경된 역사 결과 공개 | 선행 두 기록과 동일 결과 연결 검증 후 `alternateViewed`. 가상 가능성과 실제 사실을 구분한다. |
| 5 | `learnerStory` | 나만의 이야기와 그림 | `storyRecorded`와 해당 사용자의 실제 창작·StoryCanvas 참조. 활동 라벨·예측·가능성 문구를 자동 복사하지 않는다. |
| 6 | `historyComparison` | 실제 역사와 나의 역사 비교 | `comparisonCompleted` / `comparisonKind=history`; 별도 입력 출처·eventId·레코드. |
| 7 | `predictionComparison` | 최초 예측과 실제 역사 비교 | `comparisonCompleted` / `comparisonKind=prediction`; history와 별도 입력 출처·eventId·레코드. |
| 8 | `artifactLink` | 미션별 8쪽 책과 통합 성장 리포트 연결 | 같은 resultId의 실제 기록을 읽어 연결. 상태 진입을 이유로 새 사용자 입력이나 새로운 이벤트 종류를 만들지 않는다. |

정규 순서:

`conditionUnderstanding → prediction → coreActivity → alternateResult → learnerStory → historyComparison → predictionComparison → artifactLink`

논리적 실행 상태:

`conditionUnderstood → predictionCommitted → (cognitiveActionRecorded 또는 명시적 보류 기록) → alternateRevealed → storySaved → comparisonCompleted(history) → comparisonCompleted(prediction) → artifactsLinked`

위 논리 상태 이름을 새로운 영구 eventType enum으로 일괄 추가하거나 과거 이벤트 이름으로 소급 치환하지 않는다. `conditionUnderstood`는 확인·선택 기록이 있다는 절차적 상태이며 사용자의 이해 능력이 확인됐다는 판정이 아니다. 기존 이벤트 대응은 위 표를 따른다. 필요한 새 이벤트·payload 변경은 별도 공통 계약 검토 대상으로 남긴다.

## 3. 결과 공개 게이트

결과 공개에는 다음 조건을 모두 요구한다.

1. 해당 결과의 조건이 선택되어 있다.
2. 최초 예측 스냅샷이 영속 저장되어 잠겨 있다.
3. 같은 조건의 핵심 활동에서 아래 네 경우 중 하나가 실제로 기록되어 있다.
4. 핵심 활동 완료/보류 기록이 영속 저장되어 잠겨 있다.
5. resultId·missionId·conditionId·missionVersion·contentVersion이 일치한다.

| 핵심 활동 기록 | 공개 전 처리 | 리포트 표시 경계 |
|---|---|---|
| 유효한 실제 사용자 입력 | 승인된 공통 행동 계약으로 입력을 검증하고 저장 | 실제 선택·배열·수정·이유 등 수집한 항목만 표시 |
| 잘 모르겠어요 | `activityDeferred`의 명시적 모름 기록; 답을 생성하지 않음 | 보류. 실패·약점·낮은 능력으로 해석하지 않음 |
| 명시적 활동 보류 | 사용자가 보류했음을 실제 이벤트로 저장 | 보류 또는 관찰되지 않음; 미입력을 0점·실패로 바꾸지 않음 |
| 접근성상 수행 불가 기록 | 명시적 근거와 보류 사유를 보존하는 공통 저장 계약 필요 | 수행 입력 대신 보류/관찰되지 않음; 장애나 능력을 추정하지 않음 |

버튼 표시, 활동 화면 방문, 자동 안내, 타이머 경과, 빈 입력, 다른 결과의 이벤트만으로 게이트를 통과시키지 않는다. 저장 실패 또는 결과 연결 불일치이면 공개를 차단한다. 모름·보류는 유효한 진행 경로이며 응답·이유·이야기를 대신 생성하지 않는다.

현재 엔진의 `deferAction.reason`은 `unknown | skip`뿐이다. 접근성상 수행 불가의 구체적 사유를 이 값으로 위장하지 않는다. 공통 payload 확장 검토는 대응표의 `EO-P1-01`로 남긴다. 아직 구현되지 않은 경로를 제공된 기능으로 표시하지 않는다.

## 4. 공개 전 도움과 정보 차단

도움은 질문을 더 짧게 나누기, 조작 방법 안내, 선택 가능한 재료 다시 보여주기, 순서 또는 관계를 시각적으로 강조하기로 제한한다. 올바른 답·추천 계획·권장 선택의 순서를 강조하는 방식은 허용하지 않는다. 사용자가 선택하지 않은 대응을 도움 사용만으로 저장하지 않는다.

변경 결과, 결과 A/B 설명, 결과 장면, 정답 또는 권장 선택을 공개 전 힌트로 제공하지 않는다. 승인된 최초 예측 선택지 자체는 예측 입력 재료로 표시할 수 있으나 변경 결과를 미리 확인한 사실이나 정답으로 강조하지 않는다.

차단 적용 대상은 본문, 툴팁, 도움 패널, 단계 미리보기, 사전 녹음 안내, 접근성 설명, 숨겨진 결과의 포커스 진입, 책·리포트의 조기 열람, 직접 URL 진입, 새로고침 및 저장 복구다. 사전 로딩한 파일의 존재와 사용자에게 결과를 공개한 것은 구분하되, UI나 안내를 통해 사전 노출되지 않아야 한다.

문서가 허용하는 결과 사전 노출 경로는 0개다. 실제 W24에서 이 경로들이 차단됐는지는 후속 브라우저·이벤트 검수 대상이며 이번 문서 검수로 통과 선언하지 않는다.

## 5. 공개 이후 불변성과 입력 출처

결과 공개 후 최초 예측과 최초 핵심 활동의 입력·보류 상태를 덮어쓰지 않는다. 공개 후 이야기·비교는 각자의 별도 입력 출처로 저장한다. 감상·설명을 최초 핵심 활동에 합치거나 PASS 수행 횟수로 중복 집계하지 않는다. 기존 계약에 없는 새 필수 이벤트가 필요하면 P1 제안으로 남기며 임의로 추가하지 않는다.

두 비교는 `history / prediction`만 사용한다. 고정 발견 카드·comparisonTag는 허용하지 않는다. 같은 문장을 각각 직접 입력한 경우 별도 eventId·입력 단계·레코드·출처를 확인하여 정상 처리한다. 반대 비교의 입력·음성·그림을 fallback으로 복사하지 않는다.

이야기책 7쪽은 실제 역사 ↔ 나의 역사 → 발견, 8쪽은 최초 예측 → 실제 역사 → 발견으로 목적·출처·레이아웃을 구분한다. 최초 예측에서 실제 선택한 그림·문구 스냅샷은 8쪽에 표시할 수 있다. 8쪽의 새로운 비교 발견을 고정 선택 카드로 받지는 않는다. 입력이 없으면 기록 없음/미제공 상태를 표시하고 다른 기록으로 채우지 않는다.

## 6. 버전과 기존 기록 보존

새 실행부터 새 실행 순서에 맞는 버전 계약을 적용한다. 구조 변화이므로 기존 버전과 구분하여 해석해야 하며, 이 문서 버전 `v1.1.1`을 missionVersion·contentVersion·appVersion 값으로 자동 복사하지 않는다. 실제 실행 버전 값과 기존 버전 읽기 경로는 후속 승인된 구현에서 확정한다.

기존 결과 및 진행 중 기록은 당시 버전과 단계 순서를 그대로 보존한다. 이전 기록을 새 순서로 변환·삭제·재정렬하거나 없는 예측·활동 이벤트를 소급 생성하지 않는다. 기존 세션 복구에 새 단계 인덱스를 그대로 적용하지 않는다. 이전 버전을 안전하게 이어갈 수 없으면 원본을 보존하고 구현 충돌로 보고한다.

모든 단계·StoryCanvas·음성·사용자 이야기·두 비교·8쪽 책·통합 성장 리포트는 같은 resultId와 해당 미션·조건·버전을 참조한다. 다른 결과·조건·버전의 자료를 섞지 않는다. 절차적 잠금은 사용자 능력 판정과 무관하다.

## 7. 100% 비AI 런타임

플레이·도움·이야기·이야기책·성장 리포트에서 생성형 AI API, 실시간 TTS, 자동 번역, 외부 생성 서비스를 호출하지 않는다. 승인된 로컬 콘텐츠, 규칙 엔진, 저장된 공용 자산, 사용자 실제 입력·수행 이벤트만 사용한다. 실제 존재하는 사전 녹음 안내만 제공하며 사용자 로컬 녹음과 구분한다. 이 부록 작성은 런타임 AI 기능 추가를 승인하지 않는다.
