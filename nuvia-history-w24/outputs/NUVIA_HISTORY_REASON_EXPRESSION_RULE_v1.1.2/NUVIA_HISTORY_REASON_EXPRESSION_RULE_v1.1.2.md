# NUVIA HISTORY 이유 자유 표현 공통 규칙 v1.1.2

작성일: 2026-09-19  
상태: **FINAL BASELINE / 사용자 승인 완료 / 동결**

이 문서는 NUVIA HISTORY 48미션·96조건·6연령 경로에서 이유를 묻는 모든 질문에 적용할 최종 공통 규칙이다. W24에서 발견된 질문–응답 불일치를 전체 공통 계약으로 해소하기 위한 설계이며, 동결 기준본·게임 코드·UI·사용자 기록을 변경하지 않는다. 이 기준본 승격은 코드 적용 완료를 뜻하지 않는다.

## 1. 적용 범위

- 48미션·96조건의 `semanticRole = reasonExpression`인 모든 질문
- 조건별 PASS 핵심 활동 안에서 선택·배열·분류·수정 뒤 이유를 묻는 하위 단계
- 6연령 경로의 화면 문구, 입력 도구, 저장, 성장 리포트 연결
- 신규 실행부터 적용할 공통 엔진 계약

이 규칙은 역사 조건, 인과 범위, PASS 배정, 최초 예측, 변경 결과, 이야기책 8쪽 구조와 실행 순서를 바꾸지 않는다. 이유 질문이 없는 조건에 이유 입력을 새로 강제하지 않는다.

## 2. 공통 이유 질문 규칙

`왜 골랐나요?`, `그렇게 고른 까닭은 무엇인가요?`, `어떤 이유로 정했나요?`처럼 이유를 묻는 질문은 고정 답변 카드만으로 구성하지 않는다. 반드시 사용자가 자기 생각을 직접 남길 수 있는 `freeExpression` 입력을 제공한다.

이유 화면은 다음 순서를 사용한다.

1. 바로 앞에서 사용자가 고른 답변·배열·분류·수정 결과를 읽기 전용으로 표시한다.
2. 이유 질문과 연령별 안내를 표시한다.
3. 허용된 글·로컬 음성·그림 입력 도구를 표시한다.
4. 실제 입력을 저장하거나 `이유는 건너뛸게요`를 명시적으로 선택한다.

이전 선택 문구를 이유 입력에 자동 복사하지 않는다. 시스템은 사용자의 이유를 생성·보완·요약·번역·전사·분류·채점·추론하지 않는다. 고정 이유 카드, 기본 선택, 추천 이유, 정답 이유를 제공하지 않는다.

## 3. 질문과 화면 문구

### 유아·초등 저학년

- 질문: `왜 그렇게 골랐나요?`
- 안내: `내 생각을 말하거나, 그리거나, 짧게 써 보세요.`

### 초등 고학년·중학생·고등학생·성인

- 질문: `그렇게 선택한 이유를 직접 남겨 보세요.`
- 안내: `선택할 때 생각한 조건이나 까닭을 적어 보세요.`

저장 버튼은 현재 입력 방식에 맞게 `내 생각 저장하기`, `말 저장하기`, `그림 저장하기`, `이유 저장하기` 중 하나를 사용한다. 이유 화면에서 `내 선택 남기기`를 사용하지 않는다.

## 4. 건너뛰기

`아직 모르겠어요`는 이유 답변 카드나 대표 선택지로 사용하지 않는다. 이유를 남기기 어려운 사용자는 화면 아래의 작고 시각적으로 약한 보조 버튼 `이유는 건너뛸게요`를 사용할 수 있다. 기본 선택하거나 일반 응답 카드처럼 강조하지 않는다.

건너뛰면 다음을 지킨다.

- 이유 텍스트·음성·그림과 `reasonRef`를 만들지 않는다.
- 이전 선택 문구나 다른 기록을 이유로 복사하지 않는다.
- 이유 범위의 `activityDeferred`만 기록한다.
- 성장 리포트에는 `이번 활동에서는 이유가 기록되지 않았어요`라고 중립적으로 표시한다.
- 이해도·정확성·태도·회피·능력·약점을 추정하지 않는다.

접근성상 수행 불가의 구체적 사유는 `EO-P1-01`이 확정될 때까지 저장하거나 추정하지 않는다. 이 기준본은 해당 이슈를 종결하지 않는다.

## 5. 완료 조건

이유 입력 단계는 다음 중 하나가 영속 저장된 경우에만 완료한다.

1. 사용자가 글을 직접 입력했다.
2. 사용자가 기기에 음성을 직접 녹음했다.
3. 사용자가 그림을 직접 저장했다.
4. 사용자가 `이유는 건너뛸게요`를 명시적으로 선택했다.

공백만 있는 글, 녹음·그림 참조 없는 표시 상태, 자동 생성 문장, 이전 선택 문구 복사, 화면 방문, 타이머 경과는 완료가 아니다. 선택 활동 자체와 이유 단계는 한 트랜잭션에서 연결하되 서로 다른 입력 출처로 보존한다.

## 6. 입력 출처와 비AI 원칙

허용하는 이유 입력 출처는 `typed`, `recorded`, `drawn`, `deferred`뿐이다. `typed`는 사용자가 직접 쓴 원문, `recorded`는 기기에 로컬 저장한 원음 참조, `drawn`은 사용자가 직접 저장한 그림 참조, `deferred`는 명시적 건너뛰기다.

생성형 AI API, 음성 인식, 자동 전사, 자동 요약, 자동 번역, 실시간 TTS, 의미 분석, 자동 채점, 외부 생성 서비스를 사용하지 않는다. 같은 입력과 같은 콘텐츠·미션 버전에서는 같은 저장 결과가 재현되어야 한다.

## 7. 이야기책과 성장 리포트

- 직접 입력한 이유는 성장 리포트에 선택적으로 연결할 수 있다.
- 이유 원문·음성·그림을 나만의 이야기나 이야기책 문장으로 자동 복사하지 않는다.
- `deferred`이면 대체 문장이나 평가 문장을 생성하지 않는다.
- 성장 리포트는 실제 입력 방식과 실제 원문 또는 로컬 참조만 표시한다.
- 이유가 없으면 `이번 활동에서는 이유가 기록되지 않았어요`를 표시한다.
- 이야기책 7·8쪽의 비교 자유 표현 계약과 이유 표현 계약을 혼합하지 않는다.

## 8. 기존 규칙과의 관계

이 부록은 **이유 질문의 입력·저장·리포트 경계에 한해서만** 다음 문서보다 구체적인 상위 참조가 된다.

1. `NUVIA_HISTORY_EXECUTION_ORDER_RULE_v1.1.1` — 실행 순서는 그대로 유지한다.
2. `NUVIA_HISTORY_MASTER_RULES_v1.1` — 14장 질문 정합성 원칙을 구체화한다.
3. `NUVIA_HISTORY_ANNUAL_INTEGRATED_BASELINE_v1.0` — 기존 `reasonRef` 계약을 자유 표현 참조로 확장한다.
4. `NUVIA_HISTORY_REPRESENTATIVE_6_SEMANTIC_BASELINE_v1.1` — 승인된 질문 의미를 유지하되 고정 이유 재료를 제거한다.
5. 개별 미션 실행 콘텐츠 — 이유 화면에 공통 렌더러를 사용한다.

실행 순서 충돌에는 계속 `NUVIA_HISTORY_EXECUTION_ORDER_RULE_v1.1.1`이 우선한다. 이 기준본은 조건 이해 → 최초 예측 → 핵심 활동 → 변경 결과 공개의 순서를 바꾸지 않는다.

## 9. 버전과 기존 기록

기존 결과를 변환·삭제·소급 생성하지 않는다. 기존 `reasonRef`가 고정 재료 ID인 기록은 수행 당시 missionVersion·contentVersion과 함께 그대로 읽는다. 새 계약을 구현할 때는 이벤트·저장 구조가 바뀌므로 해당 미션의 `missionVersion` MAJOR 증가가 필요하며, 문구·표현 데이터 변경은 `contentVersion`을 별도로 증가시킨다. 정확한 새 버전 값은 후속 구현 승인 시 결정한다.

새 이유 기록은 같은 `resultId`, `missionId`, `conditionId`, `missionVersion`, `contentVersion`의 선택 활동에만 연결한다. 다른 결과·조건·버전의 이유를 fallback으로 표시하지 않는다.

## 10. 최종 기준본 판정

규칙 문서 내부 정합성 검수를 통과하여 사용자 승인에 따라 최종 기준본으로 승격·동결했다. 현재 실행 계약과 W24 화면의 [P0 3건](./OPEN_ISSUES_P0_P1_P2.md)은 구현 대기 상태로 유지한다. 이 기준본을 코드에 자동 반영하지 않으며, 별도 구현 명령에서 공통 계약을 먼저 적용하고 W24 구현·실행 검수를 통과한 뒤 다른 미션에 확대한다.

세부 연령·이벤트 계약은 [AGE_INPUT_AND_EVENT_CONTRACT.md](./AGE_INPUT_AND_EVENT_CONTRACT.md), 기존 충돌과 W24 변경 전후는 [RULE_CONFLICT_AND_W24_BEFORE_AFTER.md](./RULE_CONFLICT_AND_W24_BEFORE_AFTER.md), 보호 파일은 [PROTECTED_FILE_INTEGRITY.md](./PROTECTED_FILE_INTEGRITY.md)를 참조한다.
