## 최상위 가드와 QA 분리

`App`이 연령을 확인한 직후 모든 preschool 단계는 전용 `PreschoolPlay`로 분기한다. 기존 기록 재개와 `new=1`, QA와 실제 연동 프로필에 동일하게 적용한다. 공통 활동 설명 컴포넌트는 이 경로에 들어오지 않는다.

`PlayGuard`는 첫 화면과 이후 DOM 변경에서 시스템 문구를 검사한다. 금지어, 텍스트 상한, 질문 수, 선택지 수 위반은 플레이를 차단하고 짧은 대기 화면을 표시한다. 내용은 저장소에서 삭제하거나 교정하지 않는다.

- 금지어: PASS, 목표, 조건, 제약, 전략, 대안, 근거, 판단, 완료 확인, 인지, 메타인지
- 시스템 표시 텍스트: 공백 정규화 후 최대 80자
- 핵심 질문: 한 화면 최대 1개, 코드 상한 18자; 실제 유아 문구는 짧은 행동 질문으로 작성
- 그림 선택지: 2~3개
- 시각 QA: 그림·사용자 그림·드로잉 캔버스 영역이 플레이 콘텐츠 영역의 70%보다 작으면 warning

사용자가 직접 쓴 글과 작품은 정책 검사로 검열하거나 자르지 않는다. 글자 수·금지어 검사는 시스템이 제공하는 플레이 문구를 대상으로 한다. 선택 후에 여는 글쓰기 입력 방식은 이미지로 집계하지 않는다.

교사용 설계 정보는 `QAInspector` 한 곳에만 표시한다. `qa=1`일 때도 학생 플레이 DOM 밖에 존재한다. PC에서는 오른쪽 접이식 패널, 모바일에서는 플레이 아래의 독립 패널로 두어 조작 영역을 가리지 않는다. 실제 연동 프로필로 QA 값을 제거한 플레이 내용과 QA 플레이 내용이 같은지 검사한다.

완료된 이야기책·성장 리포트는 플레이 밖의 접힌 `보호자 기록` 열람에서 기존 결과 뷰를 재사용한다. 학생 플레이 중에 보호자용 설계·리포트 문구를 넣지 않는다.

| 재검토 | 공통 단계의 설명에 의존 | 그림 결과 확인 후 `다시 골라 볼까?`, 유지·변경 모두 허용 |

| 역사·예측·두 비교 | 공통 장문 화면 | 짧은 질문과 서로 구분된 그림·원본 입력 |

그림은 실제 조작을 표현하는 코드 기반 SVG로 제작했다. 빈 자료 자리나 의미 없는 장식 아이콘으로 선택지를 채우지 않았다. 실제 역사, 상상, 사용자 작품은 표시와 저장 출처를 구분한다.

## 연령별 게임 행동

| 대표 경로 | 표시와 행동 |
|---|---|
| preschool / 5~7세 | 한 단어 그림 카드, 첫 행동 하나 선택 → 그림 결과 확인 → 한 번 재선택 |
| 초1 (`elementary-low`, `grade=1`) | 짧은 상황 설명 추가, 첫 행동 선택 → 그림 결과 확인 → 재선택 |
| 초2 (`elementary-low`, `grade=2`) | 같은 세 대안 중 두 행동의 차례 구성 → 결과 확인 → 차례 재구성 |
| 초3·4 (`elementary-high`, `grade=3` 또는 `4`) | 구체적인 행동 문장, 세 행동의 차례 구성 → 결과 확인 → 유지·수정 |

선택지 수는 세 개로 유지한다. 수행할 행동 간 관계와 차례 구성을 늘렸으며 선택지 개수 증가를 난이도 상승으로 취급하지 않는다. 학년은 연결 프로필의 선택 필드 `schoolGrade`로 보존하고, QA에서만 `grade` 쿼리로 모의 입력한다. 플레이에는 학년 선택 UI를 넣지 않는다. 기존 프로필의 연령 enum과 과거 기록은 유지한다.

W24 C1·C2는 모두 Planning이다. 새 `planningInteraction` 이벤트에는 실제 첫 선택·그림 확인 버튼·재선택, 선택한 순서와 유지·변경 여부를 기록한다. 목표 맥락 ID와 연결하지만 아이가 목표를 이해했다고 추론하지 않는다. 그림 확인 버튼을 누른 사실을 시선·주의 측정으로 바꾸지 않는다. 자유 표현 이해, 정답 판정, 능력 점수는 생성하지 않는다.

Attention·Sequential·Simultaneous를 이 Planning 화면의 이름만 바꿔 제공하지 않는다. 현재 W24 전용 유아 경로는 지원하지 않는 PASS/활동 계약을 차단한다. 다른 영역의 실제 그림 탐색·기억 복원·관계 묶기 미션을 구현하거나 검수했다고 주장하지 않는다.

## 표현·저장 보존

- 말과 그림이 직접 표현 수단이며 쓰기는 `다른 방법`에서 선택한다.
- 읽어주기는 기기 내 한국어 TTS 음성이 확인될 때만 표시한다. 음성이 없으면 작동하는 버튼을 표시하지 않는다.
- 마이크 녹음은 해당 브라우저 API가 제공될 때만 표시한다. LAN HTTP에서는 마이크가 제공되지 않을 수 있다. 음성 인식·자동 전사 기능은 없다.
- 글·그림·녹음 초안은 수행 ID와 입력 단계별로 보존한다. 그림 초안의 새로고침 복원과 실제 저장 경로를 브라우저에서 검증한다.
- 유아 그림은 세로 캔버스를 사용한다. 기존 640×360 그림과 새 640×800 그림 모두 읽고 저장할 수 있으며 다른 연령의 기존 가로 캔버스는 유지한다.
- 이유는 핵심 선택·관찰·재선택을 마친 뒤에만 건너뛸 수 있다. 이유의 생략과 핵심 사고 행동의 수행 기록은 별개다.
- 두 비교 입력과 이야기 원본은 기존 resultId·단계별 출처 계약을 유지한다.

## 검증 근거

- TypeScript 검사 및 프로덕션 빌드 통과.
- 기존 회귀 270개 + 새 정책·학년·행동 기록 검사 12개 = 282개 통과.
- `qa/preschool-guard/browser-check.cjs`: 모바일 390×844와 데스크톱 1440×900, 5개 대표 연령/학년 × C1·C2 = 20개 경로.
- 각 크기의 `results.json`, `desktop-results.json`에 시스템 텍스트, 질문 수, 가로 넘침, 그림 면적과 경고를 저장한다.
- QA 패널 열기, production/QA 플레이 동일성, 선택 후 새로고침 재개, 그림 초안 복원, C1 이유 그림 저장, C2 이유 생략, 두 비교와 완료까지 확인한다.
- 플레이 영역에 금지어를 강제로 삽입한 DOM 회귀 검사에서 차단 동작을 확인한다.
- 최종 결과: 20개 경로·108개 화면 확인에서 정책 실패 0, 가로 넘침 0, 시각 면적 warning 0. 유아 그림·캔버스 박스의 콘텐츠 영역 대비 비율은 모바일 최저 70.9%, 데스크톱 최저 70.8%다. 이는 픽셀별 그림 의미 분석이 아니라 실제 렌더링 요소의 면적 검사이며 캡처를 함께 검토했다.
